# 0.10.0-rc.3：从实际会话失败到针对性修复

本次是基于一份用户授权分析的DSH会话导出和16页PPTX进行的工程修复。原始会话、用户报告、所下载的论文图片、身份信息与字体不包含在本包中。单次失败不能代表某个模型的普遍能力；下面讨论可观察行为和插件缺口。

## 已观察到的失败模式

模型已加载rc.2、收到真实图片输入，实际请求中推理档位为max；不能归咎于旧技能或未启用视觉。生成层能够表达复杂页面，但执行过程把注意力放在通过几何/字段校验，方法和多图组织仍退化成小字分栏。

两次视觉/最终确认前没有展示文件；read_image只把图送给模型。全稿16页只打开过10个不同单页，却提交了16页已实看的审稿。取图日志报告的文件远多于入稿资产，缺少从下载目录到全稿用途的完整去向记录；缺图注与下载失败被混淆。正式pilot-review直到整稿已完成才补录，未起到提前校准作用。

## 修改层次

| 层次 | 实现 | 不代表什么 |
| --- | --- | --- |
| 真实图片输入 | Host监听成功read_image真实附件；当前单页字节须匹配本会话记录。归一化/缩放附件用调用前后未变的源文件快照关联。 | 不认证模型理解；不是人类审美批准。 |
| 用户预览 | render默认沿同一Host工具流水线调用present，最多4文件；缺工具或失败明确返回unavailable。 | 不代表人已打开文件；不绕过宿主授权。 |
| 反馈时序 | 有当前渲染的视觉确认不再弹阻塞问答；发布预览、最终消息附文件链接、结束本轮、等自然回复。 | 规则只识别相关提示，不是通用对话解析；文本澄清仍可问。 |
| 逐图清单 | plan(kind:figure-inventory)扫描明确指定的下载目录，记录图像哈希、尺寸、归属及逐图决定；context/check显示待处理项。 | 不自动联网发现遗漏文件，不自动判定图注语义；无图片数量配额。 |
| 样张优先 | Host中有六页以上故事板及pilot时，匹配当前pilot-review之前不可新增非样张页；修改现有页和取证可继续。 | 不替用户批准，不禁止制作可撤销候选。 |
| 构图教学 | 四个结果案例外加入方法闭环与多图组织案例；教条件迁移，不运行案例脚本冒充成果。 | 新两页为助手编排的构造教材，不是用户认可或真实模型成效。 |
| 执行工艺 | 提供splitBox/nativeDrawing等可组合函数；支持对齐、连接和拒绝文字溢出。 | 不替模型选择研究关系，也不降低字号或科学门槛。 |

图清单是现有plan动作的新kind，工具总数仍19。旧工程未存figureInventory仍可读取、修订和构建草稿；新的Host整稿review路径使用本地原图时须补清单。无需重新检索已获取资料。

## 验证范围

本包附有新的Host图片/展示、逐图清单与组合函数回归测试；完整测试结果单独记录于交付验证文件。`scripts/check-host-visual-path.mjs`运行官方0.2.1-rc.3的工具流水线、真实PPTX渲染和官方read_image/attachments；present和ask_user_question端点为受控测试夹具，证明嵌套调用及拒绝路径，不冒充桌面实机测试。其LLM适配器禁止任何模型请求。

没有使用真实DeepSeek生成第二份成品，没有替用户改模型、读密钥或配置profile。CLI直接调用没有宿主会话和图片入口，不伪造Host收据；PTC结果到模型的可见性仍由宿主管理，不能拿native流水线测试外推为所有入口通过。

收据保存在会话内存，重启后需重新读当前单页、重新展示。源图语义与人类审查仍需要诚实的作者判断。代码约束无法抵消错误的论文理解或糟糕的构图。

## 本轮测试结果摘要

最终串行全量Node回归609项通过、0失败、0跳过；启用DSH_REQUIRE_REAL_RENDER=1并提供本地官方Host测试运行时。Python结构解析9项通过。包检查核对19工具、6个当前案例、资源哈希与517个本地文档链接。最终安装包解包doctor检查通过，依赖复用审计环境已有安装，并非用户电脑全新联网安装。
