# v0.5：把模板研究落实到最终页面

## 为什么继续重做

用户明确否定了 v0.4 的视觉结果：与提供的两份正式学术汇报模板仍相差很大。v0.4 的记录完整性、溢出检查和独立试用不能推翻这一反馈。这次以两份原始模板的实际页面和 v0.4 的最终 PPTX 为对照，重新检查生成过程与表达结果。

两份参考稿分别为 19 页与 20 页。对照使用安装中文字体后的实际 PPTX 渲染；早期缺中文字体的图片不作为字体与排版判断依据。参考稿也包含占位身份、局部模糊图及个别碰撞，学习时不继承这些缺陷。用户上传的模板、原始会话和研究资料不随公开包分发。

## 找到的根因

| 层面 | v0.4 的实际不足 | v0.5 的改动 |
| --- | --- | --- |
| 模板学习 | 模型拿到字号、颜色等统计，但统计不会改变封面、正文页眉与全页布局；导入小组件也不能建立完整报告风格 | template 返回可直接 record 的 suggestedDesign；design.system 真正控制封面、页眉、分区与字体。解析证据与视觉确认分别记录 |
| 封面 | 大标题加几行身份文字仍像普通介绍页，缺少参考稿的报告身份层级 | 增加 framed、project 封面：场合、完整题名、责任主体与日期各有明确区域。真实身份缺失时省略，不移植模板机构与计划等级 |
| 正文 | 多页沿用“左证据、右文字、底部限制”，模板学习退化为颜色和边框 | 学术组合页按行与加权面板分配图、表、机制、统计图和解释；章节、共同条件、主证据与结论形成全页结构 |
| 科学图形 | 独立样本排序后连接成线，容易暗示趋势或配对；关键区间只写在文字中 | 原生分布图保留每个观测且不连线；区间图明确估计、上下界与参考值；同页多图通过稳定 ID 对应面板 |
| 机制与方案 | 方法、证据、缺口与后续动作被拆成平级备忘卡 | 用显式节点行和边表达分支、汇合、反馈与无向关联；排版不代替作者确定科学关系 |
| 排版可靠性 | 固定槽位难容纳不同学科的长图注、非对称图表与多行标题 | 按真实文字与载体最小需求测量行高和面板；不自动缩小字号、不丢弃未分配内容。信息过量时指出具体面板 |

## 从参考稿学到的具体原则

第一份模板的代表证据页把研究目标、真实图像、机制解释与页面结论相连；第二份模板用连续章节色带、不等宽证据区和成组的技术路线组织复杂材料。共同点是读者可以沿画面看出比较与推导关系。

对应到插件，迁移的对象是封面身份层级、页眉结构、字体比例、证据与解释的空间关系、流程拓扑及结论位置。研究题名、机构标志、作者图片、实验数字和正文判断不成为模板资产。解析器不按文件名、学科关键词或已知文件摘要选择特殊分支。

不同学术任务需要不同的关系表达。理论汇报可以围绕假设、构造、保证与反例展开；研究进展可以把已观察结果、混杂解释与下一步验证相连；定性研究可以并置原文、编码和不同解释。组合页提供这些表达的工具，不规定所有学科都必须套用实验数据图。

## 独立制作继续暴露的问题

第一轮材料稿的生成者已自行修正柱图长小数换行，但独立评审仍判第6页不可提交：机制图的边注释上缘被节点底板覆盖。节点间距原来固定为36px，标签向总线上方偏移，测量与绘制没有共同预留完整注释高度。这是通用布局缺陷，不通过手动挪动该例的节点或删标签解决。

理论稿则在完整PPTX中自行发现数学上下标、取整和分布符号缺字，以及一处表格图注碰撞。渲染器的missingFonts=[]并不能证明字形完整。SKILL把关键原生公式与高密度表格前移到代表页小样；最终仍要求逐页实际核对。

第一轮CLI使用者多次把命令名当作contract主题，并摸索review与能力记录参数。后续提供单命令--help/--schema；assessment契约另外给出capabilities的合法登记路径与完整schema。未知能力不会自动升级，不能冒充人工审查。事实、绘图和校验门槛都没有为这些试用降低。

原生柱/条图新增可选valueDecimals，将显示精度与原始series数值分开。实际PPTX与SVG使用相同标签格式，内嵌工作簿保留完整精度；不强制把所有学科的数据四舍五入到统一位数。

第二轮材料稿又在真实PPTX中发现，Office图表引擎自动跳过了四个分组中的两个类别标签，静态几何检查未发现。生成者自行换成完整的原生表格后完成交付。仅在XML写入标签频率的第一次修复未奏效；随后核对LibreOffice导入逻辑，为所有缺失显式旋转属性的原生类别轴补标准rot="0"，保留已有旋转。原样记录重渲染后四个分组完整显示，图表数据、字号与工作簿保持一致。渲染器回归单独标注，不计作新一轮独立制作。

第二轮独立科学审查仍未接受成稿：下一批试验的判据把所有未满足正向成功条件的结果都叫“不确定”，遗漏明确反向证据。实际当前数据的计算正确，错误在预定判断逻辑。技能新增跨学科的结果分支与反例检查，要求页面、讲稿、计算报告保持一致；没有把该示例的数字或正确答案写入提示词。此后再次封存候选，重新执行无上下文制作。

发布代码审查还发现并修复两处既有验收状态缺口：教学图的输入路径在嵌入后丢失、同一PPTX重渲染后沿用旧审查。补丁保留解析后的资产来源并在成功重渲染后废弃旧画面审查；不改变C3封存的SKILL或排版。详见 [代码审查](CODE_REVIEW_V05.md)。

## 效果验收规则

候选代码与技能封存后，新制作智能体只接收普通制作任务、原始来源、两份原始模板和运行入口。它不能读取旧成品、诊断结论或事先算好的答案；主线程不在制作途中提示它如何完成科学分析或修正页面。制作结束后再独立核对原始数据、论文和最终 PPTX。

如果结果仍不合格，先记录具体失败；通用实现或引导存在缺陷时修改插件，再让新的智能体从原材料开始。单次作者措辞错误与通用渲染器缺陷分别归因，不能把某个案例的正确答案写进提示词。主线程手工修好的示例不能算插件通过独立制作。确定性测试、生成者自审、独立科学审查和视觉审查各自报告，不合并成一个自动质量分数。实际轮次与结果见 [验证范围](VALIDATION.md)。

本轮没有接入用户的 DeepSeek 付费账户。工具调用次数、返工原因和文件大小可以实测；人民币成本、特定 DeepSeek 端点的完成率和目标投影设备效果需要各自的真实测试。
