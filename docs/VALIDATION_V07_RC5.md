# v0.7.0-rc.5 验证记录

日期：2026-10-25。基于 main 的 rc.4 提交 `4e5ade4`，本轮 renderer 为12。环境为 Node 24.22.1，使用锁定依赖，不新增模型请求或运行用户收费账户。

## 软件回归

`npm test` 完整执行：**30个测试文件通过，0失败、0跳过**。本环境的 Node 测试报告按隔离文件汇总，因此不把文件数写成单个用例数。四个新增测试文件包含22项具名回归，并另补封面/导航留白的几何检查；旧版证据、字号、原生对象、受控修改、撤销和交付状态测试保留。

新增验证重点：

- 五套色板的指定文字/背景组合对比度、独立颜色副本和非法 ID。
- 默认无图封面、无图 editorial 空间回收、SVG 与 PPTX 实际细描边，以及显式样式覆盖。
- 目录、章节关联、问题保全、局部目录序号与高亮、8节容量、长文本溢出、坏引用与兼容路线。
- 公开 create/record/build/edit/check 工作流：同一计划进入导航与自定义标题，过渡同时进入 PPTX 备注和 Markdown 讲稿，构建后可修改/移除新字段。
- 封面、目录和章节留白只提醒；正文与结尾 compact 门槛继续阻断，装饰不能刷正文占幅。

首轮回归曾暴露旧测试仍要求 plain 卡片和封面密度阻断，已按新的明确行为更新断言。代码复核还发现并修复构建后新字段无法 edit、自动目录覆盖旧卡片式目录、局部序号冲突及导航序号被误判为正文的问题。未删除科学、字号或越界检查以获得通过结果。

`npm run check` 与 `npm pack --dry-run --ignore-scripts` 均通过。包检查确认14个工具、48种参考页型及9个既有PPTX资产摘要；包版本、锁文件和CLI加载一致。技能的 `quick_validate.py` 及相对链接检查也已通过。

## 实际 PPTX 视觉检查

7页合成样张实际生成 PPTX，并用 `@deepseek-ai/libreoffice-kit` 的 LibreOffice WASM 在96 dpi渲染，字体为 Noto Sans CJK SC Regular/Bold，返回 `missingFonts: []`。制作者与主线程都查看了这些页面：

1. 默认 minimal 文字封面。
2. 无图 editorial 封面。
3. 有细描边的独立卡片页。
4. 四节目录。
5. 四节分节定位。
6. 八节双列目录。
7. 八节双列分节定位。

观察到中文完整、题名与元信息有层级、默认封面没有不相关图像、editorial 不再保留空右栏、卡片存在可见细轮廓。目录中章节名称及其问题均保留，当前节有可见定位。八节样张使用正常长度的农业研究问题，标题30px、问题28px，未见截字或文字重叠；更长文本仍须由容量检查与实际渲染处理。

其中四张原始渲染公开于 [学术视觉与导航样张](../examples/academic-style-v07/README.md)。它们属于合成软件/版式回归，卡片页不是完整报告的固定布局建议。用户提供的三张参考截图只用于理解信息层级与正式程度，没有复制到仓库或作为新封面背景。
