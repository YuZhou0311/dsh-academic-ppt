# 0.10.0-rc.2 安装前审计

基于候选提交 `414317c3b1f09f4d02c840bc92ea00ccf236062f`。目标是统一实际Agent指令链并交付可安装候选，不宣布DeepSeek端到端创作质量已验证。

## 已修正的方向冲突

- 主SKILL、workflow-v010、设计/审稿/协商入口、工具描述和返回摘要统一为证据与构图双轨。六个styleProfile仍兼容，但只是可覆盖的运行时基底。
- 新的designCases通过contract(design)暴露绝对PNG和解释路径；四页均为原十二页中完全原创的结果页，重新通过插件生成并实际渲染。未公开用户原稿及科研源图。
- 新增`design-case`参考来源和合法ID校验，能够用真实契约登记，不发明不可提交的记录。旧academic-style和componentStudies兼容保留，旧稀疏图册加历史技术样张标识，不再作主入口。
- init/context/prepare/build/render/review/check/deliver的原生工具返回和CLI摘要都带对应阶段指导；协作问题仍优先，不被长内容截掉。
- 修复渲染工具可见摘要只列联系表却未列单页PNG路径的问题；render/context/study/template实际单页路径提前输出，长稿明确如何读取其余页清单。官方宿主接入测试新增当前案例PNG和解释读取。
- 无生图时fallback由`select-native-cards`改为`design-evidence-pages`，原生图表/方法图/自由composition继续可用；生图新增真实契约字段 `imageGeneration.requested`（缺省false），不再成为有能力/有卡片就必做的动作。
- 移除“只给研究推理投入注意、设计留给最后处理”的偏向，明确构图/证据整合也需要作者判断。几何、版本及文件操作仍用确定性工具。
- 包版本升级到0.10.0-rc.2；加入离线doctor和版本查询，安装说明明确旧包不含修复、升级后新会话。

## 关键节点：哪些是代码检查，哪些仍需模型执行

| 节点 | 代码能核对的部分 | 不能自动证明的部分 |
| --- | --- | --- |
| 实际加载 | 包版本、19工具、完整SKILL和引用资源 | 模型是否理解并遵循 |
| 能力 | 视觉审稿要求支持的图像能力记录；宿主read_image真实入口另行核实 | 手写supported不证明当前provider看到了图 |
| 来源/故事线 | 来源记录、真实回答字段与有范围委托；proposed不等于批准 | 用户原话真实性、科学判断 |
| 案例学习 | 真实目录ID、预览定位与适配字段 | 字符串不能证明看图，样张不是当前研究证据 |
| 困难页/pilot | 当前PPTX、真实渲染、指定页审稿、设计/证据/故事板绑定 | 样张审美是否达到参考 |
| 扩展与局改 | 明确局部编辑范围，内容改变使原产物审查失效 | 跨页节奏是否好 |
| 实际渲染 | PPTX/PNG/receipt哈希与缺字体检测 | missingFonts为空不证明字重/字形正确 |
| 逐页审稿 | 当前版本、完整页覆盖、四项观察、当前风险回应；needs-fix不被自动升级 | 观察是否准确、美观与专业性 |
| 最终交付 | review而非draft、完整故事板/pilot（六页以上）、当前逐页审查、真实最终意见或委托 | 真人讲述、PowerPoint/WPS实机结果 |

`check-art-direction.mjs`仍是可选旁路证据检查，未伪称已成为自动审美裁判或deliver强制拦截。为避免破坏旧工程，本轮没有增加虚构美学分数或偷偷放松科学/字号/用户确认门槛。
