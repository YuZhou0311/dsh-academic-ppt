## 公开示例重建的原则

随包示例的内容重放必须显式标为离线重建。新工程不继承旧项目的id、修订、历史、artifact、visualReviews或已经确认的视觉能力。模型从原始输入自行制作与执行`npm run demo`重放已写好的记录，是两种不同测试。

输入路径可以迁移，原始科学记录、作者图像、来源、讲稿和布局不能为通过检查而改写。重建若改变实际页面，需要指出改变位置和原因；没有实际查看的新版本不能沿用旧版本的通过状态。

## 恢复入口与发布打包的专项检查

独立检查使用既有公开v0.4资料派生的隔离夹具和真实运行代码，未接触当时仍在制作的C4终稿。中文和空格工作目录、相对来源、图片及分析支持文件均成功导入；题名、brief、design、claims和slides原样保留，来源路径逆向重定位后相同。新工程保持imageInput为unknown、无旧审查、readyForDelivery为false。已有输出目录、工作区越界、来源路径穿越和外部符号链接均被拒绝。

发布辅助脚本审查另复现了两个问题：只比对已有tar成员会漏掉缺件；末尾清单可能覆盖同名文件。修复后按npm的完整打包清单核对文件集合与每个成员字节，在复制前检查所有交付目标，并排他创建每个输出。针对性复验8项通过：完整归档成功，漏文件归档拒绝，六种已有输出均在复制前拒绝且原字节不变。这些是安装与包装的验证，不计作新模型制作或C4质量通过。
