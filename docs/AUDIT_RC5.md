# rc.5：视觉工艺改造与验证边界

## 依据与目标

以用户上传的两份项目答辩PPT、已认可方向的十二页版面实验，以及最新四页DSH PDF对照。本轮只学习页面视觉组织，不把参考中的占位研究内容当事实；没有公开分发用户原稿、图片、Logo或字体。

失败稿仍是白底截图加段落，字级、色面、题签、图像比例与图注邻接没有作为整体处理。因此本轮不以多加“认真设计”要求或增加流程检查代替视觉实现。

## 实际修改

1. `artDirection` 把 structured/editorial/open 变成真实字级、页眉、题签/分组默认值；显式用户字段优先，旧工程不自动迁移。正常Agent新建工程默认structured，底层SDK保留兼容。
2. group提供 band/tab/rail/rule/text；支持paper/soft/accent/ink/plain。深浅底实际计算可读文字色，零内边距的rail不压住首字。
3. figure默认上对齐；图与图注整体对齐，图注紧随实际图像底部，而非容器底部。保持原图比例及已登记viewport，工具不猜科学裁切。
4. 纵向 `extent:content` 测量文本、表格、共享比较及嵌套分组高度，弹性区域取得剩余空间；超过空间时返回逐节点诊断，不降字号或删数据。
5. comparison用同一指标行对照2–4种方法，值为作者提供的原样字符串，不自动计算、不填缺失。statement组织简短条件或命题，不自动生成结论。
6. authoringMap保存主角、阅读顺序、实际节点框和原生对象ID。原VisualPlan保留兼容，真实内部关系单独提供给审查；可检测对象缺失，不能理解图像或自动证明美观。
7. 新增两个原创教材，累计8个；共享指标案例的左侧是标明的弱例，不能当成正样板。当前入口统一指向视觉工艺与相关教材。

19个工具、既有来源/图像输入/预览/协作/样张扩稿/交付机制不变。没有更换模型、读取凭据或发起模型请求。

## 视觉回放

最新失败PDF的三张正文使用相同图像像素，经普通 init/record/plan(compose-page)/build(draft)/render重做。原图没有重绘，原报告读数不变；不能把这份候选称为重新查证后的论文汇报。时间统计口径、长时序曲线与短部署对应、左右方法集合差异在候选中明确保留。未填科学verified或用户confirmed。

第一轮渲染后继续收紧多余高度，调整过淡的强调色、图注短尾行及rail边线首字间距。最终检查逐页实际PNG，不用HTML示意代替。源码回放包保留输入与事件；科学证据不足的草稿风险不以降低阈值消除。

## 检查与限制

测试数量、当前文件摘要和实际命令结果以随交付验证记录为准。本轮增加23项视觉工艺专项测试，并执行原有回归、包结构、正常Host链路和最终TGZ解包检查。

Host测试使用官方运行时及预设回复/测试UI端点，非真实DeepSeek创作。安装检查使用隔离的现有依赖，非用户电脑全新联网安装；未做原生PowerPoint/WPS逐页实机验证。字体文件不随包分发。发布状态为本地候选，未同步GitHub PR/主分支或发布Release。

软件通过只证明相关实现和路径有效；是否达到用户的科研审美与模型稳定创作能力仍需实际输出，不给自动美学分数，不宣称“去AI化完成”。
