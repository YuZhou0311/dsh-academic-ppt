# v0.7.0-rc.4：从论文证据设计真实页面

本版本从远端 v0.6.0（`33c03dd`）重新实施，渲染器版本为 **11**。此前未上传的工作区及参考文件已经丢失；本版本不声称恢复了旧提交、旧成稿或旧验收记录。代码、来源核对和样例制作均重新进行。

## 1. 本轮具体解决什么

用户连续反馈了两种失败：每份报告套同样的小卡片；去掉卡片后，又只剩大标题与零散文字。两者共同缺少的是对科学证据的组织：哪些图表值得放大，哪些条件必须紧邻结果，什么是分支、反馈、对照或推断，哪些文字属于注释。

本轮把创作流程改成：**原文图表盘点 → 参考页面研究 → 本稿视觉方向 → 实际候选 → 全稿 → 科学和画面复核**。模板用于学习主辅证据比例、局部分组、图文邻接和阅读层级。作者为当前证据重新安排坐标，保留有用的卡片或题签，不要求每段套框，也不要求全部去框。

插件不自动发起模型或生图请求。设计由当前宿主模型完成；没有生图模型也能用原生几何绘制实际候选。精确科学图、数据和研究关系不得交给位图生成模型随意补画。

## 2. 自由区域与原生绘图

正文有三种可组合路径：旧 `composition.rows` 保留加权行；新 `composition.regions` 直接指定不重叠的证据区域；`drawings` 描述当前页面自己的局部图形。一个 composition 只能选 rows 或 regions。

```json
{
  "layout": "academic",
  "heading": {
    "box": {"x": 48, "y": 24, "w": 1184, "h": 60},
    "fontSize": 44,
    "lines": ["标题保留完整主张与必要条件"]
  },
  "drawings": [{
    "id": "evidence-reading",
    "width": 1184,
    "height": 500,
    "elements": [{
      "id": "condition",
      "kind": "text",
      "x": 0, "y": 0, "w": 850, "h": 40,
      "text": "测试范围与结果一起出现在主要视图",
      "fontSize": 28,
      "role": "body"
    }]
  }],
  "composition": {
    "regions": [{
      "id": "main-evidence",
      "title": "",
      "heading": "hidden",
      "padding": 0,
      "surface": "plain",
      "box": {"x": 48, "y": 120, "w": 1184, "h": 500},
      "drawingIds": ["evidence-reading"]
    }]
  }
}
```

这是字段片段，不是可直接交付的学术页；完整 slide 还需 ID、来源、论证、时长、备注等字段。首次使用读取 `contract(topic:slide)`，不要从片段猜完整 schema。

坐标采用 1280×720 CSS px。drawing 在自身坐标系中设计，区域承载时等比缩放、居中；区域内不再写 drawing.box。没有 composition 时，drawing 必须提供页面 box。矩形、椭圆、文本、折线与箭头为独立 PowerPoint 对象，SVG 与 PPTX 使用同一个场景。图片只能引用登记资产，原图仍是独立位图，不能把它宣称为可编辑数据点。

`role:group/decoration` 用于分组或装饰，不用于刷内容占幅；`role:data` 的图形必须关联含数值口径的 claim。关系线用 `role:relationship`，作者声明方向和含义。引擎检查端点、零长度线段、越界和压字，但不会自动证明某个箭头在科学上成立。

自由 region 可使用 `heading:hidden` 和 `padding:0`，不再强制每块内容都有标题条和内边距。复杂局部分组放在同一 drawing 内；region 不互相覆盖。自由 region 的高度由 box 明确控制，`align:start` 仅保留旧 rows 的兼容路径。

## 3. 标题、色义与投影阅读

`heading` 支持页标题的自定位置、32–64 px 字号和语义断行。断行后的内容必须与完整标题一致，不能借断行悄悄缩写。标题的实际高度会为后续正文让位。封面仍可用已有 `cover.custom + boxes`，也可用自己的原生构图；不要把作者身份、机构、会议或日期编造出来填位置。

全稿用 `design.direction` 保存视觉思路，用 `design.colorRoles` 记录颜色的含义。例如观测、模型状态、验证误差可各有固定色义；同一个颜色不应在另一页突然变成另一种科学角色。

新建默认政策为：

| 阅读角色 | CSS px | PPT 字号 | 用途 |
| --- | ---: | ---: | --- |
| body | 28 | 21 pt | 必要正文、条件与解释 |
| label | 24 | 18 pt | 轴标签、流程节点、必要图中文字 |
| note | 18 | 13.5 pt | 引用、图注、辅助注释 |

最终场景按实际缩放后字号检查。必要正文不能标成 note 以通过检查。字号不是内容配额，也不要求整页只用几句大字；图表、普通正文和局部分组共同承担信息。投影是否足够清晰仍须查看原图内部文字和真实渲染，政策不能自动读懂位图内的小字。

旧序列化设计没有 projection 字段时保留旧几何。用户显式设置的字号不被偷偷缩小或覆盖；不满足已选政策就报告冲突。更新 design 时省略 projection/direction/colorRoles 会保留已有设置。

## 4. 内容必须真正入画面

`slide.contentChecks:[{id,text}]` 可登记必须出现在主要视图的关键条件或数字。例如测试年份、样本数、负 R²、计量单位和验证方式。

检查读取实际场景中的正文、原生表格和图表标签，不读取讲稿或来源记录；图注、引用和书目不代替主要内容。它保留科学单位大小写，正负号和完整数字边界，不把 `1 mm` 当作 `1 mM`，也不把 `1e5` 中的 `5` 当作独立结果。

这是作者指定文字的保全检查，无法代替事实核验，也不会 OCR 论文原图。原图中必须读到的条件，需要实际检查其尺寸和裁切，必要时在图旁以可读字级同步标注。缺少 contentChecks 不代表没有关键条件；作者仍需完成图表盘点和逐页覆盖复核。

定量证据页如果只剩文字，会得到 `quantitative-evidence-text-only` 提醒。空框、装饰图片和孤立巨字不算证据载体；未识别的自绘图可能误报，所以这是复核提醒，不是自动审美评分。

## 5. study：先画出候选，再作选择

`academic_ppt_study` / CLI `study` 读取当前工程的来源和设计，导出作者提供的 2–6 个实际候选。推荐同一轮放两个封面和两个困难证据页，确保比较的是可见构图。

```json
{
  "projectPath": "talk/project.json",
  "expectedRevision": 3,
  "candidatesPath": "talk/candidates.json",
  "outputDir": "talk/study-01",
  "render": true,
  "fontDirectories": ["fonts"],
  "externalReferencePrompts": true
}
```

candidates.json 是 UTF-8 数组，每项 `{id,label,slide}`，slide 为完整页面记录；文件不超过 1 MiB。DSH 常驻工具定义只公开文件路径，完整 slide 契约按需读取；CLI/core 保留内联候选入口。输出目录必须尚不存在。

输出包括实际 SVG、原生 candidates.pptx、并列 HTML、候选记录和摘要；`render:true` 才尝试生成实际 PPTX 图片/PDF。渲染引擎不可用会明确显示状态，不能拿 SVG 预览冒充 PPTX 实际画面。可选提示词用于进一步获取外部视觉参考，不请求账户或自动调用生图服务。

候选中的来源 ID、数据关联与内容几何仍需有效；不对四页小样强加全稿的页数或完整书目门槛。候选不改原工程、不写入正式审查、不自动选择赢家。作者需看图记录理由，再把选定结构写回正式 slide。

## 6. portfolio：比较明确指定的报告

`academic_ppt_portfolio` / CLI `portfolio` 接受 2–12 个不同工程路径，只读取这些文件，不扫描其他工作区。结果提供可并列复核的页对和封面结构。

比较忽略文字、颜色、ID，以及数据标记所表达的数值长度。改变柱高不构成新构图。包含图和解释的 paper 精读页仍计入正文，纯书目信息导读页排除。重复的同一工程副本会被拒绝。

该比较基于作者记录的几何骨架，不能判断模型是否独立思考、像素是否近似或作品是否原创。没有高相似提示也不等于设计好。相同实验的可比图保留共同尺度，跨稿同构较多时需要并列看实际全稿。

## 7. 交付与本次重建边界

正式流程仍为 build(review) → render → 看当前全部页面 → review → check。科学判断与逐页视觉观察分别记录，不能把导出成功当作审查通过。`referenceIds` 可在自定区域呈现完整书目，长题名和作者元信息按实际行高排版。

本轮真实论文来源是 Cheng 等（Frontiers in Plant Science，2022）、Zhuo 等（Remote Sensing，2019）和 Shahhosseini 等（Scientific Reports，2021）。两个新上下文作者从相同论文和任务各自制作完整报告，随后复核。实际数量、返工、文件哈希与限制以 [本轮验证记录](VALIDATION_V07.md) 为准。

没有恢复已经丢失的原始用户参考 PPT，也没有在本次工作中重新查看它的页面。历史 v0.5/v0.6 示例与验收继续保留当时身份。当前模型的两个示例不能推导为 DeepSeek 收费账户、DSH Desktop/Web、PowerPoint/WPS 全平台或十次独立生成的稳定成功率。
