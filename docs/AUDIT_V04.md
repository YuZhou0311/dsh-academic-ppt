# v0.4 问题审计与改动依据

审计日期：2026-10-20。基线代码为 v0.3.0，仓库提交 `7cee508b5beb87108f0fdba701f6f2dc0c68b576`。输入为用户提供的一次 DSH 会话及子任务日志、19 页农业遥感汇报、两份分别 19/20 页的理想参考稿。此处公开方法与聚合结果，不分发私人会话、原始模板或其中的研究材料。

## 1. 结论及证据边界

问题由研究分析、执行协议、排版和验收共同造成。原会话实际做过研究，也正确区分过“受益像元占比”和“RMSE 下降”等口径；不能概括成全部虚构。但大量信息没有形成贯穿全稿的论证，介绍卡片占据较多页面，封面与正文没有区分，语义关系和最终验收出现了具体错误。

用户后来在原会话中明确允许使用插件的 48 页参考库。因而“不再直接读取理想模板”不能单独认定为违反当时已更新的指令。日志也没有显示执行者实际读取 `slide-records.json` 后逐段复制其长正文；直接抄袭不能作为已证实事实。可以确认的是，旧工具默认暴露教学文件入口，参考布局会继承示例题签，产物有较强模板化结构。这些是本次去除内容诱导与加强论证的依据。

## 2. 执行过程中的可定位故障

| 观察 | 证据与影响 | v0.4 对应实现 |
| --- | --- | --- |
| 保存成功后返回失败 | 6 次 slide-content 修改已推进 revision，但返回对象包含 `preservation: undefined`，被 DSH lossless JSON 拒绝；随后使用旧 revision 重试发生冲突 | `core.mjs` 仅在有值时返回 preservation，`tool-contract.mjs` 约束 JSON 返回值，回归覆盖提交后的可序列化性 |
| 错误信息误导重试 | 工程目录被误当作 `projectPath`，3 次错误表现为 FILE_LIMIT，执行者转而排查图像大小 | 精确返回 `PROJECT_PATH_IS_DIRECTORY`，工具参数说明必须是 init 返回的 project.json |
| 原要求被放宽 | 初始工程要求全文，后来被改成 false；原任务的 IF 条件也未准确体现在初始化门槛中 | 已登记的全文、篇数、IF、逐篇导读要求不能通过替换 brief 降低或删除；技能要求一开始准确登记用户约束 |
| 阅读声明超过实际观察 | 提取完整文本被当作完成全文阅读的依据，实际读取范围并不总覆盖所声称章节 | 技能区分获取、提取、阅读和观察；来源 analysis 与具体 locators 支持复核，不宣称代码能验证执行者是否诚实 |
| 最终审查跨版本合并 | 最终 r23 后实际看图只覆盖第 17、18、19、11 页，却登记同一最终哈希的 19 页全检；此前版本曾看过其余页 | 每页 observations 与当前哈希绑定；明确禁止跨版本回填；存在 issue 不能 passed |
| 已知缺陷仍被通过 | 最终记录承认图例或文字显示问题，但仍声称 passed | 已知几何问题阻断 review 构建，未解决视觉问题阻断 passed；静态估算仍须真实渲染补足 |

原会话最终交付说明确实披露了两篇仅有摘要、两篇低于 IF 门槛等限制。审计没有将它描述为完全隐瞒；问题是工程门槛被改写后仍走到了正式交付流程。

DSH 对工具输出的规范依据：[官方工具开发说明](https://deepseek-harness.github.io/deepseek-harness/en/reference/cookbook/adding-a-tool)。大 schema 进入提示、返回值必须符合规范 JSON，是可减少无效执行和上下文负担的工程边界。

## 3. 对照 58 页实际 PPTX

三份文件均用 LibreOffice 实际渲染，先查看全部概览，再放大关键页面。最初运行环境没有中文字库，补充 Noto Sans CJK SC Regular/Bold 后重新渲染；没有把缺字当成用户原稿问题，也没有将 LibreOffice 的检查描述成 PowerPoint 实测。

| 统计 | 生成稿 | 参考稿一 | 参考稿二 |
| --- | ---: | ---: | ---: |
| 页数 | 19 | 19 | 20 |
| 非空白可编辑文字字符数 | 6,492 | 3,739 | 4,084 |
| 单页字符数中位数 | 342 | 170 | 232 |
| 图片对象 | 5 | 58 | 37 |
| 原生表格 | 2 | 0 | 3 |
| 正文字号众数 | 18 pt | 18 pt | 18 pt |

数量只描述对象与密度，不是质量分数。差距不能简单归因于正文字号小：三个稿件正文众数相同，主要差在用途层级、主证据面积、关系表达和页面容器分配。

具体观察：

- **生成稿第 1 页**使用了普通内容页标题位置和 30 pt 标题，大片空白没有形成封面阅读中心。参考稿分别使用 88 pt、50 pt 的独立主标题；可迁移的是封面层级，不能机械复制 88 pt。新默认封面使用 45 pt 原生标题并预留身份区。
- **第 6 页**称为核心闭环，实际只显示一条观测到模型的箭头，后续节点断开且没有反馈路径；窄框里的单位表达贴边。**第 7 页**将四类策略用箭头串联，而正文指出它们并非替代关系。**第 8 页**的步骤缺少清楚连接或编号。新指导要求先确定并列、顺序、反馈、层级等关系，再构图；现有语法无法自动证明关系科学正确。
- **第 10 页**小表集中上方、页脚堆内部文献 ID 和 DOI，证据与留白分配失衡。新正文来源简化，完整元数据留在参考页/备注；短表之后的说明跟随实际表高。
- **第 11、12 页**把原图与口径解释相邻放置，属于应保留的方向。改进目标不是把所有原图改成装饰，也不是把全部页面换成新卡片。
- **第 16、19 页**的参考文献被附录打断，末页只剩一篇且重新编号。技能要求连贯安排主稿与备份页，渲染器已改为全局一致编号。

参考稿自身也存在问题：参考二第 10 页标题换行压到正文，部分多面板图模糊；第 7、8、18、19 页有占位文案，第 16、17 页有示例数值。因此模板学习必须同时记录可迁移设计和不应继承的缺陷。

## 4. 成本与负担

按主会话和子会话中唯一 assistant message 的 usage 去重，避免重复计算流式事件：

| 项目 | 记录值 |
| --- | ---: |
| 模型步骤 | 358（主 284，子 74） |
| 工具调用 | 484（主 375，子 109） |
| bash 调用 | 279 |
| build 调用 | 12：5 次阻断、7 次生成 |
| 实际 PPTX 渲染 | 7 轮 |
| 主会话墙钟时长 | 46 分 31.685 秒 |
| 非缓存输入 token | 356,253 |
| 缓存读取 token | 79,533,824 |
| 输出 token | 309,813 |

缓存读取约占已记录 token 总量的 99%，不是一次新增了八千万 token 的文本。内部检索模型请求存在 usage 不完整的情况，且没有当时账户单价、折扣和账单明细，不能据此复算人民币金额。

以注册工具的 `name + description + parameters` 压紧 JSON 字节数比较：v0.3 的 11 个工具为 **42,293 字节**；v0.4 的 12 个工具为 **12,860 字节**，减少 **69.6%**。这是工具定义字节，不是 tokenizer 测量，更不是费用下降比例。详细记录契约仍在需要时完整读取，执行端保持完整类型、长度和数量校验。

另外减少已知成本来源：保存后误报、工程路径误判、每轮重读全文/大工程、无目的样式轮换，以及正式全稿前没有难页验证。约三页试样和一轮全稿是目标预算；存在具体失败项时仍必须修复，不能用少渲染掩盖缺陷。[DeepSeek 缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)

## 5. 防止针对案例“作弊”

没有把农业题目、特定作者或论文数字写进生产校验规则。新增规则适用于来源、证据、推导、页面、模板内容隔离与渲染版本。模板长段原文检测比较整个随包教学库，不以某个测试句子为黑名单；它只能识别明显复用，不能证明原创性。

原会话最终记录重建后，仅只读运行新的结构规则，得到 5 项来源 analysis 缺失、29 项 claim reasoning 缺失、5 项推断/方案前提缺失、14 项正文 argument 缺失。这 **53 项是新记录契约的缺项，不是 53 个科研事实错误**；没有恢复伪造图像、验收或哈希，也没有声称已重做原来的科学报告。

独立前向试用采用真实理论/机器学习论文和明确标识的材料教学数据，执行者只拿原始任务与本版技能，不给审计答案，不允许修改校验器。产物与具体结果见 [验证记录](VALIDATION.md)。软件回归、样例重建、独立制作、真实 DeepSeek 付费效果和目标 Office 显示是不同证据层，分别报告。
