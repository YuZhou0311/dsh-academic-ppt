# v0.3 视觉设计与图片适配方法

这轮改进依据用户对 v0.2 实际样例的六点反馈：密集竖图适配不足，文字层级弱，小字零碎，卡片同质化，图文缺少层次，以及对模型的审美指导过于抽象。参考仍是用户提供的两套学术模板；具体结构观察保留在 [USER_TEMPLATE_STUDY.md](USER_TEMPLATE_STUDY.md)。

## 1. 先处理图片与阅读任务的匹配

截图中的 PLA 页把多任务完整竖图放在左栏，曲线细节放在右栏。完整图内部的信息量远超该区域的阅读能力，下方短说明也没有把空间转化为充分解读。

新的选型从图的职责开始：主证据、局部证据或定位。记录当前要看的面板、必要轴/图例/对照、原始像素与最小必要标签高度，再对候选槽位做几何估算。密集复合图承担读数或面板比较时，先选相关面板；完整图的存在不能挤小主要证据。

`academic_ppt_reference` 的图片查询使用真实参考槽位返回最多三个候选，并报告具体可读性问题。选择还需依据科学内容和实际画面。尺寸元数据不等于视觉理解，测量声明不等于自动核实，返回候选不等于验收通过。

固定页型都不适合时，无 `referenceTemplateId` 的 `figure-focus` / `figure-split` 页可通过 `figureBoxes` 与各卡片的 `box` 定义新的图文比例。自由区域继续遵守图像保全、边界和实际画面检查；科学关系与阅读路径先于坐标。

完整工作步骤与字段见 [图片选版](../skills/dsh-academic-ppt/references/figure-selection.md)。

## 2. 用视觉层级表达学术信息

| 用户反馈 | 制作动作 | 复核的问题 |
| --- | --- | --- |
| 密集竖图无法读 | 先选面板/换构图，区分证据与定位 | 观众能从页面读出当前讨论的关系吗 |
| 字号和颜色没有层级 | 主标题、区域标题、正文、引用分级，正文局部强调 | 第一眼是否能看到主题和关键变量 |
| 顶部和图下小字过多 | 省装饰 kicker，合并重复出处，重要限定保留正文尺度 | 是否把需要理解的信息降成脚注 |
| 卡片单一、关系不清 | 用语义色与题签/侧标/开放文字/边线表达并列、流程、条件和限制 | 同色同形是否确实同类，异类是否有可见区别 |
| 图像与页面分离、缺层次 | 框线贴合实际图像，选择性使用统一轻阴影 | 是否改善分组而没有增加装饰负担 |
| 模型缺少具体审美指导 | 短设计记录、有限候选、难例先行、实际 PPTX 复核 | 是否执行了规则，还是只描述“高级、丰富” |

颜色与文字同步编码。方法使用蓝色方向，设置使用蓝灰，观察结果使用青绿，局限使用赭红，待检验方案用紫色或虚线；同一对照保持一致结构。原图内数据颜色保留作者定义，解释层不得赋予冲突含义。

`card.emphasis` 指定正文中最多四个精确片段，保留为可编辑富文本。`asset.displayCaption` 负责简洁上页图注，完整说明、出处、版本和许可仍保留。`asset.treatment` 控制轻框与阴影，图像完整原始媒体不变。

`asset.displayLegend` 将准确核对的原图图例转录成独立可编辑文字与短色线，预留足够空间。原图中的颜色仍表达作者数据系列，不能按卡片角色改色。部分表格页型会让解释区跟随实际表高，避免行数减少后留下断开的大片空白；指标总块另有溢出预警。

主标题、正文等字号与标签投影预检值是工程起点，不是全场景显示保证。信息密度也不使用固定留白率或卡片数打分。详见 [视觉决策](../skills/dsh-academic-ppt/references/visual-decision.md)。

## 3. 对 DeepSeek/DSH 的执行约束

将一个复杂制作任务拆为可核查的小步：读证据，观察图，选关系，定层级，构建，再审查。普通页面复用已经确定的视觉语言，最密原图、最长标题和复杂机制页优先验证。每轮只读取当前参考与相关记录，候选布局控制在两到三个。

插件依据宿主实际模型与端点能力安排视觉任务。`unknown` 或不支持图像时，可以完成结构检查，但不得登记视觉通过。模型能力、推理预算或上下文长度不直接换算为审美评分，也没有以当前例子证明任何模型的普遍优劣。执行细节见 [DeepSeek 指导](../skills/dsh-academic-ppt/references/deepseek.md)。

## 4. 如何复核本轮改进

先看连续缩略图中的主次与节奏，再逐页检查真实 PPTX 渲染的正文、原图标签、图注、边框和阴影。特别检查完整竖图、长题名、结果与限制同页、短文本区域及中文混排。颜色、字体和结构检查必须与科学口径和裁切语义分开报告。

这份文档记录设计方法和实现接口；软件与产物的实际验证范围以对应版本的验证记录为准。用户只要求小卡片时继续锁定已认可整页，不能因新的视觉规则擅自扩大修改范围。
