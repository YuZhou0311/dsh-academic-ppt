## 2. 两份原模板与新参考库

本轮实际读取并渲染用户提供的两份源 PPTX：20 页重点项目结题答辩模板与 19 页重点研发计划模板，共 **39 页**。逐页查看缩略图，并放大代表性的双面板、图文交错、题签和实验流程页。具体观察与对应改动见 [USER_TEMPLATE_STUDY.md](USER_TEMPLATE_STUDY.md)。

原生盘点在两份源文件中分别取得 12 和 3 个当前支持的组件，同时报告 322 和 400 条不支持记录。源渲染存在字体替换；这里证明实际研究过源模板，不声称所有母版、阴影、复杂组合或特效已经无损导入。

新制参考包包含 **48 页原生 PPTX、8 个分类分册、48 张 SVG 预览、8 张实际 PPTX 分类拼图、HTML 画廊、几何索引与逐页输入记录**。数据图使用明确标记的合成教学数据；用户完整源模板和原有研究素材不公开分发。

实际用 LibreOffice kit 渲染完整 48 页，查看 8 张分类拼图，再原尺寸核对长题名、强化学习闭环、多行表格、完整图与局部图、训练/验证/测试分支和书目页。最后修订将 T03 的默认验证标签改为中性表述，T15 改成按独立单位划分到三个集合的分支；与上一轮比较仅 3、15 页 PNG 改变，其余 46 页一致，变化页已再次查看。不能用集合间串联箭头代替数据划分关系。

模板库本次静态检查为 **0 errors / 0 warnings**，48 页实际渲染的 `missingFonts=[]`。画廊里的实际 PPTX 拼图与 SVG 预览有明确身份，未把 SVG 当作最终导出画面。最终 PPTX 摘要和审查记录见模板 [manifest.json](../skills/dsh-academic-ppt/references/templates/manifest.json)。

## 3. 真实论文示例与可编辑成品

[随包示例](../examples/README.md) 是 PhenoAssistant 单篇精读，**14 页、670 秒，约 11 分 10 秒**。它包括原文完整题名、三个案例的方法与数据、两幅完整授权原图的不同展示视窗、工具链评分、不同评价分母、读图失败边界以及待验证研究方案。

所有科学数字、原文位置和解释身份在 [science-demo.mjs](../examples/science-demo.mjs) 中保留。Figure 3/4 的出处、原图 SHA-256、许可和各视窗说明在 [ASSETS.md](../examples/ASSETS.md) 中保留。原图保持完整媒体；可编辑解释层与原图分开。论文原实验使用 GPT-4o 的事实有来源，不能将论文评价结果宣传为 DeepSeek 或本插件的实测效果。

本次生成 PPTX、HTML、讲稿、证据清单和图像清单，再对实际 PPTX 生成 14 张 PNG 与 PDF。制作环境逐页查看，并放大长题名、PLA 轴与图例、统计结果、相关系数、表格和研究方案。检查详情、文件摘要与范围见 [VISUAL_QA.md](../examples/VISUAL_QA.md)。原生小组件单页样例也单独实际渲染和查看。

本次实际渲染采用 **@deepseek-ai/libreoffice-kit 0.1.5 / WASM**，提供 **Noto Sans CJK SC Regular/Bold**。运行时字体不随插件分发。论文示例的离线脚本仍将模型图像能力设为 `unknown`，复用者不会自动继承本次 ChatGPT 图像审查，也不会自动获得视觉通过状态。

## 4. 本轮实际画面暴露的问题与修复

| 观察到的问题 | 修复方式与复核 |
| --- | --- |
| 中文自然行高与相对行距叠乘，实际画面比场景估计拥挤 | 普通文字及每个原生表格单元格使用明确点行距，重建实际 PPTX |
| 接近列宽的中英混排在原生表格中多折一行，图注压住最后一行 | 保留文字内宽余量，预先分行后计算行高，未缩小正文；同一反例实际 PDF 中最后行与图注间隔 6.864 pt |
| 长原图授权串从书目左栏伸入右栏 | 按资产逐行记录 Fig./面板/许可证，完整保留来源并实际重渲染 |
| 未阅读全文的 metadata-only 记录被贴上全文阅读标签 | 按真实阅读状态生成标签，同一输入实际验证 |
| 过长书目 ID 拆行 | 编号位使用短索引，原 ID 保留在书目信息中 |
| 表格未显式关联来源仍可构建 | 缺少 `table.sourceClaimIds` 产生 error，页上其他 claim 不替代表格来源 |
| 不支持的 subtitle/takeaway 只警告，可能丢失科学限定 | 未消费的字段升级为 error，要求换合适构图或组织内容 |
| 字体存在但 `ₜ` 显示方框 | 正式示例使用有字形的 `s_t/a_t/r_t`；保留原始反例以说明 `missingFonts=[]` 不能替代特殊符号视觉检查 |

静态边界、文件摘要和字体报告都不能单独证明最终可读。实际有效的视窗坐标，也可能裁掉解释必需的坐标轴或对照；代码只验证几何，不自动理解图中科学语义。

## 5. 独立 CLI 演练与小卡片范围保护

另一执行者从技能与按阶段参考出发，调用公开 CLI，选择六个 reference，独立制作六页明确标为合成内容的教学工程。覆盖九种工具；没有将此次演练称为全部十一工具、全部 48 页、真实 DSH GUI 或 DeepSeek 端到端评测。

原始单卡修改仅将 S05 指定卡片的 `style` 从 `academic-side` 改为 `academic-tab`。独立解包 PPTX 核对：共 **141 个顶层对象，目标之外 137 个对象保持**；其他 **5 页 XML 字节一致**，全部 **6 页备注 XML 一致**。卡片内容、数值、外框及证据关联保持；两份嵌入 PNG 均逐字节等于完整源图，裁切通过原生视窗实现。卡内文字位置可随结构调整，不承诺每个文字子对象的坐标恒定。

同一批输入复验了表格显式来源、完全无关联表格、未消费 subtitle、未消费 takeaway 四个反例，均被 error 阻断。修复后的表注、阅读状态和书目索引又做了实际渲染。该工程故意保留 `ₜ` 缺字输入，因此视觉状态仍为 **needs-fix**、`readyForDelivery=false`，没有为凑“全部通过”改变测试输入。完整范围、时点与摘要见 [独立审查](forward-review-v0.2.0.md)。

较早的 [validation-audit.json](validation-audit.json) 是 v0.1.0 时点的历史审查，保留其原始源文件摘要；其中工具数和示例范围不代表本版。

## 6. 依赖与发布检查

根工程审计只约束本源码与锁文件。PptxGenJS 的传递依赖通过根 overrides 固定；插件作为依赖安装时，其自身 overrides 不自动约束 DSH profile 的依赖树。目标宿主需要依据实际安装树检查，不能从本仓库根审计外推。

发布采用明确文件清单，包含源码、技能、文档、测试、新制参考资产、授权原图和必要成品；排除依赖目录、运行时字体、用户原始模板和临时工程。安装 `.tgz` 与完整源码归档的用途不同：前者适合加载插件，后者含根锁文件与开发测试。

## 7. 未完成的效果验证

本轮未执行真实 DSH Desktop/Web GUI 的完整安装会话，没有指定 DeepSeek 账户的模型端到端质量、耗时和成本实验，也没有 PowerPoint/WPS GUI 全平台编辑验证。模板风格与不同主题的适配仍需要用户在真实汇报中评价。48 页参考库、1 页小组件样例与单篇 14 页示例的实际检查，不能自动证明五篇长综述或任意作物主题都达到相同效果。

这些边界不阻止使用现有可编辑产物，但必须与已完成的软件测试和实际画面检查分开。后续比较评价设计见 [DESIGN.md](DESIGN.md#8-怎样评价是否比通用流程更有效)。
