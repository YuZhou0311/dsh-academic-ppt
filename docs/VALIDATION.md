## 真实论文示例与实际 PPTX 渲染

[随包示例](../examples/README.md) 为 PhenoAssistant 单篇研究的 **9 页、420 秒**汇报。全文题名、原图、统计分母、验证场景和待验证研究提议有明确区分。它不是原先五篇综述的重新交付。

本次实际完成：

- 用模板工具读取本项目自制的原生参考 PPTX，保存 profile，并在论文导读页使用两个真实提取的组件 ID。
- 用同一套工具创建工程、登记证据、分批加入页面、生成 PPTX、HTML、备注与来源清单。
- 从插件目录以外的工作目录运行示例，使用受控路径；源码和生成脚本不依赖本次机器的绝对路径。
- 用 **@deepseek-ai/libreoffice-kit 0.1.5 / WASM** 读取生成的 PPTX，实际生成 9 页 PNG 与 PDF。
- 用官方 **Noto Sans CJK SC Regular / Bold** 检查中文。实际渲染曾暴露图表数据标签继承 Arial；明确设置标签字体后重建，最终渲染记录的 `missingFonts` 为空。
- 对 9 页实际 PPTX 画面逐页查看，重点放大完整英文题名、论文原图与图注、17/3 数据标签、卡片边界、来源和流程连线。未观察到遮挡、截字或源图拉伸。

示例最终结构检查为 **0 errors / 0 warnings**。视觉检查由本次有图像能力的制作环境完成，**未调用 DeepSeek 模型**，不能作为 DeepSeek 端到端效果实验。离线示例默认保留 `imageInput: unknown`；重新运行不会继承本次视觉审查或自动变成“审美通过”。

## 小卡片局部修改的独立核对

另以 3 页明确标注的测试工程进行技能正向演练：只把第 2 页指定卡片从开放框改成纸面投影。除工具返回的语义比较外，再独立比较 PPTX 中的实际对象与文件。

结果：第 1、3 页 XML、全部 3 份备注、嵌入图片、讲稿、证据与资产清单逐字节相同；目标卡片以外 **36 个场景对象**保持。卡片文字和 **3/4** 数值保留。

保留边界也已查明：目标卡片的内部标题下移 19 px，其余文字下移 12 px，正文框高度相应调整。因此承诺的是卡片内容、外框与目标外对象保持，**不承诺样式变化后卡内每个文字子对象坐标仍相同**。这一点已经写入技能与工具返回。

## 依赖与发布包

本次在**源码根目录、按本锁文件安装**后运行 `npm audit --omit=dev`，最终结果为 **0 个已报告漏洞**（2026-10-20）。该根工程通过 overrides 将 PptxGenJS 的传递依赖 image-size 固定为 2.0.4。插件作为依赖安装时，自己的 overrides 不会自动约束 DSH profile 的宿主依赖树；因此此结果不能外推为实际 DSH 安装后的审计结果。该审计也只代表当日 registry 的已知报告，不等于软件不存在漏洞。

GitHub 源码发布清单采用允许目录，保留源码、技能、文档、测试、参考模板、授权原图与必要示例；排除依赖目录、运行时字体、临时工程、初轮不安全探针和无关历史文件。`npm pack` 安装包与 GitHub 自动生成的完整源码归档用途不同：前者用于安装，不附开发测试和根锁文件；后者包含二者。
