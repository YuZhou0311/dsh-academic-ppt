# 学术叙事与设计（v0.7.0-rc.5）

本轮同时调整工作流、契约、渲染和检查。目标是让研究问题、证据和结论形成一条听众能跟随的路线，并以克制的学术视觉表达这条路线。正文仍由当前会话模型依据材料自主设计，插件不会根据学科名自动套模板或编造发现。

## 1. 先建立整场报告的问题路线

在完整的 brief 记录中增加 `narrative`：

```json
{
  "throughline": "先界定跨情景评价的问题，再解释独立验证设计，最后说明现有证据的适用范围。",
  "sections": [
    { "id": "question", "title": "研究问题", "question": "当前比较要回答什么问题？" },
    { "id": "validation", "title": "验证设计", "question": "哪些证据能够检验这个判断？" },
    { "id": "boundary", "title": "解释边界", "question": "结论在哪些条件下成立？" }
  ]
}
```

这里的内容仅演示字段，不是任何研究的预设结论。`throughline` 应说明本次问题与论证的连接，`sections` 为2–8节，每节有稳定 ID、标题和需要回答的问题。综述可以围绕研究分歧组织，论文精读可围绕关键机制与证据组织，开题可围绕缺口与验证组织；不强制所有任务套同一章节顺序。

正文页保留原有 `argument`，另加 `sectionId` 指向所属章节。不要把完整题名、逐篇论文标题或摘要机械当作故事线。

```json
{
  "sectionId": "validation",
  "transition": "这组比较只覆盖同一观测条件，下一节需要说明跨情景外推还缺少什么证据。"
}
```

`transition` 同时进入原生 PPTX 备注和导出的 Markdown 讲稿。它不会自动加进画面；需要当场可见的转折，应同时在准确的页标题、`subtitle` 或正文中表达。完整内容不会被隐藏在讲稿后当作已显示。

## 2. 目录、分节和正文使用同一套章节名称

- `layout:"roadmap"`：没有显式 `agenda` 时，从 narrative 派生整稿路线、章节名称及各节问题。
- `layout:"section"`：用 `sectionId` 指定当前章节，从同一计划派生编号、名称及目录高亮。`subtitle` 可说明进入本节的原因。
- 其他正文：`sectionId` 派生 `section` 标签；自定义 `heading` 也保留可见章节定位。用户明确设置 `chrome.showSection:false` 时尊重该选择。
- 显式 `agenda.items` 支持 `title`、`sectionId` 和 `question`，可制作局部导航；`active` 使用当前条目从1开始的索引。

不会自动插入任何幻灯片。短稿可以只保留轻量章节标签，长稿宜先给出路线并在重大转折处使用分节页。无需每节都增加一张空过渡页。自由构图的路线页可用 `composition`，不要同时填写需要原生导航消费的 `agenda`。

检查区分两类问题：坏 ID、重复 ID、同一章节名称/编号冲突和高亮冲突属于确定性错误；缺目录、漏章节内容、缺过渡、章节回看和结尾缺显式回应属于需要作者判断的提醒。检查不能证明论证成立，也不会用关键词相似度代替内容审查。

## 3. 克制、可选择的学术色板

调用 `academic_ppt_contract({"topic":"design"})`，读取 `academicPalettes` 和 `defaultPalette`。把选中项的完整 `palette` 写入 `design.palette`，按需要调整，并在 `design.direction` 中说明它怎样服务当前证据与阅读层级。

| ID | 视觉方向 | 选择依据 |
| --- | --- | --- |
| `blue-slate` | 深蓝与石墨 | 新工程默认，突出题名和清楚层级 |
| `forest-stone` | 墨绿与暖灰 | 当前证据适合低饱和绿色时使用 |
| `indigo-gray` | 靛蓝与冷灰 | 需要克制的冷色标题与辅助强调 |
| `burgundy-stone` | 酒红与石灰白 | 需要正式的暖色主调与中性正文 |
| `graphite-blue` | 石墨与灰蓝 | 原始图表本身已经多彩时减少干扰 |

这些是独立设计的可调候选，不是学校或期刊官方配色。不要自动把农业绑定绿色、AI绑定蓝紫。图表中的实验组、变量与来源色义独立核对，同一含义跨页保持一致，并用文字或线型辅助辨认。色板的文本对比度回归覆盖白色和浅底场景，不代表任意自定义组合都已验证。

## 4. 封面靠信息层级形成设计

新工程默认 `system.cover:"minimal"`，以完整研究题名、报告性质和真实身份形成重心。`editorial` 无图时不再保留右侧空色栏。已有 `framed`、`project`、`split` 和 `custom` 形式仍可按内容选择；自主构图继续使用 `custom + boxes`，不要求固定标题坐标、横条比例或唯一字体。

默认不放封面图片。只有能够识别本研究对象、装置、场景或方法的图片才有理由进入封面，且必须登记来源与用途。不能为填补留白放通用农田、芯片、地球、科技纹理或不相关图标。

用户参考只迁移正式程度、题名层级、对齐、色彩克制度等抽象原则。截图不是 PPTX，不调用 PPTX 解析器处理截图；只有封面参考时，不推断正文也应使用同一条带和比例。机构标志、项目名称、人员、旧图表和具体装饰组合不会自动成为新报告素材。

## 5. 卡片有边界，证据有自己的结构

新工程 `cardDefaults`：

```json
{ "surface": "outline", "radius": 4, "padding": 16, "accent": "none", "elevation": false }
```

轮廓为1.2px细线，导出为0.9pt原生 PowerPoint 线条。独立解释、条件组或边界卡可据此辨认，不靠粗色边、重阴影或大圆角建立层级。开放旁注可显式设 `appearance.surface:"plain"`，已有明确外层分组时避免重复套框。表格、流程、公式和证据图不应全部转成同款卡片。

封面、目录和章节页的留白只触发视觉提醒。正文与结尾仍保留 compact 最大连续空区门槛，背景、卡框和装饰不能刷内容占幅；原始科学图内部留白不受罚。字号、越界、遮挡、来源与必要条件检查继续执行。

## 6. 验证与兼容

包版本为 `0.7.0-rc.5`，renderer 为12，schemaVersion 保持1。新增叙事字段可选，旧序列化设计与显式卡片样式保持；原有 preset 默认保留，仅新工程默认明确选择 minimal/rule/line 等参数。旧导出需重新构建与复核。

正式复核先读整稿标题、章节问题与过渡，确认结尾回答中心问题，再查看所有实际 PPTX 页面。自动检查和单个示例不能保证任意模型都生成优秀原创学术报告。本轮实测与环境边界见 [VALIDATION_V07_RC5.md](VALIDATION_V07_RC5.md)。
