# 四个实际协作节点

先确定默认原创或用户模板，再让用户决定研究取舍与真正看到的表达效果。完整节点顺序和记录见 [workflow-v091.md](workflow-v091.md)。颜色、边界、语言、层次与封面属于完整方向，不拆成七轮参数问卷。作者负责把用户的意图变成可用页面，不能把日常对齐、裁切修复和取图责任推回给用户。

## 先复用已有信息

读取本次请求、反馈和工程中的决定，区分已确定、已明确委托、尚待讨论。用户提供优秀参考时，先指出实际观察到的特点，不让用户重新描述整套模板。继续工程或局部改稿不重新启动整稿问卷。

用户明确将某些决定交给作者时，在其真实范围内继续，并记录delegationTopics。只有“帮我做PPT”“开始吧”或“专业些”不能解除协作；“配色你定”不解锁故事线或最终审查。已有明确选择和授权不重复问。

受众、时长、研究范围或材料缺失如果会实质改变成果，先完成能够独立推进的工作，再一次提出最有价值的少量问题。不要为形式收集无关偏好。

## 节点 0：默认原创或用户模板

未知时先展示默认原创设计、参考模板提炼、明确套用模板三种方式及区别，再等待真实回答。写入consultation.source的mode/status/userResponse；参考或套用还要实际templatePaths。已提供文件但用途不明时只问学习还是保留版式，用户已经明确选择时沿用。

无回复、缺少提问工具、尚未上传都不能转成默认同意。没有提问工具时在聊天中问并结束本轮；等附件可整理证据，不冒充已读模板或直接完成整稿。

## 节点 A：共同确定故事线

初读来源后，给出这份报告的具体中心问题、推荐推进顺序、关键证据和缺口。有两种合理路线时，说明各自取舍，不给仅改标题的伪选项。

例如，同一综述可以按“观测到底约束了什么”组织证据，也可以按“泛化失败来自哪些假设”组织比较。应使用当前材料能支持的路线，不能为吸引注意而提前保证结论。

同时落实观看场景和密度：现场短讲、答辩兼复读、阅读材料。说明正文承载哪些必要条件，讲稿补充哪些解释。用户已明确这些信息时直接采用。

确认后写入 `brief.narrative` 与可读故事板。用户只同意顺序，不能被登记成同意尚未展示的视觉风格。

## 节点 B：看真实样张，选择成套方向

先准备封面、困难证据/机制页和连续三页；使用真实原图与实际信息量，实际导出并渲染。展示两套有意义的完整方向即可，不要求为没有争议的项目穷举所有组合。

checkpoints 中 `prepare` 返回的 `designDialogue.nextAction:prepare-pilot-candidates` 指向这一制作步骤。未确认的视觉主题保留为待选，不应提前要求用户回答；工具返回的方向问题在真实候选展示后使用。参考学习和草稿检查仍照常执行。

每套方向一并描述：

- 证据与解释如何分配空间，如何支持用户确定的信息密度。
- 色板与颜色职责如何配合原图，字体如何区分题名、解释和数据标签。
- 边界、留白与层次怎样表达研究关系。
- 标题语言、封面和连续页面如何形成同一份报告。

提供明确推荐及代价，让用户选择 A、B 或具体局部组合。问题应是“哪一种更接近你要的学术汇报感”，同时指出可比较的具体差异，不能只丢下一句“觉得怎么样”。

一项完整方案选择可以同时覆盖 density、palette、shape、language、texture、cover 和 layout 等字段。明确讨论配色、深浅用量、风格、卡片尺寸、主图占幅、版式与信息密度，不能用笼统“方向”省掉讨论。只有方案明确展示了这些取舍时，才把同一真实回答映射到相应主题。未展示的选项不能事后冒充用户选择；故事线授权也不自动变成视觉授权。

用户明确把设计交给作者时，自行决定并记录依据。仍然要制作和检查真实困难样张，委托省去的是不必要的等待，不是设计与验证。

## 节点 C：成品的最终审查

先完成逐页自查并修好已发现的问题，再展示当前成品、概览、路线、时间预算和讲稿，明确询问研究重点、配色、版式和关注页还需怎样调整。默认等待真实反馈。接受或明确最终审查委托写consultation.finalReview，绑定当前pptxSha256与renderReceiptSha256；Agent自查passed不替代这个节点。

用户已请求成品时，不再询问是否允许导出。不能在 `needs-fix` 后交付失败稿并问“要不要做 v2”；裁切、重叠、缺字、漏证据和读不清的轴标签属于作者应完成的修复。

如果用户在这一节点提出修改，按影响范围处理，保留其他已确认项，不从节点 A 重新开始。

## 记录真实决定，兼容现有工程

先查询 `academic_ppt_contract` 的 design 与 preparation 契约。`academic_ppt_prepare` 只提供计划，不代替提问、用户回答或写入工程。将实际发生的选择通过受支持记录接口保存，并在故事板中保留节点、依据和预览路径。

| 字段 | 正确含义 |
| --- | --- |
| `mode: collaborative` | 用户参与重要取舍，作者负责日常实现 |
| `mode: delegated`、`delegation`、`delegationTopics` | 用户明确委托具体主题，记录原话与范围；source和final-review单独有范围 |
| `workflowVersion:2`、`interaction:checkpoints` | v0.9.1 新工程按四个节点协作，一次真实回答可落实明确展示的多个主题 |
| 旧工程未标记workflowVersion | 保持原协议；准备既有工程时prepare传existingProject:true，不将局部修改自动升级为新流程 |
| `decisions[].topic` | 新版 density / storyline / palette / shape / language / texture / cover / layout 是存储字段，不是八次提问任务 |
| `status: proposed` | 建议尚未决定，不能证明已经问过或得到同意 |
| `status: confirmed` | `selected` 对应展示过的选项，`userResponse` 保留真实回答 |
| `status: delegated` | 在用户真实委托范围内采用的决定，同样保留依据 |
| `referencePaths` | 用户或作者实际看到的候选、样张或参考路径 |

选项可用 `{id,label,rationale}`，每轮通常给2–3项可比较选择；不要让用户先了解内部 preset ID 才能回答。允许自然语言组合修改。

v2的record局部更新保留省略的协商字段，decisions按topic更新，显式空数组清空；保留每个主题当前有效决定及真实依据，不把尚在等待的消息写成“用户无回复”。一次回答覆盖完整方向时可以映射多个字段，无需重复询问。旧工程没有协商记录时按当前任务补充，不能倒填过去的对话。

故事线的具体论证与选择写入 `storyboard.decision`，实际样张的成套方向选择通过 `academic_ppt_plan` 的 `kind:pilot-review` 请求登记。后者只能在当前样张真实渲染且逐页 passed 审查后写入，不用纯聊天表态代替看图。

先将真实反馈明确映射到 `design.consultation` 并用 `record` 保存，再写 `pilot-review`；该请求不会自动补全或批准全部设计主题。只记录决定且所有其他工程内容不变时，工具可在核验现有产物完整性后保留同一渲染和原观察，操作仍保留修订历史。实际调整色板、字体、图文、来源、能力或参考学习记录时，重新构建和审查；过期产物与 `needs-fix` 不因回答而获得通过。

恢复时以 `academic_ppt_context` 返回的具体 `selected`、`userResponse`、`rationale` 和 `referencePaths` 为依据，不只看已解决主题列表。对很长的记录按返回路径读取完整工程中的对应记录，避免凭主题名猜测用户选择。

参考学习围绕当前困难页的证据与阅读关系。用 `referenceStudy.designStudies` 保存可定位的整页、学术风格、科学图表或用户模板观察，记录阅读顺序、证据层级与改造；需要组件时沿用 `componentStudies`。用 `paletteRationale` 说明颜色职责。开放排版不强制先看卡片目录；实际采用preset仍需相应已查看 `catalogIds` 或同ID的 `card-library` 细读记录。仅写参考ID、路径或好听的形容词不足以证明看图，参考记录也不构成用户选择。

## 让决定落实到画面

将故事线写入 `brief.narrative`，方向写入 `design.direction`，色义写入 `palette/colorRoles`，字体和观看要求写入支持的 `system/projection`。记录用户偏好不会自动改变 PPTX，必须通过真实样张验证。

“丰富”优先指证据、局部比较、机制解释与多样阅读关系，不能靠增加长段落、阴影、图标和装饰提高信息量。“简洁”先删除同义复述，再重组说明，不能删掉决定结论含义的条件。

实际原图与方向冲突时先尝试保持科学含义的重排。只有涉及真正取舍，例如拆分过载页面导致超出页数约束，才向用户展示具体方案。普通断行、对齐、错字和裁切由作者自主修复。

明确密度后不要为消除检查失败降低阅读要求。草稿可以用于验证初始密度；一旦落实用户选择，修复应改内容组织与实现。颜色、圆角、语言和层级也遵循同样原则。用户否定样张的视觉效果时，将该方向视为待修订，回到实际参考页比较并制作具体修订样张；不以自动检查通过替代用户审美判断，也不把作者的修复决定记成用户已批准新方向。
