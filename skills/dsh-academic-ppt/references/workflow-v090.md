## 1. 共同约定与交互节点

围绕一条研究问题建立证据、故事板、实际页面与最后可用文件的对应关系。不是填完流程表就算成功。每项记录必须对应已发生的工作；所有工具的契约以当前 `academic_ppt_contract` 或 CLI 帮助为准。

只保留三个对用户有实际价值的节点：

| 节点 | 用户看到什么 | 需要决定什么 | 已有明确授权时 |
| --- | --- | --- | --- |
| A 故事线 | 中心问题、章节推进、每页结论/问题摘要、证据缺口 | 报告重点、推进顺序、保留或舍弃的范围 | 依已知意图继续，记录依据 |
| B 真实样张 | 封面、困难正文、连续三页的真实渲染 | 整体方向、信息密度与图文关系 | 作者自主选择并落实，无需逐项询问 |
| C 最终使用 | 已修复成品、讲稿、时间预算、具体未决科学事项 | 必要的学术判断、使用方式或最后修改 | 直接交付已授权结果，不再询问是否允许导出 |

配色、形态、语言和质感属于节点 B 的完整方向。不能让用户先回答一遍七项问卷，见到真实页面后再从头确认。用户后续修改只更新相关决定；已有内容、设计或局部调整授权持续有效。

研究检索、原图盘点和可撤销候选可在等待反馈时继续。尚未回答不能写成已确认，用户沉默不能写成整体委托。已有“按你的判断直接做”等授权时不要故意把自主工作降为等待。

## 2. 分阶段产物和进入条件

| 阶段 | 最小可审阅产物 | 进入下一阶段前要成立的事实 |
| --- | --- | --- |
| 输入 | brief 与材料清单，区分已知、待核和明确委托 | 听众、目的和主要约束足以决定研究范围 |
| 研究 | 核心 paper/claim/asset 记录、图源盘点、缺项清单 | 关键结论有证据，或明确保持为问题/方案 |
| 故事板 | 逐页任务、论证链、素材映射、承接和预算 | 没有无证据结论，也没有只为模板凑出的页面 |
| 方向 | 参考语法摘要、字体/色义/网格、两套必要候选 | 方案适合当前研究材料和阅读场景 |
| 样张 | 真实 PPTX、真实渲染、具体观察、用户选择或委托依据 | 困难内容容纳得下，连续页面的阅读关系成立 |
| 整稿 | 全页内容、讲稿、完整来源与构建记录 | 故事板要求的证据、条件和章节位置落实到画面 |
| 复核 | 当前哈希的渲染与逐页 review、修复后验证 | 无未修复阻断项，最终画面与记录一致 |
| 交付 | 当前 PPTX、讲稿、真实预览、可恢复工程 | `academic_ppt_deliver` 检查通过且作者已实际看图 |

`academic_ppt_plan` 通过 `requestPath` 读取不超过1MiB的UTF-8 JSON请求；先查 `academic_ppt_contract({topic:"storyboard"})`。`kind:storyboard` 写完整规划，`kind:pilot-review` 记录当前真实样张选择；省略 `requestPath` 查询当前规划。调用参数始终含 `projectPath` 与当前 `expectedRevision`，请求文件不重复放这两个路由字段。

六页及以上整稿的最终交付要求完整故事板和当前样张；更短报告不强制该机器门槛，仍完成实际所需的论证与视觉复核。工具输出是缺项和结构提示，不是自动写作替身。不得凭一个“规划通过”就跳过来源阅读或样张。

工具调用失败时先处理该层的输入或环境。无法取全文时记录来源缺口；缺少实际渲染器时记录验证缺口。两者都不能通过修改“已核验”字段解决。

## 3. 真实样张的最低覆盖

样张检查需要覆盖不同风险，不按固定张数表演流程：

- **封面：** 完整题名、真实元信息、研究范围及层级，检查标题断行和主次。
- **困难页：** 从全稿挑证据最复杂、文字最长或结构最难的一页。可为多面板结果、复杂机制、条件比较或定量综合，不能只挑最容易的图片页。
- **连续片段：** 至少连续三页，检验问题如何推进、密度如何变化、读图方式是否重复。困难页可包含在片段内。整稿不足三页则查看全部。

选择候选时必须保持相同必要信息。A 方向的大图与旁注、B 方向的同步证据带，应该改变真实阅读关系；换色、换阴影或替换一张背景图不能算实质候选。

候选须使用已获取的实际原图与最终量级的文字。用合成示意作设计演示时明确标为示例，不能用它证明某份真实论文图会清晰。对候选执行检查、PPTX 导出与真实渲染，查看图本身而不只看参数。

若困难页失败，先找到原因：素材读不清、内容任务过多、页面关系选错、字号/宽度不匹配、几何实现错误。修正方法后再扩展；不能把未解决的模式批量复制十几页。

故事板的 `pilot` 指定 `hardestSlideId`、三个按计划相邻的 `sequenceSlideIds` 和选择 `reason`；存在封面时加 `coverSlideId`。当前接口的连续片段固定为三页，少于三页的短稿不要杜撰页面或该记录，直接检查全部实际页面。

完成当前实际 PPTX 渲染、确认无缺字体且指定样张逐页审查 passed 后，再写 `kind:pilot-review`，填写 `decision:confirmed` 或 `delegated`、真实 `userResponse` 和具体 `notes`。工具绑定当前哈希与内容指纹；改变样张科学内容、字体、配色、主线会使记录失效，增加其他页面不会。

## 4. 参考转化与页面生产

从参考页问四个问题：信息如何分组、视线先落在哪里、证据与解释怎样对应、相邻页为什么变化。把答案转成可泛化规则，再用当前内容检验。

例如，从一张“双证据面板+中间判断”的参考中提取“共同尺度的两组证据可被同一解释连接”，而不是复制它的标题、数字、照片、框的全部位置和装饰。当前材料只有一项证据时，改用适合单证据的结构，不制造第二项填空。

模板资产与科学证据分开管理。付费模板默认只在用户项目分析；不把原件、原图、Logo、受限字体、完整整页截图放入公开示例或插件。版本里的设计规则和示例应为独立编写。

`referenceStudy.status:reviewed` 可保留 `pageRecipeIds`、`templateReferences` 或 `catalogIds` 中的真实来源，以及 `previewPaths`、`observations`、`adaptations`；详细组件记录也可独立承担其对应的来源、预览、观察与改造，不要求重复抄录。用 `componentStudies` 写明看过的具体框线、填充、题签、间距与适配，用 `paletteRationale` 说明色彩职责，见 [academic-visual-language.md](academic-visual-language.md)。先查看原48卡和20款局部参考中的相关候选，再决定是否采用；自主drawings不豁免组件细读。新 checkpoints 流程中计划或现有页数达到6页时，只有整页ID不能通过参考检查；旧工程局部编辑保持兼容。使用preset还须有对应已查看`catalogIds`或同ID的`card-library`细读记录，不设置组件采用配额。

整页先定关系，局部再定组件：比较用共同尺度，流程用准确顺序，层次用包含或分区，机制用有证据的连接，空间问题用地图/位置，综合用条件矩阵或论证汇合。卡片只是承载局部文字和图的工具。

作者可改变未绑定的构图建议，但必须保留结论、证据身份、比较条件、必要文字与已确认的设计方向。需要改变科学含义、页数约束或用户明确保留的内容时，更新故事板并讨论真实取舍。

保持色义、字体角色、来源样式和必要导航一致。版式多样化不等于每页换视觉品牌；同一实验的重复结构可使读者更容易比较。只有不同任务被机械套成同一骨架才需要改造。

## 5. 修复、恢复和交付

`check → build → render → 看图 → review` 是一轮验证。出现 `needs-fix` 后回到错误所属层，修复、重建、重渲染并重新审查。不能只修改 review 的结论，不能让旧哈希的观察证明新产物。

按以下优先顺序处理：科学错误和缺失条件；证据未上页；关系和阅读路径错误；裁切、重叠、字号与字形；可影响理解的细节。修复已知问题是制作任务的一部分，无需再问用户是否愿意要可用版本。

恢复工作时读取当前工程和具体缺项，不从第一步重新提问。局部改字只复核受影响区域与可能重排的页；换字体、全局字号或页面数量则扩大检查范围。未变化页可以保留真实历史观察，但不能称作新的人工查看。

最终使用节点不会替作者承担排版质量责任。用户只需判断研究观点和表达取舍，不必批准缺字、重叠或未验证的图表。

只有无法完成的外部依赖才可以形成受限交付；列出具体缺项和影响，把中间稿标清楚，不称为最终可用版本。正常路径由 `academic_ppt_deliver` 封装已经通过检查、渲染和实际审查的同一产物。
