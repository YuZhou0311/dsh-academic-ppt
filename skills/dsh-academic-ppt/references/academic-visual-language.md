## 实际读图与记录

把参考分成三个尺度阅读。全稿概览看页序和疏密；完整正文页看主证据、解释、条件与阅读路径；局部放大看框线是否真无填充、题签怎样覆边、文字距框多远、阴影落在哪里。没有看过的页面不能列入观察记录。统计颜色和形状只能辅助定位。

同时查看原[48款卡片](card-library/index.html)和[20款局部组合](editorial-v083/index.html)中与本稿相关的候选。前者提供题签、侧签、括线、读数和图卡等可执行结构，后者帮助理解图与注释怎样组合。**学习是制作步骤，采用哪个 preset 是设计选择。** 最终用自主 drawings，仍要完成相关组件的视觉学习；并不要求采用卡片、凑款数或改造所有参考。

在 `design.referenceStudy.componentStudies` 保存具体观察，每项包括 `source`、`referenceId`、`previewPath`、`frame`、`titleTreatment`、`spacing`、`adaptation`，可加 `colorHierarchy`。来源分别为 `card-library`、`editorial`、`user-template`；用真实卡片 ID、C01–C20 或可定位到页的模板 ID。记录实际画面，不用“简洁、专业、丰富”替代细节。`paletteRationale` 说明主色、正文、边界和必要强调色的职责。

```json
{
  "source": "user-template",
  "referenceId": "project-reference:p12",
  "previewPath": "reference-render/page-0012.png",
  "frame": "主证据为白底细实线框，阴影在右下；外层共同条件只有虚线，没有可见底色。",
  "titleTreatment": "短题签覆在上边线，题签与正文之间另留空隙；没有重复的内部标题。",
  "spacing": "同组两图的顶部、底部与图注基线对齐；组间空隙明显大于题名到图面的距离。",
  "colorHierarchy": "深蓝命名组别，黑灰解释数据，只有结论改变处用暗红。",
  "adaptation": "本稿两幅同条件结果共用虚线范围，保留相同绘图区；限定直接放在两图下方，不照搬原页三栏。"
}
```

上述内容仅展示记录格式，必须换成实际观察。新 checkpoints 整稿的计划或现有页数达到6页时，需要组件细读和配色理由；只写整页 recipe ID 不足以完成学习。旧工程局部修订保持兼容。记录可审查，但不能证明调用者真的看过图，也不能自动证明审美达标。

## 边界与表面的选择

下表是表达职责，不是逐页轮换的样式清单。先问“这条边界把哪些信息归在一起”，再选外观。同一比较组使用相同线重、题签位置和阴影；不要用外框差异暗示不存在的证据强弱。

| 表达 | 适合的内容关系 | 需要保留的细节 | 常见误用 |
| --- | --- | --- | --- |
| 无填充实线框 | 一个实验、方法模块或独立证据组 | 真正 `fill:none`，清楚的线重，内容距线有余量 | 用白填充冒充透明，覆盖底层内容；每句话单独套框 |
| 无填充虚线／点线框 | 共同条件、同一来源的多个子图、方法阶段的包含范围 | 完整边界、清楚的范围题名；框不穿过图例和文字 | 把虚线自动解释成“未验证”或“不确定”；用满页虚线抢走数据注意 |
| 白底实线加轻阴影 | 主证据面板、需要从背景分离的关键解释 | 白纸面、细线、同方向低对比阴影；内部仍有主次 | 对所有内外层同时加阴影，形成厚重按钮；缩小原图给阴影腾位置 |
| 白底无可见边线加阴影 | 与开放画面区分的短说明、问题与响应 | 主要由纸面和阴影形成边界，留白必须足够 | 把无边线误写成实线；灰影过重使文字看似模糊 |
| 开放括线／双横线 | 定义、条件、读数账本、贴近图面的注释 | 端点对齐、组内行距与共同基线 | 因支持描边就强行闭合，丢掉原本轻量的组织方式 |
| 标题带加白色正文 | 同级研究任务、协议阶段、方法模块 | 深色窄标题区、足够的正文空间；同级同色 | 彩虹标题带、过高标题带、把完整句子挤进窄题签 |
| 侧签与横向内容行 | 研究条件、风险类型、输入输出的对应行 | 侧签宽度由真实名称决定，行高由完整正文决定 | 长中文竖排导致逐字阅读，多个侧签重复页标题 |
| 外层范围加内层模块 | 实验阶段中包含处理与验证，或证据组中包含子比较 | 外层轻、内层清楚；每层确有不同归属 | 三层同样粗的框；重复命名同一组；外框遮住连线端点 |

虚线没有固定的科学含义。需要表达假设、待验证或方案时，明确写出身份，不只靠虚线让听众猜。阴影也不表示可靠性、显著性或重要程度。

## 题签、间距与嵌套

题签是阅读入口。先确定它命名的是来源、实验、阶段还是条件，再选择位置。短题名可用深蓝白字浮签；较长题名可直接置于白底并打断上边框；连续行适合侧签；只有一个独立图且自身标题已清楚时，可以没有外题签。

覆边题签应盖住它下面的那段边线，不能让线从文字中穿过。浮签顶部和正文起点分别预留空间，不能依靠阴影掩盖接缝。题签宽度跟随标题的自然长度，保持同组一致；遇到长标题，扩大标题区或换为开放标题，不截字、不缩到低于正文。

在1280×720场景中，可先试下列范围，再依据参考和实际渲染调整。数值是设计起点，不是所有稿件的统一标准：

| 项目 | 起点 | 实际检查 |
| --- | --- | --- |
| 常规边框 | 约1.1–1.6px，灰蓝或中性灰 | 缩到完整幻灯片观看仍看得见，不与图内数据线竞争 |
| 分组虚线 | 约1.5–2px，深蓝或中灰 | 虚实节奏可辨，角落自然，内容不贴线 |
| 圆角 | 0–8px | 图内证据保持完整矩形；同组弧度一致 |
| 卡片内边距 | 16–24px | 图注、字母标记、单位都在安全范围；短卡不人为拉高 |
| 相邻证据组间距 | 约20–32px | 大于组内标题到内容的距离，阴影没有连成脏边 |
| 轻外阴影 | opacity 0.10–0.18，blur 3–6px，offset 1–3px | 纸面与背景略有分离，框线和文字仍清楚 |

单位必须区分：场景1px约0.75pt；OOXML线宽以12700 EMU/pt计。参考中的40%不透明阴影、大范围柔光或极细边线属于那张页面的整体效果，不能原值复制到所有新稿。由图片截图推测的尺寸应标为估计，只有读取原对象才能记录精确参数。

内层组件可以只用题签、对齐或留白。外层无填充虚线、内层白色实线是可用组合，但不是默认答案。用同一外框包含多张图时，保护各图原有轴线、图例与出处；外框不承担数据尺度。

## 稳重配色与图表色义

先确定页面主色和颜色职责，再组织局部层级。正式学术答辩可从深蓝、黑灰、白色出发，配一个克制的强调色；也可依据用户机构色和真实图表选择其他方向。稳重来自主次、对比、用量与一致性，不等于“所有学科必须深蓝”。

下面是一套可复用的正式方向。若用户已固定颜色，沿用用户要求。

| 角色 | 示例颜色 | 用法 |
| --- | --- | --- |
| 主色 | `#003E87` | 章节、短题签、少量关键结构 |
| 次深蓝 | `#023160` | 稳定的图形边界或主方法标记 |
| 正文 | `#17243A` | 正文、必要条件、图旁解释 |
| 辅助文字 | `#606A77` | 来源、真正次要的说明 |
| 线与中性浅底 | `#AAB8C9` / `#F3F5F8` | 分组和承托，避免铺满正文 |
| 克制强调 | `#8F1111` | 明确的分歧、关键限定或需要读者注意的一处比较 |
| 纸面 | `#FFFFFF` | 图文主背景与证据面板 |

不要给每一组解释分配不同色相来制造“丰富”。同一实验的多方法可用可辨认的灰与同色系深浅，加文字、标记或线型；若图中确实需要多色系列，保留数据色义。原研究图是多彩的，不意味着边框和题签也要多彩。解释源图某模块时，可以复用该模块颜色，但应记录对应关系。

`design.colorRoles` 是声明，不是自动重绘器。自由 drawings 中的颜色由作者参数决定；构建时复用同一色表，最终逐项检查，不假设写了色义就能约束硬编码颜色。

## 受支持的原生参数

普通卡、48种 preset 和12种图片卡均可设置以下外框参数。preset 的内部关系、题签、条目和图像槽位保持原配方；不要用外框参数改变比较尺度或内容容量。

```json
{
  "fill": "none",
  "stroke": "#023160",
  "strokeWidth": 1.6,
  "dash": "dash",
  "shadow": false
}
```

把这组参数放在 `card.appearance` 中，得到透明虚线边界。开放括线类 preset 保留自己的开放几何；需要完整闭合边界时选本来具有完整外框的组件，或使用 `drawings`。

```json
{
  "fill": "#FFFFFF",
  "stroke": "#AAB8C9",
  "strokeWidth": 1.2,
  "dash": "solid",
  "shadow": {
    "color": "#17243A",
    "opacity": 0.14,
    "blur": 4,
    "offset": 2,
    "angle": 90
  }
}
```

第二组是白纸面板的起点。无可见边线时设 `stroke:none`。真正透明和白色填充不同，即便白背景上看起来相同。`plain` 默认不画外表面，显式填色或描边时才绘制；`shadow:false` 明确关闭阴影，覆盖旧 `elevation:true`。透明边界不会因为默认 elevation 自动获得纸面阴影。

显式覆盖填色时，文字前景按实际底面检查对比，避免白底白字或深底深字；独立题签仍按自己的底色处理。这个修正不重着色研究图片，也不保证任何色板都适合当前学术任务。切角与折角的外表面是完整可编辑闭合轮廓，填色与阴影沿同一斜边；折线和内部槽位仍保留。

`fill/stroke` 接受六位HEX或 `none`；`strokeWidth` 为0.1–6px；卡片 `dash` 接受 `solid/dash/dot`。阴影用 `false` 或完整的五项对象：color、opacity 0–0.4、blur 0–32px、offset 0–24px、angle 0–359度，零值有效。原生 drawing 的 rect/ellipse 也可使用同名阴影对象；其余绘图参数按 `contract(slide)`。

现有 `radius/padding/elevation` 继续兼容。preset 不接受另一套 `appearance.layout/surface/accent` 去重写内部结构，颜色入口仍有 `card.accent`。浮签、双框、侧签或独立标题需选相应 preset，或用独立原生文本和形状组合。视觉嵌套不等于Office的组合对象，不宣称不存在的SmartArt或整组编辑能力。

## 把细节迁移到真实正文

从证据问题出发安排同一稿件中的结构差异。例如，配对结果可用同尺度的白底证据面板；机制页用方法模块和实际连接；研究设计用对应行列和共同条件范围；综合页保留跨来源的限制；下一实验用明确标注的方案区。框的样式应跟着这些职责变化。

改造记录应能指到实际页与区域：“第3页两幅同条件图使用同样白底实线框；第5页外层虚线标出共同方法范围，内部路径仍为原生对象；第7页读数贴近原图，使用一张阴影侧卡。”这些只是写法示例，不能成为所有报告固定的第3/5/7页模板。

克制不等于删除全部边框、浮签和层次；丰富也不等于卡片等分或框型轮换。科学上平行的对象应该保持视觉一致，内容任务变化时再改变阅读关系。保留原图尺寸、关键条件和普通解释，不能以更大题签、更厚阴影替代真实证据。

## 实际渲染与用户反馈

同时查看全稿总览、代表正文的完整画面和局部放大。检查题签遮线、框线可见性、阴影方向、组内间距、共同图例、数据标签和来源位置。确认SVG预览与真正PPTX渲染的no-fill、线型和阴影一致；对象参数存在不等于最终画面正确。

把同一科研内容的真实样张交给用户判断风格和密度。用户说“不够学术”“没有体现参考”时，标记该视觉方向待修订，回到具体参考页比较，不用自动测试通过或卡片数量反驳。先完成可审阅的修订样张，再请用户作有意义的方向判断；不得把作者自评记成用户已批准。

记录具体修复及重新渲染的观察。检查表负责发现问题，最终是否符合用户的视觉预期仍由真实样张与反馈决定。
