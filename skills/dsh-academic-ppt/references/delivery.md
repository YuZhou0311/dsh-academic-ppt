# 正式交付检查

## 先分清五种证据

| 范围 | 验证什么 | 不能替代什么 |
| --- | --- | --- |
| 学术记录 | 来源、推导关系、限定、门槛完整 | 实际阅读与科学判断 |
| 静态几何 | 页内边界、文本估计、区域碰撞、有效内容分布与大空区 | 最终字体、渲染和设计判断 |
| PPTX生成 | 文件可写且原生对象存在 | 文件能正常放映、内容好看 |
| PPTX真实渲染 | 当前文件生成实际页面、字体情况 | 人或视觉模型审阅 |
| 逐页审查 | 实际看过的当前版本页面及具体结论 | 未看页面和旧版本审查 |

## 操作顺序

先运行check，按对象ID修阻断问题。build默认review，未齐材料只能draft；draft不能当成满足条件的成品。通过render取得当前PPTX页面，再查看全部页面。

代表页小样用于提前发现规则问题。完整交付检查至少覆盖封面、所有正文、参考页与密集图。概览用于节奏与层级，单页原尺寸用于标签、文字和对象冲突；只看缩略图不能证明小字可读。

核对：

1. 标题、正文、图与讲稿是否支持同一研究判断，有无泛泛介绍替代机制或证据。
2. 作者报告、汇报者推断、建议是否区分；数值、单位、样本/分母、对照和模拟身份是否保留。
3. 封面是否有完整题目、明确视觉重心与真实身份；身份未知时是否连同空基座删去；结束页是否收束当前论证，而非重复三列短文。
4. 独立解释、条件与边界组是否有可辨认的卡片或容器；轮廓、浅底、内边距和图标在实际渲染中是否清楚，是否出现框套框或卡片只剩裸文字。
5. 主证据是否占据足够面积；正文是否只在上半页、短句是否占长侧栏、上下内容之间是否有大空洞；cover与closing是否也满足用户的紧凑要求。
6. 标题、章节角标、品牌小字、页脚与横线是否各有用途，是否残留参考模板旧字；整稿是否对不同任务反复使用同一骨架，只改标题、颜色或比例。
7. 当前文件有无溢出、覆盖、缺字、过小图例、被裁关键元素；页序和讲稿是否连贯，实际文件与工程revision/hash是否匹配。

空间检查的large-unused-region与unused-region-review帮助定位连续空洞，不是审美分数。design.density为compact时的阻断问题必须重排或合并解决；repetitionReason不能豁免空洞。背景、边框、图标与空文本框不能代替有效内容。原图内部的留白与图例区域应保留，不能为提高占幅损坏科学图。对仍需保留的提示，写明具体内容关系与实际看图结果，不用“有意留白”“保持一致”作为统一理由。

missingFonts为空只表示没有报告缺失字体，不证明数学或科学符号的字形齐全。逐页检查上下标、希腊字母、取整符号、负号与单位；遇到方框先选有该字形且有许可的字体，或使用含义明确、完整可编辑的等价记号并解释，不能直接删符号或当作渲染已通过。

## 登记实际检查

调用review时使用当前pptxSha256。reviewedSlides只列本次真正看过的页，observations一一对应，每页写contentCheck、legibilityCheck和issue。legibilityCheck也应记录本页具体的分组、内容占幅或阅读顺序判断。issue为空表示本次未发现问题；有具体问题则needs-fix。记录可复核的细节，不用每页相同的“检查通过”。

修改后重新构建，旧hash下的审查不自动转移。当前接口要求最终版本全部页重新确认，不能把早期未改页直接填入当前检查范围。若用户人工确认，应如实标reviewer: human，不能由模型冒充。

readyForDelivery要求当前review构建、学术记录完整、没有阻断项、真实渲染、当前所有页审查齐全且没有未解决的缺失字体。任一条件未满足则为false；通过也不是自动科学真实性或审美认证。

## 处理未完成项

缺视觉能力/引擎/字体则记录unavailable或not-verified，提供可以复核的部分并说明具体缺项。不能伪造receipt或编辑质量报告变通过。发现缺图例不能只写到备注后通过，需恢复图例或正确拆页。

默认争取两次渲染完成：代表页、完整稿。额外轮次只针对明确失败，修完停止装饰返工。如果预算或材料不足影响交付，应明确范围，而不是降低证据门槛。

## 交付

交付可编辑report.pptx、对应speaker-notes、工程和必要来源/资产清单。HTML可作浏览辅助，不能称PPTX已实际审查。明确是否使用替代字体、哪些结果只读到摘要以及其他实质限制。

不要把构建日志、校验用语或制作流程放进正式幻灯片与讲稿。不声称在PowerPoint/WPS亲测，除非实际打开该应用检查。
