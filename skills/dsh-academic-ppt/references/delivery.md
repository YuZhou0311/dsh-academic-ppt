# 正式交付与真实复核

## 0.9.1 的交付条件

`build` 产生文件，`review` 保存实际观察，`academic_ppt_deliver` 检查并封装当前可交付版本。三者不能互相替代。最终交付必须对应同一份当前 PPTX、真实渲染和逐页审查；任何 `needs-fix`、过期审查或未完成渲染都应先处理。

发现普通排版、文字裁切、图表不可读、证据未上页或科学条件缺失后，默认继续修复。不能把失败稿当作最终结果，再问用户是否要一个“优化版”。草稿可用于讨论，但要明确其用途与缺项，不能冒充已完成交付。

只在不可解决的外部依赖确实阻断时说明限制，例如全文无法获取或运行环境没有可用渲染器；记录受影响页面和验证范围。不得通过修改 review 结果、降低 projection、隐藏关键内容或删除检查项把障碍变成“通过”。

## 分清验证范围

| 范围 | 实际能验证 | 不能替代 |
| --- | --- | --- |
| 学术记录 | 来源、引用链、口径、要求是否齐全 | 全文阅读和科学判断 |
| 设计协商与参考学习 | 记录是否完整、哪些主题仍待决定、采用的候选是否可追溯 | 用户真实回答、实际看过参考以及画面兑现 |
| 叙事与导航检查 | 声明的章节引用、目录映射、次序及缺项 | 论证真的连贯、转折有依据、结尾回答了问题 |
| 内容与几何检查 | 载体是否消费、尺寸、边界、字号估计、空间风险 | 关键语义真的正确、最终字体与审美 |
| PPTX生成 | 文件与原生对象存在 | 正常放映、好看或完整可读 |
| 实际渲染 | 当前PPTX生成真实PNG/PDF和字体报告 | 人或视觉模型逐页查看 |
| 逐页审查 | 具名执行者实际看过的当前页面及观察 | 其他版本、未看页或独立科学验证 |
| 跨稿结构比较 | 指定工程中的主体结构近似 | 像素审美、原创率或抄袭判定 |

## 顺序

正式构建前先核对`design.consultation`与`design.referenceStudy`：故事线和完整方向是否有真实决定或明确委托，参考是否实际查看并按内容适配。一次完整方向选择可覆盖多个兼容主题，不为七个字段重复提问。待讨论的方案可输出draft，不把proposed记成confirmed。随后check修阻断项，再build；最终稿使用review。render后看整稿概览，再按可读尺寸查看所有页面，包括封面、书目与补充页。HTML不能冒充PPTX实际显示。

代表页用于提前发现设计和执行问题，必须包括真实信息量的困难页。确定方向时查看连续三页的任务与视觉节奏，再扩展整稿；短稿按实际页数处理。全稿检查覆盖新的全部内容。同轮问题集中修复后重建，额外渲染针对具体问题。

先只读目录、章节问题、页标题、transition与结尾，核对问题如何逐步得到回答；再在整稿概览中检查导航可见性和节奏。较长报告不能只在JSON里有路线而画面缺少定位；短稿也不必为达到固定数量插入空章节页。声明中的坏引用需修复，章节回看和空间提醒结合实际论证与画面判断。

## 每页检查什么

打开当前图源清单和逐页设计稿，与实际页面逐项对应：已选原图及真实资产、可见内容和来源、语义关系、表达载体、层级与阅读路径。`figureReview`选中的图必须能在相关页面找到并读懂，不能只留在工程记录。完整设计稿不能在生成后补写成对现状的解释。若设计本身需要改变，同步更新相关段落并保留原因，再核对新输出。

1. 页面与讲稿支持同一主题或判断；来源报告、推断、未实施方案清楚区分，样本单位、分母、对照、信息条件和单位完整。
2. 逐项回查本页必要信息：主证据、辅助比较、条件、方法和解释是否按实际需要可见，缺项是否影响判断。结果页应能看到支撑判断的原图或准确数据表达，方法页能看到操作与变量关系；不能只剩摘要卡、技术名词或几个大数字。图标、框和带来源的文字卡不算研究视觉证据；同时不强制定义、目录、章节或每一页都有图。
3. 入口、主次和阅读路径清楚，比较、包含、先后或解释归属能从画面读出。入口可是一组共同组织的表图或方法区域，primaryPanelId不要求唯一大图。查看实际距离、尺度、连接和边界，而不仅是visualPlan的文字。
4. 章节、页题、题签、普通解释、数据/轴与来源有各自字级；按用户确定的阅读场景检查最终字形。逐项检查孤字、孤行、窄栏频繁折行、术语/数值与单位拆分，按[typography-editing.md](typography-editing.md)修复。主要读数、条件和边界不能降为note；projection也不能在失败后调低。
5. 流程输入、预测、反馈、分支和返回对象正确。端点不误接，交叉不暗示汇合，标签靠近对应线，路径修改后标签同步。
6. 裁切保留必要轴、单位、图例、尺度与面板身份；重建的轴名、刻度、图例与原图位置和含义一致。数据点不被遮挡或篡改。
7. 章节定位、页级题名与局部题签的职责和视觉层级清楚，标题具体、断行合理，封面使用完整题名和真实身份。标题承托与正文区域相协调，没有靠过大标题挤掉证据。自定heading继承chrome时检查实际重叠，省略重复题签时保留必要定位。
8. 需要的卡片描边与题签实际可见，结构与实际查看的候选和本页内容对应；图卡真正嵌入来源图，轴和图例未被卡框遮挡。开放旁注有归属，必要嵌套表达包含关系。组内风格一致，不靠换色、圆角或样式ID轮换冒充新构图。颜色职责清楚，关键身份不只靠颜色。
9. 连续看相邻页面，确认本页接住什么、补了什么、下一页为何出现。结合全稿概览核对左图右三卡、上图下文等结构是否支配了不同任务；需要变化时重排关系和载体，不仅微调比例。同一实验的共同尺度与必要复用保留，结尾回应开场并保留边界。

有参考时，回到[template-learning.md](template-learning.md)的差距记录，确认修复是否出现在实际页面。核对用户选择的圆润/干净、语言、层次质感和信息密度是否一致；用户没有逐页挑卡不代表可以跳过作者选型。材料种类不同如实说明，可改的标题、换行、标注、邻接与组合问题继续修复。仅颜色或字号接近不代表参考学习完成。

代码提醒只定位风险。contentLayers、readingOrder或其他声明存在，不证明信息足够或关系已经落实。`source-led`核心来源缺少实际查证/图源盘点、选图未上页，或有适用结果图却退化为全篇文字卡时，应修复并保留未完成状态。真实无适用图的来源要有已查材料、具体理由和替代表达，不能把图未下载或全文未读伪装成无图。自绘表格或关系有时未被自动识别，须结合页面和来源核对并保留解释；不能删提示、改模式、添加无关图或画空框刷过检查。

封面、目录和分节页允许服务层级与定位的留白，其空间提醒通过实际画面复核；不要为消除提醒增加装饰图或冗余文字。正文仍检查证据覆盖、可读性、卡片内部空腔、主体过小和compact空间要求。短卡收紧后检查整页剩余空区，不能仅外框缩短就认定通过；深浅层次、部分填色和实际文字背景对比也须逐页看图。留白政策不豁免缺字、重叠、错位或不可读导航。

缺失字体列表为空不证明所有字符可用。实际检查数学上下标、希腊字母、负号与单位。出现方框时选择有相应字形的字体或准确的原生字符定位方式；必要时保留独立公式源资产，不能删符号。

## 记录与修订

用当前pptxSha256登记review，reviewedSlides只列实际看过的页。observations逐页写contentCheck、legibilityCheck与issue；v2还须spaceCheck、colorCheck，逐项以diagnosticChecks回应当前reviewTargets。具体字段及有意留白的处理见[space-and-tone.md](space-and-tone.md)。描述本页具体观察，不能复制一套“检查通过”。有未解决问题记needs-fix，模型不能冒充human。

每项未解决问题写明页面、对象、影响与可执行修复。集中处理本轮发现的问题后，重建、重渲染并复查相关页面；修复引入新的问题也要处理。已修改代码或坐标不算验证完成，必须看修改后的实际画面。最终整稿核对页序、导航、来源和当前文件哈希。

修改后重新构建，旧哈希的批准不转移。确认最终整稿实际页面与当前产物对应；若借助未变化页面的字节一致核对，明确先前实际看过的版本、变化页和比较范围，不把它写成新的人工查看。接口接受审查也不证明声明真实，执行者需保留可复核依据。

修复次序是科学错误/缺项、载体与关系、比例和阅读层级、细节。只对剩余具体问题继续返工，不以降低要求、缩小关键文字、改verified或删科学限定掩盖。

readyForDelivery只是当前记录、构建、渲染与具名审查的汇总，不能称为学术论坛通用验收、科学真实性认证或模型稳定效果。

## 交付

完成上述步骤后调用`academic_ppt_deliver`，提供当前`projectPath`、`expectedRevision`与新建交付目录`outputDir`，不用历史记录或旧输出替代当前产物。六页及以上整稿还要求完整故事板和当前真实样张记录；没有强制绕过或自动降级为草稿的选项。若工具拒绝交付，读取具体阻断原因并修复；它返回通过仍只说明记录和产物满足其检查范围，不能证明审美或科学真实性自动获得认证。

提供当前可编辑PPTX、对应讲稿、实际渲染PDF/页面和可恢复工程，保留必要来源、许可与资产。说明影响使用的字体、编辑范围或未完成验证。论文原图是独立图片，不声称其内部点与文字全部可编辑。

最终用户审查是第四个节点：先完成作者自查并修复，再展示实际成品、全稿概览和具体关注页，询问研究重点、配色、布局及风格是否还需调整，等待真实意见。将接受或明确包含final-review范围的委托写入consultation.finalReview，绑定当前PPTX与渲染清单双哈希，再deliver。导出请求不等于审查授权，但也不额外问是否允许导出。仍需专业判断的推断须标清依据与限制，不能把普通制作缺陷留给用户选择接受。

正式画面与讲稿不放构建日志、版本验收术语或制作报告。验证细节另存。只有实际打开PowerPoint/WPS、实际运行用户宿主或真人排练后，才能声称完成相应验证；记录重建不算新模型创作。
