# 48 种学术汇报模板

这套参考包提供 **8 类 × 6 页，共 48 个内容结构**。按要解释的科学问题、证据类型和必要条件选页型。它们与运行时的 `referenceTemplateId` 共用 [reference-catalog.mjs](../../../../src/reference-catalog.mjs)，选择模板后得到的是可继续编辑的结构。

先看 [可筛选图文索引](gallery.html)，也可以下载 [48 页 PPTX 总集](academic-templates-48.pptx)。完整字段、版面尺寸和每页示例位于 [manifest.json](manifest.json) 与 [slide-records.json](slide-records.json)。

**全部书目信息为占位，全部图表数值为合成演示值。** 这些示例说明怎样呈现研究对象、样本单位、对照、效应、不确定性和解释边界。用于正式汇报时，必须替换为已经核查的论文信息、原图与数据。

## 文件与用途

| 分类 | 可编辑分包 | 六种内容结构 |
| --- | --- | --- |
| 论文导读 | [paper.pptx](paper.pptx) | 单篇全景、缺口与假说、论点证据对应、研究范围、贡献比较、精读讨论 |
| 方法与机制 | [method.pptx](method.pptx) | 智能体反馈、强化学习接口、工具路由、机理耦合、算法步骤、目标与约束 |
| 实验设计 | [experiment.pptx](experiment.pptx) | 独立样本、因子设计、数据划分、公平基线、测量链、复现协议 |
| 结果与统计 | [results.pptx](results.pptx) | 主效应、两个终点、消融、跨环境表现、代价权衡、错误分母 |
| 原图解读 | [figure.pptx](figure.pptx) | 宽幅图、双面板、互补证据、主证据与补充面板、竖图独立面板、图例与变量 |
| 跨文献综合 | [synthesis.pptx](synthesis.pptx) | 机制对应、证据层级、同维度比较、进展、分歧、研究问题 |
| 局限与失败 | [limitations.pptx](limitations.pptx) | 失败定位、迁移边界、测量偏倚、效度审查、风险干预、复现缺口 |
| 研究计划与附录 | [plan.pptx](plan.pptx) | 可检验假说、公平实验、采集与评价、阶段产物、结论、参考文献 |

## 选型与组合

1. 先写本页希望观众理解的一个具体关系。需要解释机制时选择流程或接口结构，需要比较实测表现时选择图形与统计条件。查看原图的内容、图例、面板和最小关键标签，再看宽高比；密集竖图即使能按比例装入，也可能完全不可读。
2. 记录不可删除的信息：完整论文题名、研究对象、实验身份、独立样本单位、比较基线、指标单位、误差含义及适用条件。把每条内容绑定到对应图、表或解释区。
3. 用 `academic_ppt_reference` 查询候选模板。`manifest.json` 中的 `slots` 给出区域坐标，`requirements` 给出需要的图、卡片、流程节点和图表数量。七个短表页型的 `tableFlow` 让说明区跟随实际表格与图注的底边；它们最终的纵坐标由输入行数决定。按选中模板提供必要内容，避免字段没有落到版面上。有组合面板时，可用 `slide.panelTitles` 写入与实际证据相符的题签。
4. 同一论文可以连续使用几种页型：`paper-overview` 介绍研究，再用 `method-agent-loop` 解释系统，接 `experiment-cohort-design` 与 `results-main-effect`，最后用 `limitations-failure-case` 限定结论。
5. 在全篇尺度检查节奏。连续几页采用相同图文比例会削弱主次。也不要为了追求变化给相同实验对照强行更换视觉编码。

科学信息够用与阅读轻松要同时满足。表格只用于严格行列映射，本包中有 8 个表格页型；其他结构使用原图、统计图、流程、横向证据链、左右不等宽组合或连续文本。短标签、淡蓝表头和细边框用来表达内容分组。

## 图片先确定阅读任务

图像的 `reading` 记录承担证据还是定位、图像内容、阅读任务、当前视窗的面板数、关键标签高度与必保留元素。`verifiedBy` 表示谁实际查看过，不是工具自己识别语义。`figureGuidance` 为每个含图模板提供候选任务与使用条件。

| 需要说明的内容 | 布局与图片选择 |
| --- | --- |
| 一幅简单宽图的整体关系 | `figure-wide-annotated`，图优先占通栏；图中每个必要元素仍需可读 |
| 两组条件或两项终点的比较 | `figure-two-panels`，选择两个独立面板，保持比较所需的尺度与上下文 |
| 主趋势与一个补充检验 | `figure-detail-window`，主面板放大，补充面板较小但同样必须可读 |
| 竖长总图中的当前结果 | `figure-portrait-reading`，取当前论点对应的独立面板，其他面板分到后续页面 |
| 三项简单互补证据 | `figure-three-panels`，仅在三图变量少、标签可读时使用；小表或密集误差分析需换页型 |
| 多种颜色、符号和统计口径 | `figure-legend-first`，将解释放在原图附近，避免重复抄写已清楚呈现的图例 |

传入 `figure` 查询时，工具按真实槽位估计图框适配和关键标签的投影高度，最多返回三个候选。**候选排序不是审美评分，也不能确认裁切保留了科学上下文。** 坐标、单位、图例、对照和误差含义由执行者逐项核对。只有总体定位有实际用途时才增加定位图，不能让不可读总图占据主要证据位置。

本版预检以画布上的 18 px 作为关键标签建议值、12 px 作为底线。这是插件的投影启发式，实际场地、屏幕和图像内容仍需检验。图片分辨率高不代表显示后文字够大；禁止改写测量记录来绕过提示。

## 层级、语义与局部质感

当前画布为 1280×720。页标题使用 40 px，解释块标题 26 px，正文 24 px；在本插件的 PPTX 单位换算中分别为 30、19.5、18 pt。大小层级还配合字重与颜色：一个长段落中只强调少数已有关键短语，`card.emphasis` 的内容必须出现在正文中。页眉取消重复类别小字，论文引用、图注和页码保留独立较小层级。

`cardKinds` 给出各解释区的语义起点。方法使用蓝色，实测结果与证据使用青绿色，约束与失败使用赭红色，待验证假设使用紫色与虚线；实验设置使用灰蓝色。同一个对照或同一角色在全篇保持相同编码，原论文图的颜色定义单独保留。

边框和样式按关系选择：共同比较用同种框，主证据用明确标题或浅色表头，限定条件使用侧签，假设使用虚线。图像的浅阴影跟随实际图像边缘，卡片用少量轻阴影或嵌边题签建立层次。不同块不必都有完整外框，也不靠随机换色体现“多样”。

## 与提供的两份 PPT 的关系

公开模板吸收了用户提供的 39 页参考 PPT 中的图文组织规律：短题签连接说明带，细边框配浅蓝表头，左窄右宽证据区，框内图与流程并置，竖图配分步解读，结论紧贴对应证据。具体观察与生成规则见 [用户模板研究](../../../../docs/USER_TEMPLATE_STUDY.md)。

本包重新绘制这些结构。它不包含原始用户 PPT、大学标识或原始研究数据。比如 `paper-evidence-map` 用两组不等宽的图文区，并把三步解释链放进右侧证据框；`figure-portrait-reading` 展开竖图中的当前证据面板；`method-model-coupling` 把计算链与接口、校准、失配条件分层呈现。

## 编辑性与图像

PPTX 中的标题、正文、边框、题签、连接线、流程节点、表格单元格与原生统计图表均保留为独立可编辑对象。科学图是独立 PNG 资产，可替换或调整位置。没有把整页渲染图作为 PPT 背景交付。

局部图通过 `viewport` 指定视窗，保留原图字节、来源、范围说明和 SHA-256。`figure-detail-window` 展示主面板与补充面板，不再强制搭配整图缩略图。修改裁切范围时，应一起核对面板标题、坐标、单位、图例和误差定义是否完整。

`assets/` 包含 7 张原创合成科学图、图形生成脚本使用的数据说明。另有两个非破坏的面板视窗记录，复用完整源 PNG。其源代码是 [create-reference-figures.py](../../../../scripts/create-reference-figures.py)。图表数据包括响应曲线、独立观测、跨环境矩阵和效应区间；同一数据在单图和组合图中保持一致，不能作为真实研究发现。

合成图将必要轴字和条件标签设为 20 pt，宽幅组合图使用 24 pt，输出为 140 dpi。按 DejaVu Sans 实际数字与大写字形测得的保守墨迹高度记录为 28/34 px。缩写 A/B 对应两种条件，Ref. 与 V1–V3 对应参考与变体；轴保留单位，图下注释和数据文件保留解释。这些数字仅描述本次明确控制的合成资产，不能套用到任意论文图。

## 可视核验与重新生成

`previews/T01.svg` 至 `T48.svg` 是运行时场景的逐页预览。`montages/` 中的八张分类拼图来自导出 PPTX 的实际渲染。二者用途不同：SVG 便于选型和定位元素，实际 PPTX 渲染用于核查字体、行距、表格高度和图像裁切。`manifest.json` 记录它们对应的 PPTX 哈希、渲染引擎和审查状态。

从仓库根目录重新生成可编辑 PPTX、SVG、HTML 和样例记录：

```bash
python scripts/create-reference-figures.py
node scripts/build-references.mjs
```

重建图形需要 Python、NumPy 与 Matplotlib。插件运行时直接使用已包含的资产。实际渲染仍使用项目的 PPTX 渲染器。渲染完毕后，可用 `scripts/finalize-reference-previews.py` 从渲染收据建立对应的拼图；脚本会核对源 PPTX 的 SHA-256，避免把旧预览误当作新版本验证。
