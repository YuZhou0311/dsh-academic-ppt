# 写出逐页设计，再把它画出来

## 1. 先确定页面怎样被阅读

在设计简报中写明本稿的使用方式。新建整稿按[design-dialogue.md](design-dialogue.md)向用户推荐并讨论密度；既有明确偏好或委托可直接沿用。不要把“只有一句任务”解释成用户放弃设计选择。

| 使用方式 | 画面承担的内容 | 讲稿或附录承担的内容 |
| --- | --- | --- |
| 现场短讲 | 当场需要辨认的对象、证据、条件和判断，安排清楚的讲述顺序 | 扩展解释、详细推导、备用证据 |
| 答辩兼复读 | 完整的比较或方法关系，关键读数、解释和适用边界；离开讲者仍能追问依据 | 深入推导、补充实验、问答准备 |
| 阅读材料 | 自解释的段落、图注、表头、条件、出处和跨页联系 | 可追溯的完整材料与计算细节 |

“正式”“简洁”不能自动推成现场短讲。用户参考包含多图、表格、普通解释和分级标题时，可推荐答辩兼复读并说明取舍，仍以用户回答为准。按材料和页面任务安排疏密，不设统一字数、卡片数、图片数或留白比例。把协商存入`design.consultation`，具体落实存入设计稿与`design.direction`。

## 2. 在坐标前写完整逐页设计稿

新稿在工作区建立`design-plan.md`或等价的可读文件。先取得并查看代表页要用的真实图表，再写本轮连续页面；随研究推进补全整稿。图片仍未取得时标记缺口，不能用文字卡先占满整稿后声称完成。已有工程仅更新本次修改范围，不为一个局部修订重做全稿计划。

```markdown
## S04 本页题名
任务与承接：前页已建立什么；本页要让读者理解什么；后页接什么问题。
证据与来源：列出已取得图/表/公式/素材的具体部分、来源位置、资产ID或核实数据文件；保留单位和比较对象。
读图任务：本页让读者看到什么分布、比较、空间结构或机制；哪些标签与范围必须可读。
可见内容：围绕实际证据写出题名、局部标题、就近解释、条件、读数和边界。
关系：哪些内容比较、包含、先后、依赖或互相限定；区分来源事实与作者整理。
表达与组合：各组用什么载体，哪些共享范围/尺度，哪里是内部子组，解释紧邻什么。
卡片与参考：实际查看的候选、拟选preset或原生重组；图是否嵌入卡片；按内容作了什么调整。
层级与路径：章节、页题、题签、正文、数据标签与来源各自职责；读者从哪里进入，怎样走完。
文字编辑：可删的同义复述、必须保留的条件、题名/题签的语义换行和本页实际字号。
范围与缺项：哪些必要信息尚无来源；哪些有依据的补充放讲稿/附录。
```

这里的“可见内容”是可直接排入画面的完整表达，不能只写“展示结果”“加流程图”或几个标题。数据较多时引用已核对的表格、脚本输出或具体图面板，并列明要显示的行列、条件、轴和图例，不必在多个文件重复抄数。图像、示意图与文字的身份要清楚；记录未提供的素材，不虚构显微图、装置照片或研究结果。

先看同一页需要共同出现的信息，再划分区域。优先尝试原图与局部放大、相关结果图组与条件表、方法结构与验证子图等内容组合，把解释放到它所解释的图段旁。一个段落如果承担因果说明、方法限定或连续解释，就保留其完整表达；真正并列的信息才适合项目符号。材料不足时先执行来源获取流程，再说明实际缺口，不把未经寻找的图片当成不存在。教学演示见[page-design-workshop.md](page-design-workshop.md)，按当前困难页类型读取相应案例。

### 同时安排整稿的图文组合

用一张简短的页序表记录每页的任务、主要材料、组合方式和与邻页的差别，再核对整稿概览。图片比例、证据关系与阅读路径要真正影响安排；先确定“左图右三卡”再逐页替换论文不属于逐页设计。

| 内容关系 | 可以采用的组合 |
| --- | --- |
| 同条件下的处理对照 | 两张配对图卡、共同条件带及跨栏判断，保留共同尺度。 |
| 整体分布与局部异常 | 总览图加已核对局部图卡，说明紧邻对应区域。 |
| 不同变量的时间变化 | 上下图列或共享横轴的多图，解释放在对应层。 |
| 方法中有关键验证节点 | 流程区域与节点图卡、局部读数相连，箭头保持真实含义。 |
| 图与完整数值共同决定判断 | 大图配短表，或图卡上方/下方接横跨条件矩阵。 |
| 跨文献证据综合 | 问题与证据逐项对应，多图卡与比较条件共同组织，不直接拼摘要。 |
| 单图承担主要观察 | 开放大图和就近注释，或一张图卡；无须额外制造三张文字卡。 |

这些是关系选择，不是按页号轮换的模板清单。一次使用几种结构由材料决定，不设置“至少几种布局”的装饰配额。相同实验的连续比较可一致；不同任务却持续同构时重新组织。图卡细节见[image-cards.md](image-cards.md)。

## 3. 用设计稿作建页输入

按以下次序完成本页，最后再写坐标：

1. 核对实际可见内容与来源，确定必须同时呈现的比较或解释。
2. 选择载体：原图、局部窗口、准确数据图、指标表、方法关系、公式或组合。可将图与解释嵌入合适图卡，也可开放排版；让结果与机制获得实际可读的视觉表达，再为必要说明选择文字卡。卡片数量不代表证据覆盖。
3. 决定关系怎样被看见：共同基线表示可比；连接线表示有依据的先后或依赖；邻接表示解释归属；共同边界表示范围；子区表示包含。没有相应科学关系就不添加暗示它的箭头或容器。
4. 确定标题和文字层级、入口与阅读路径，给普通解释和条件留出空间。共享大区域可以承载多个局部组，不要求每组单独套框。
5. 分配真实面积、间距与坐标，按[composition.md](composition.md)映射到受支持对象。空间不足时按[typography-editing.md](typography-editing.md)删除同义重复、改善行宽或重组任务，保留改变判断的限定；用户需要更大字时在代表页实际比较后调整。

在设计稿中随手补充必要的对象ID对应，例如“验证曲线 → drawing-validation”“条件矩阵 → panel-conditions”。可以使用一组对象共同完成一个信息组；无需把每个词拆成面板。重新设计时同步更新有关段落，保留更改原因，不能先完成页面再补一段声称符合原计划的理由。

组合页的`visualPlan`是这份设计的工具侧摘要。`primaryPanelId`可指承载主要比较、方法或组合入口的区域，表示阅读重点，不强制一张唯一大图。`readingOrder`覆盖实际面板一次；`contentLayers`按需对应真实区域，字段以contract为准。设计稿比这些字段更完整，字段存在也不代表画面已经兑现。

## 4. 比较同等内容的真实候选

新做整稿时，为封面和最难的证据/机制页各绘制两个实质不同的候选。两种困难页保留同一组必需内容，比较完整阅读路径与信息组合：例如配对数据加误差视图，或原图局部加条件矩阵；不要通过删去证据得到一个更稀疏的候选。封面比较题名承托、范围与真实元信息的关系。

将2–6项`{id,label,slide}`写为小于1MiB的UTF-8 JSON数组，用`academic_ppt_study`的`candidatesPath`与新outputDir输出实际预览。先查工具契约。颜色、圆角或同组框的小幅宽度变化不构成另一种组合。需要图像模型时可利用视觉提示，但精确数据、公式与科学关系仍由已核对材料决定。

以相同观看尺度并列检查候选、来源图和相关参考正文。按[template-learning.md](template-learning.md)记录具体差距、原因和修复，不只写“更专业”。向用户展示封面与代表正文，明确询问封面选择及密度、图文大小和风格是否符合预期；已明确委托时自行选定并记录依据。形成连续三页后查看任务推进、主视觉和文字节奏，再继续整稿。坐标、对齐和常规修复由作者完成，不把全部设计工作转交用户。

## 5. 检查实际兑现

渲染后回到逐页设计稿，逐项对应实际页面：

- 图源清单中的已选材料是否实际可见且足够大，哪些被遗漏、只留在讲稿，或退化为几条结论。文字卡和装饰面积不能冒充证据占幅。
- 比较、包含、先后和解释归属能否从位置、尺度、线和边界读出，是否与源材料一致。
- 章节、页题、题签、普通解释、读数和来源是否各司其职；入口可以是组合区域，不必所有页一图独大。
- 文字是否在语义处换行，题签是否出现孤字，术语与单位是否拆开；用户选定的密度和字级是否出现在实际画面。
- 图卡与文字卡是否使用了适合内容的候选，而不是只调用过目录；相邻不同任务的页面是否仍然重复同一种图加三卡骨架。
- 与参考的差距来自材料缺少图像/实验，还是来自标题、比例、标注、图文邻接和表达不足；后者要修复，前者不靠编造补足。

记录实际问题和本轮修复，在当前PPTX上复看。科学错误与缺项优先，其次是载体与关系，再处理比例、层级、间距和线条。连续同尺度比较可保持一致，不为变化破坏可比性。提供旧工程时按[originality.md](originality.md)调用portfolio；没有工程不扫描其他任务。软件通过和结构不重复都不能证明已达到用户参考的设计水平。
