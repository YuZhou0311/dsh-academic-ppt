# 学术页面语法：由问题与证据选择整页关系

0.9.0 的页面语法用于把已经核验的材料组织成可读论证。它们是可改写的构图建议，不能替代研究、不能提供结论、不能证明原图可读。所有配方及图册均为原创；用户的商业模板只可提炼通用原则，原图、字体、Logo、整页设计和示例研究数据不能混入公开分发包。

## 使用顺序

1. 先写本页要回答的问题、证据支持到哪一步、如何连接上一页与下一页。
2. 检查图的长宽比、面板数、最小标签、坐标单位与比较条件，确认需要的真实载体。
3. 根据关系选择起点；已有选择或明确委托直接沿用。若完整方向仍有实质分歧，或困难样张暴露出可读性风险，再用同一批真实内容比较 2 个候选，集中在样张阶段解决，不为每页重复制作备选或重新询问。
4. 选择语法并绑定已存在的 figure/card/drawing/table/diagram/plot。没有对应内容时换语法或原创布局，不能为填槽位编造数据。
5. 按实际字号和原图标签检查容量。改变区域比例或转为自由构图，必要时拆页。
6. 渲染实际 PPTX，逐页检查证据保全、标题、标注、连接线和口头讲解节奏。结构检查通过不代表视觉通过。

同一实验的多组结果可以使用相同构图，以帮助直接比较。语法数量、图片数量、卡片数量、最低字数不构成质量配额。解释侧栏、证据多面板和单幅大图均可成立，取决于本页任务。

## 32 种关系及适用范围

| --- | --- | --- | --- | --- |
| `question-evidence` | 现象、证据与可检验问题 | evidence-explanation | 开场需要把实际现象收束为一个能被研究回答的问题。 | `research-gap` / `hero-evidence` |
| `hero-evidence` | 单一证据精读 | evidence-explanation | 一幅复杂图需要完整画幅读清轴、图例与关系。 | `evidence-margin` / `small-multiples` |
| `evidence-margin` | 主证据与开放旁注 | evidence-explanation | 一幅可读主图只需要短的解释与适用边界。 | `hero-evidence` / `evidence-ledger` |
| `evidence-ledger` | 主图、解释与边界分层 | evidence-explanation | 同一证据需要明确分开结果解释与适用边界。 | `evidence-margin` / `mechanism-proof` |
| `paired-comparison` | 共尺度对照 | comparison | 两个处理、方法或状态在同一评价口径下直接比较。 | `before-after-delta` / `literature-matrix` |
| `before-after-delta` | 前后状态与差异解释 | comparison | 同一对象的两个时间点或干预前后需要同时呈现差异。 | `paired-comparison` / `contradiction-explainer` |
| `small-multiples` | 可比较的多面板 | matrix | 同一变量在不超过四个明确条件下比较，且能共用尺度。 | `paired-comparison` / `hero-evidence` |
| `result-statistics` | 总体结果与精确统计 | evidence-explanation | 趋势/分布与少量精确统计值需要同时供观众核对。 | `distribution-uncertainty` / `evidence-ledger` |
| `distribution-uncertainty` | 分布与估计不确定性 | comparison | 需要区分个体观测分布和总体估计区间。 | `result-statistics` / `paired-comparison` |
| `map-and-detail` | 总体定位与局部证据 | hierarchy | 需要把局部现象放回总体对象、空间或系统。 | `hero-evidence` / `evidence-ledger` |
| `scale-ladder` | 跨尺度关系 | hierarchy | 研究把不同尺度的观测、过程或外推联系起来。 | `method-pipeline` / `source-evidence-map` |
| `source-evidence-map` | 来源到论证的映射 | synthesis | 多篇研究为同一个问题提供不同证据角色。 | `literature-matrix` / `cross-study-synthesis` |
| `literature-matrix` | 文献证据矩阵 | matrix | 跨研究按少数相同维度进行可审查比较。 | `source-evidence-map` / `cross-study-synthesis` |
| `research-gap` | 已有能力、失效条件与缺口 | synthesis | 需要从已有研究推导一个具体缺口。 | `question-evidence` / `proposal-decision` |
| `method-pipeline` | 方法管线与输入输出约束 | sequence | 方法有清晰的输入、变换、输出以及相应条件。 | `method-swimlane` / `feedback-cycle` |
| `method-swimlane` | 并行方法泳道 | sequence | 两个主体、数据源或阶段并行执行后汇合。 | `method-pipeline` / `factorial-design` |
| `feedback-cycle` | 状态更新与反馈回路 | mechanism | 观测或反馈改变系统的下一状态，线性列表会丢失核心机制。 | `method-pipeline` / `equation-interpretation` |
| `experiment-design` | 实验处理与共同评估 | hierarchy | 需要说明样本如何分组、接受处理并进入共同评估。 | `factorial-design` / `cohort-flow` |
| `cohort-flow` | 样本流转与排除理由 | sequence | 样本数量在筛选、随访或清洗中发生变化。 | `experiment-design` / `result-statistics` |
| `factorial-design` | 因子、处理组合与分析 | matrix | 两个或多个因素的处理组合决定实验安排。 | `experiment-design` / `literature-matrix` |
| `mechanism-proof` | 机制与支持证据 | mechanism | 机制示意需要与具体结果相互核对。 | `evidence-ledger` / `contradiction-explainer` |
| `equation-interpretation` | 公式、符号与成立条件 | definition | 核心方程值得逐项解释，并且影响后续方法或判断。 | `feedback-cycle` / `method-pipeline` |
| `ablation-study` | 消融结果与干预定义 | comparison | 需要把性能变化与具体移除/替换的组件关联。 | `result-statistics` / `paired-comparison` |
| `robustness-landscape` | 条件变化与稳健性边界 | matrix | 结论随环境、参数或数据分布变化，需要呈现失效区域。 | `small-multiples` / `limitation-response` |
| `contradiction-explainer` | 冲突结果与条件解释 | comparison | 研究得到方向不同的结果，需要解释条件差异。 | `paired-comparison` / `cross-study-synthesis` |
| `cross-study-synthesis` | 跨研究证据与综合判断 | synthesis | 一组研究已经比较过，需要回答共同问题并保留分歧。 | `literature-matrix` / `source-evidence-map` |
| `limitation-response` | 局限、影响与可检验响应 | matrix | 需要把局限具体连接到影响和补救/验证动作。 | `proposal-decision` / `robustness-landscape` |
| `proposal-decision` | 研究方案与判定分支 | sequence | 尚未实施的方案需要解释如何得到可判定结果。 | `experiment-design` / `research-gap` |
| `work-package-dependency` | 研究任务的依赖网络 | hierarchy | 多个工作包有真实数据、方法或交付物依赖。 | `method-swimlane` / `milestone-timeline` |
| `milestone-timeline` | 里程碑与验收证据 | sequence | 研究进度必须对应时间和可核验交付物。 | `work-package-dependency` / `proposal-decision` |
| `resource-allocation` | 资源结构与精确核对 | hierarchy | 需要解释资源如何分配，并核对总量与项目。 | `result-statistics` / `literature-matrix` |
| `conclusion-return` | 以证据回应开场问题 | synthesis | 结尾需要回到开场问题，明确已知、边界和下一步讨论。 | `cross-study-synthesis` / `question-evidence` |

## 调用与现有格式的关系

运行时目录由 `academic_ppt_layouts` 暴露。JavaScript 可直接使用以下原生 API：

```js
import { listPageRecipes, getPageRecipe, recommendPageRecipes, compilePageRecipe }
  from './src/page-recipes.mjs';

// 排名仅提供建议；score 不是内容质量分，也不授予交付权限。
const candidates = recommendPageRecipes({
  purpose: 'comparison', relationship: 'comparison',
  carriers: ['figure', 'card'], evidenceCount: 2,
  figureAspect: 1.35, textChars: 100, limit: 3,
});

const compiled = compilePageRecipe('paired-comparison', {
  // rows 由现有 renderer 根据标题、来源等实际剩余空间分配。
  mode: 'rows',
  bindings: {
    a: { figureIds: ['source-a'] },
    b: { figureIds: ['source-b'] },
    conditions: { cardIds: ['comparison-conditions'] },
  },
  rationale: '两个处理共用指标、坐标和评价窗口，条件就近共享。',
});
const slide = { ...authoredSlide, ...compiled.slidePatch };
// authoredSlide.figureIds、cards 和 project.assets 仍须包含真实来源。
// 编译只产生现有 composition + visualPlan，不生成研究内容。
```

编译器返回 `{recipeId, slidePatch, warnings}`。`slidePatch` 只包含现有契约字段 `layout:'academic'`、`composition`、`visualPlan`。请将返回 patch 合并到已经撰写的 slide，不能把整个返回对象当成 slide。

`mode:'regions'` 需要显式给出 `contentBox:{x,y,w,h}`。这是当前页题、导语、结论、来源占位后的**真实剩余正文区域**，不是固定画布边界。区域按照配方的归一化坐标映射到该范围。`overrides[slotId].box` 可替换归一化坐标，例如改变主辅比、图的高度或阅读顺序。独立区域不得重叠；嵌套分组用同一个 drawing 内部的形状表达。修改阅读顺序需同步调整最终 `visualPlan`，不能假定几何变化后原顺序仍然适用。

同一载体只能分配到一个位置。空槽位、错误 carrier、非法 ID、重复分配、超出页面契约的对象总量、越界和区域重叠会报错。建议容量超出会提示，不用悄悄缩字来修复。编译器不验证资产是否真实存在、论文结论是否成立或原图文字是否可读；这些仍由正常 record/check/render/review 流程验证。

### 每个配方的证据要求与反例

#### 现象、证据与可检验问题（`question-evidence`）

- 构图关系：现象建立入口，证据解释为何重要，问题连接下一页的检验。
- 证据需要：可定位的现象或需求证据；明确尚未回答的关系。
- 避免使用：已经进入结果精读，或现象图只起装饰作用。
- 容量提示：1–2 个主要证据对象，解释文字约 180 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`observation`（实际现象）；`context`（现象发生的条件）；`question`（需要回答的问题）。

#### 单一证据精读（`hero-evidence`）

- 构图关系：阅读入口由证据本身决定，内部多面板仍需实际阅读顺序。
- 证据需要：原图、定位、完整轴和单位；解释在图中邻接或进入讲稿。
- 避免使用：没有单一共同问题，却把无关拼图塞满整页。
- 容量提示：1–1 个主要证据对象，解释文字约 80 字是重新测量的起点，不是最低内容要求。优先保住原图标签。原图过密时拆面板，不能仅放大截图。
- 语义槽位：`evidence`（本页主证据）。

#### 主证据与开放旁注（`evidence-margin`）

- 构图关系：证据占主要画幅，侧栏就近解释局部，不复述整页标题。
- 证据需要：主图来源；旁注须区分观察、推断和边界。
- 避免使用：旁注很长，或窄栏使主图的关键标签不可读。
- 容量提示：1–1 个主要证据对象，解释文字约 150 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`evidence`（主证据）；`interpretation`（解释与适用边界）。

#### 主图、解释与边界分层（`evidence-ledger`）

- 构图关系：大证据跨两层；上部解释，下部条件，避免相同大小三卡。
- 证据需要：一幅证据，得到该解释的依据，至少一个真实限制条件。
- 避免使用：两个辅助区都只写同义结论。
- 容量提示：1–1 个主要证据对象，解释文字约 210 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`evidence`（观察或结果）；`interpretation`（结果意味着什么）；`boundary`（何时不应外推）。

#### 共尺度对照（`paired-comparison`）

- 构图关系：两个证据在相同高度与尺度对齐，共享比较条件只写一次。
- 证据需要：A/B 的同一尺度、基准、分母、评价窗口和独立样本定义。
- 避免使用：两组研究的样本、指标或尺度不可比且未披露。
- 容量提示：2–2 个主要证据对象，解释文字约 120 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`a`（对照 A）；`b`（对照 B）；`conditions`（使比较成立的共同条件）。

#### 前后状态与差异解释（`before-after-delta`）

- 构图关系：上部保留前后证据；下部以差异或变化机制连接，不重复两个描述。
- 证据需要：对象配对规则、前后时间、变化的计量方式与混杂限制。
- 避免使用：不同对象被误写成前后变化，或未排除时间混杂。
- 容量提示：2–3 个主要证据对象，解释文字约 150 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`before`（基线或干预前）；`after`（随访或干预后）；`delta`（配对差异与解释）。

#### 可比较的多面板（`small-multiples`）

- 构图关系：行列有明确语义；位置代表条件，不能为凑四格而添结果。
- 证据需要：各面板的条件、共享或明确不同的尺度、完整图例和来源。
- 避免使用：原论文四个过密面板仍看不清，或各图坐标不相容。
- 容量提示：4–4 个主要证据对象，解释文字约 90 字是重新测量的起点，不是最低内容要求。四面板只是本配方形态；材料只有两组时改选双图。
- 语义槽位：`a`（条件 A）；`b`（条件 B）；`c`（条件 C）；`d`（条件 D）。

#### 总体结果与精确统计（`result-statistics`）

- 构图关系：上部读模式，下部核对数值；统计表不应挤成小角落。
- 证据需要：结果图、同一分析的统计量、单位、n 和不确定性定义。
- 避免使用：数字表仅复述图中全部数值，或不确定性来源未知。
- 容量提示：1–2 个主要证据对象，解释文字约 100 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`result`（结果模式）；`statistics`（精确统计与样本条件）。

#### 分布与估计不确定性（`distribution-uncertainty`）

- 构图关系：分布与估计分开表达，并共享样本及单位说明。
- 证据需要：原始观测或已报告分布；已报告或可复算区间；区间的定义。
- 避免使用：只有均值却编造离散点、箱线图或置信区间。
- 容量提示：2–2 个主要证据对象，解释文字约 120 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`distribution`（个体观测分布）；`uncertainty`（估计与区间）；`sample`（样本与区间定义）。

#### 总体定位与局部证据（`map-and-detail`）

- 构图关系：总览跨两层，两个局部与总览中明确标记的位置对应。
- 证据需要：总体与局部的定位关系、比例尺/坐标、裁剪与放大说明。
- 避免使用：局部图与总体没有可追踪对应，或裁剪丢掉决定性边界。
- 容量提示：2–3 个主要证据对象，解释文字约 140 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`overview`（总体与定位标记）；`detail-a`（局部 A）；`detail-b`（局部 B）。

#### 跨尺度关系（`scale-ladder`）

- 构图关系：一个连续关系图表达尺度转换；辅助栏列出不能直接外推的条件。
- 证据需要：每层的空间/时间支持、测量对象和跨尺度映射假设。
- 避免使用：仅有三个平行对象却画成上下游或尺度递进。
- 容量提示：1–3 个主要证据对象，解释文字约 200 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`scales`（尺度与映射关系）；`assumptions`（跨尺度映射条件）。

#### 来源到论证的映射（`source-evidence-map`）

- 构图关系：来源列对接论证图；连接线必须能解释支持的具体命题。
- 证据需要：每个来源的具体结论、定位和支持/冲突/补充身份。
- 避免使用：只是将论文封面并排，缺少共同问题或支持关系。
- 容量提示：2–4 个主要证据对象，解释文字约 230 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`sources`（来源与研究条件）；`argument-map`（共同问题与证据关系）。

#### 文献证据矩阵（`literature-matrix`）

- 构图关系：列是比较维度，行是研究或方法；边界与缺测必须显式保留。
- 证据需要：来源、研究条件、比较维度与不可比项，逐行可追溯。
- 避免使用：表中塞下每篇论文的所有摘要，或指标定义不同却直接排名。
- 容量提示：2–8 个主要证据对象，解释文字约 350 字是重新测量的起点，不是最低内容要求。典型 3–6 行、3–5 列是可读起点，不是硬性研究数量要求。
- 语义槽位：`matrix`（可审查的研究比较）；`scope`（可比性与缺测说明）。

#### 已有能力、失效条件与缺口（`research-gap`）

- 构图关系：上部对照能力与边界，下部把缺口写成可操作的关系。
- 证据需要：已有能力的真实证据、失效/未覆盖条件及可检验问题。
- 避免使用：用“研究很少”代替证据，或未检索就宣布首次。
- 容量提示：1–2 个主要证据对象，解释文字约 240 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`known`（已有研究已经做到什么）；`boundary`（在哪些条件下仍不足）；`gap`（由证据推出的研究问题）。

#### 方法管线与输入输出约束（`method-pipeline`）

- 构图关系：主流程横贯画幅，下方解释输入条件与输出验证，箭头端点真实。
- 证据需要：真实操作和数据流；每一步的输入输出对象；训练/评估边界。
- 避免使用：步骤本身是反馈或并行依赖，却被线性箭头掩盖。
- 容量提示：1–1 个主要证据对象，解释文字约 200 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`pipeline`（输入、变换与输出）；`inputs`（输入与约束）；`validation`（输出与验证）。

#### 并行方法泳道（`method-swimlane`）

- 构图关系：行代表主体、列代表阶段；跨行连线表达数据交换，不做装饰。
- 证据需要：各泳道主体、共享阶段、交互/汇合点及传递对象。
- 避免使用：实际仅是三个相邻标签，或流程顺序/同步关系未知。
- 容量提示：1–1 个主要证据对象，解释文字约 220 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`swimlanes`（并行阶段及交互）。

#### 状态更新与反馈回路（`feedback-cycle`）

- 构图关系：闭环中区分预测、观测与校正，右栏保留状态/参数/单位身份。
- 证据需要：预测状态、观测、误差/创新量、更新对象和时间索引。
- 避免使用：没有实际更新方程或因果方向，却画一个闭环表示完整。
- 容量提示：1–2 个主要证据对象，解释文字约 220 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`cycle`（预测与更新回路）；`states`（状态与更新条件）。

#### 实验处理与共同评估（`experiment-design`）

- 构图关系：分支代表处理，汇合代表共同评估；下栏保留公平比较的条件。
- 证据需要：实验单位、分配规则、处理、对照、评价指标和重复结构。
- 避免使用：直接放结果却没有交代随机化、对照或分析单位。
- 容量提示：1–1 个主要证据对象，解释文字约 210 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`design`（样本、处理与评估）；`controls`（对照、重复与测量条件）。

#### 样本流转与排除理由（`cohort-flow`）

- 构图关系：纵向流转与右侧排除/分组对应，不能以流程图掩盖样本变化。
- 证据需要：每一步的样本数量、排除理由、分析集与重复单位。
- 避免使用：只有总样本量，无法核对各步骤的数量守恒。
- 容量提示：1–2 个主要证据对象，解释文字约 220 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`flow`（筛选与分析集）；`accounting`（样本量与排除依据）。

#### 因子、处理组合与分析（`factorial-design`）

- 构图关系：左侧精确组合矩阵，右侧表达分配/分析关系。
- 证据需要：因素、水平、重复、随机化/区组方式、交互效应的分析定义。
- 避免使用：观测分组被误写成随机因子设计。
- 容量提示：1–2 个主要证据对象，解释文字约 190 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`factors`（因素与水平组合）；`allocation`（分配、重复与分析）。

#### 机制与支持证据（`mechanism-proof`）

- 构图关系：左机制右证据逐点对应，下栏标明证据不能证明什么。
- 证据需要：机制来源、对应观测/干预、替代解释和适用边界。
- 避免使用：示意箭头被当成因果证据，或证据只支持相关性。
- 容量提示：1–2 个主要证据对象，解释文字约 180 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`mechanism`（待解释的机制）；`proof`（支持或约束该机制的证据）；`limits`（因果与外推边界）。

#### 公式、符号与成立条件（`equation-interpretation`）

- 构图关系：公式为主视觉；符号解释与假设是不同层，不能只放无定义方程。
- 证据需要：公式来源/推导身份、变量与单位、假设、适用域。
- 避免使用：公式仅增加学术感，或渲染不能保留数学符号。
- 容量提示：1–1 个主要证据对象，解释文字约 220 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`equation`（关键表达式）；`symbols`（变量、单位与含义）；`assumptions`（成立条件）。

#### 消融结果与干预定义（`ablation-study`）

- 构图关系：左侧结果对齐右侧组件/干预表，阅读者能核查每个比较的含义。
- 证据需要：基线、唯一干预、共同训练/验证条件、方差和指标方向。
- 避免使用：多个因素同时变化却把差异归因于单一组件。
- 容量提示：1–2 个主要证据对象，解释文字约 170 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`effects`（消融效果与不确定性）；`interventions`（组件与公平比较条件）。

#### 条件变化与稳健性边界（`robustness-landscape`）

- 构图关系：上部条件空间保留连续性/离散性，下部解释有效域与失效域。
- 证据需要：实际扫描范围、指标尺度、失败条件与未观测区域。
- 避免使用：只有最佳配置的一个数字，却宣称普遍稳健。
- 容量提示：1–2 个主要证据对象，解释文字约 180 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`landscape`（条件空间与结果）；`supported`（被证据支持的范围）；`failure`（失效或未知范围）。

#### 冲突结果与条件解释（`contradiction-explainer`）

- 构图关系：冲突先可见，再比较可能解释；假设性的解释明确为推断。
- 证据需要：两项结果的真实出处、指标、样本、尺度及可比性。
- 避免使用：通过删去反向结果来制造一致结论。
- 容量提示：2–2 个主要证据对象，解释文字约 220 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`finding-a`（结果 A）；`finding-b`（结果 B）；`explanation`（条件差异与替代解释）。

#### 跨研究证据与综合判断（`cross-study-synthesis`）

- 构图关系：上部证据关系压缩但可追溯，下部明确综合判断与尚未知之处。
- 证据需要：比较过的来源、支持/冲突/缺测记录和推断边界。
- 避免使用：未完成逐项核对就生成包罗万象的共识。
- 容量提示：2–6 个主要证据对象，解释文字约 240 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`evidence-map`（共同维度下的证据）；`synthesis`（有条件的综合判断）；`unresolved`（仍待回答）。

#### 局限、影响与可检验响应（`limitation-response`）

- 构图关系：每一行是局限→影响→行动的同一关系，行数由实际材料决定。
- 证据需要：局限的证据、影响哪一项判断、可测的响应与失败分支。
- 避免使用：列出泛泛缺点，然后默认未来工作必然解决。
- 容量提示：0–3 个主要证据对象，解释文字约 300 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`responses`（局限、影响与响应的对应关系）。

#### 研究方案与判定分支（`proposal-decision`）

- 构图关系：问题通向实验，再分为支持/不支持两条路径，保留两种结果。
- 证据需要：明确假设、公平对照、观测指标、预先定义的判断及失败后行动。
- 避免使用：将预期效果写成已取得结果，或只画成功路线。
- 容量提示：0–2 个主要证据对象，解释文字约 240 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`hypothesis`（待检验假设）；`test`（实验与判定流程）。

#### 研究任务的依赖网络（`work-package-dependency`）

- 构图关系：节点是研究任务，边是可说明的交付物，关键路径不能靠颜色臆断。
- 证据需要：每个工作包的输入、输出、负责人/边界、依赖与汇合。
- 避免使用：只需并列任务清单却画大量无意义箭头。
- 容量提示：0–1 个主要证据对象，解释文字约 240 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`dependencies`（任务、交付物与依赖）。

#### 里程碑与验收证据（`milestone-timeline`）

- 构图关系：上部时间与任务对齐，下部说明关键里程碑如何被验收。
- 证据需要：开始/结束或阶段时间、依赖、当前状态与验收定义。
- 避免使用：时间点没有依据，或把所有任务画成顺序串行。
- 容量提示：0–1 个主要证据对象，解释文字约 200 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`timeline`（时间、任务与依赖）；`acceptance`（里程碑验收依据）。

#### 资源结构与精确核对（`resource-allocation`）

- 构图关系：结构图解释归属，表格保留精确数值；图表不新增虚构预算。
- 证据需要：真实总量、单位、分配规则、分类互斥性与加总校验。
- 避免使用：缺少真实预算或数量，却用饼图面积暗示精确比例。
- 容量提示：1–2 个主要证据对象，解释文字约 150 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`allocation`（资源归属关系）；`accounting`（精确数值与总量核对）。

#### 以证据回应开场问题（`conclusion-return`）

- 构图关系：主区域回答问题，下部将关键证据与未决条件并置，不引入新发现。
- 证据需要：已讲过的证据链、可支持的回答、不可外推范围。
- 避免使用：最后一页只重复章节标题或喊口号。
- 容量提示：1–3 个主要证据对象，解释文字约 180 字是重新测量的起点，不是最低内容要求。
- 语义槽位：`answer`（对开场问题的有条件回答）；`support`（已呈现的关键证据关系）；`boundary`（讨论与下一步判断）。

## 从优秀参考学习而不套用

可学习网格、主辅比、层级、证据邻接、共享尺度、标题与来源职责、留白和章节节奏。先记录“为什么这个关系适合当前材料”，再独立构图。不要保存商业模板截图作为生成代理的可复制底图；不要复用人物、机构、科研图片、示例结论或其授权不明的字体。整个页面的证据、布局、讲解顺序应能从当前研究问题解释。
