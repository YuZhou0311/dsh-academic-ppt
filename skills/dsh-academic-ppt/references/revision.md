# 在正确版本上控制修改范围

## 1. 先判定层级

| 反馈 | 层级 | 先核查 |
| --- | --- | --- |
| 主题偏、主要围绕智能体、论文不深入 | 科学内容 | 相关性、真实材料、证据 |
| 看不懂要讲什么、逻辑断裂、没有目录分节 | 叙事 | 中心问题、narrative章节问题、sectionId、过渡、结尾回应 |
| 太简单、信息少、整页同一层级、标题没有设计 | 信息与整页设计 | 被摘要掉的必要材料、主辅信息、标题职责、局部关系与阅读推进 |
| 大图太小、大片空白、各页长得一样 | 整页设计 | 主证据占幅、阅读关系、行列与chrome |
| 卡片无描边、框重复、回到此版本 | 局部组件 | 基线、具体卡片、appearance与外层分组 |

“高级一些”不是重做整套汇报的自动授权。用户进一步限定“小卡片”后采用明确局部边界。已有可识别基线与对象就直接推进，不重复确认已确定条件。

用户明确要求改善整页信息量、表达方式或整稿设计时，按该范围重构必要信息与区域关系，不把反馈缩成换配色、加粗标题或换圆角。先确认本页承担什么任务和缺什么信息，再调整主次、组合、局部题签和载体；保留科学口径与来源。多分块不自动等于多栏，更不要求全部并列或套框。

## 2. 确认真实基线

调用 `academic_ppt_context` 读取项目 ID、revision、产物记录、页面与卡片 ID，核对用户所指版本。文件名相同不保证内容相同，页数不能代替哈希。

要求回到历史版本时先用 `academic_ppt_undo` 恢复相应内容为新 revision，再修改；不能只恢复旧颜色却保留被否定的页序和大布局。

局部编辑针对本插件 JSON 工程与稳定场景 ID，不提供任意外部 PPTX 的无损对象编辑。Office 手改成品或第三方 PPTX 需先确认对应工程；模板检查不是完整工程导入。保留原成品，说明从 JSON 重建不会包含未回写的 Office 修改。

## 3. 样式允许名单

每项记录 slideId/cardId、原因、允许样式和基线。调用 `academic_ppt_edit` 时提供当前 `expectedRevision`、`scope: card-style` 和明确 `changes`。

仅允许 `style`、`accent`、`templateComponentId`、`appearance`、`icon`。appearance可改变layout、表面、圆角、内边距、强调边与轻微层次；layout支持stacked / banded / side-label，具体字段见component-grammar与当前契约。icon从受支持语义图标中选择。锁定卡片标题、正文、指标、单位、证据 ID 与 `box`；同时锁定论文图、完整题名、引用、页序和备注。

更换结构可以调整卡内文字坐标，但不能删字、改数、移动或扩大外框。不能借修溢出删科学限定，也不能移动主图为装饰腾位置。不适配就换更轻结构；确有内容修改需求时，采用已授权的 `slide-content` 并重新核对证据，已构建页面不能走 record 覆盖。

`slide-content` 支持明确删除可选字段：在 change 中设置 `removeFields`，例如从固定模板切换到自定义图框时移除 `referenceTemplateId` 与 `panelTitles`。逐页标题线、品牌字和导航通过chrome调整；组合结束页不再使用原生closing对象时显式移除它。不使用 null、undefined 或手工删工程 JSON；同一字段不能同时放入 patch 和 removeFields。可删除范围见 edit 契约，必需证据和记录不能借此删除。

改写数值、单位或图注后，对照修改前后核对条件、分母、观察量名称与关键限定是否仍完整。修一个单位不能顺手删掉删失、模拟、未随机化证据或尚未执行等边界；同步检查对应演讲备注。把同一轮已发现问题集中修正，再构建和渲染。

若工具报错但可能已发生保存，先用 context 读取当前 revision 和相关对象，确认是否提交；不要直接用旧 revision 重放整个修改批次。

## 4. 检查真正局限在目标卡片

场景节点使用稳定 ID。只有目标卡片前缀下允许结构样式变化，其他节点与备注必须相同；目标文字内容、数值与外框几何保持，装饰留在卡片范围内。目标卡片内部文字坐标可以变化，不能将语义保留描述为整页像素完全不变。

读取实际 diff 与保留检查结果，不能因只传样式字段就声称全部外部对象已验证。不要绕过工具改 JSON、历史或哈希使检查变绿。

查看受影响页的新预览，优先最矮卡片、最长正文、数值/单位和临近主图边界。若修改涉及整页阅读关系，还要查看前后相邻页的承接和重复。内容保持不等于新结构视觉适配。

## 5. 审查随版本失效

构建、修改、撤销都产生新的对应状态。旧审查不能沿用；审查时提供当前 `pptxSha256`，明确 `html-preview` 或 `pptx-render` 与实际看过页面。

若读取后基线变化，先重新读取再形成补丁，不强制覆盖或拿旧 revision 反复重试。撤销用新 revision 恢复历史内容，重建并检查，不就地伪造旧成品身份。

每次构建写入新输出目录。保留外部 Office 手改文件；新 JSON 构建不是这些手改内容的往返同步。

## 6. 交付具体改动

说明哪些卡片用了哪些结构、为什么适配、实际检查了什么。数字来自本次项目，不能沿用旧案例“49 张卡片”“592 个锁定对象”。保留审计不等于用户审美已认可。
