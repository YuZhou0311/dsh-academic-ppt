# 局部分组与原生组件

按信息归属设计局部组件，使证据、条件、解释与边界形成整体。独立卡片默认采用可见的克制细描边；需要开放注释时显式选择。不要把某一种外观变成所有页的固定答案，也不要将去装饰理解为所有分组都没有边界。

## 先确定职责

| 职责 | 适合的表达 | 要避免的问题 |
| --- | --- | --- |
| 主证据 | 大图、原生表格、同尺度比较或方法结构 | 把原图缩成小卡，放大结论代替证据 |
| 读图解释 | 紧邻数据的短注、图旁文字或局部浅底 | 解释与对象分离，独立短句占满长栏 |
| 条件 | 共同条件条、组内题签、与子图对齐的标签 | 每页重复背景口号，局部条件误作全局 |
| 对照 | 等尺度子图、行列对齐、成组标记 | 为变化破坏共同尺度或改变基线 |
| 机制 | 原生节点、显式边、模块与输入输出 | 无序名词串成因果，交叉线暗示汇合 |
| 边界 | 紧邻相关结论的限定、侧注或证据矩阵 | 把关键限制缩到脚注或只留讲稿 |
| 书目 | 可读的完整参考条目，与正文可分组组合 | 只写作者年份代替完整来源 |

## 选择可见边界

当多个对象属于同一观测来源、处理、模型阶段或比较范围时，可用浅底、细线、题签或框表达共同归属。独立数据图自身已有坐标和边界时，外部可以开放。短注只要邻接与对齐明确，不必套卡片。

常规解释卡从`appearance.surface:outline`起步，使用白色或极浅背景、灰蓝或中性灰细描边、小圆角与适量内边距；`accent:none`、`elevation:false`避免默认粗强调条和阴影。原生卡片会继承`design.cardDefaults`；需要开放时明确覆盖`surface:plain`，不要为了修某一旁注把整稿默认边界全部删除。

通常只保留一层主要分组：外层浅底内用开放文字，或开放主区域旁有少量解释卡。空框、强阴影和重复标题不增加科学信息。卡片不必等宽等高，图内标签不必套独立卡片，未分组的内容也不能任意散落。

composition的surface、heading与padding控制外层表达；heading:hidden可去重复题签，padding按载体分配。rows和regions采用相同的载体规则，后者提供自由位置。精确属性及互斥关系通过contract查询。

## 原生绘制与既有卡片

需要自主组件形状、关系或位置时使用slide.drawings的文本、矩形、椭圆、线与登记图片。用内部坐标设计后，检查实际区域缩放的字号和线宽；既有card.appearance仍可用于常规解释，选择outline/tint/solid/plain、圆角、强调边与内边距。两种方法服务当前内容，不要求从固定卡片库挑选。

样式只改变表达，不补充证据。涉及数据的长度、面积、位置或连接必须有明确含义和出处；辅助框与装饰线不计科学载体。复杂关系优先精简节点标签，将条件放到对应关系旁。

颜色用于帮助辨认变量、模块、条件或证据身份，在全稿保持一致；关键区别也用文字或线型表示。保留原图数据系列原义，不用卡片语义色随意重染数据。图标可选且应明确，不依赖emoji缺字，不给每张卡强制添加。

## 层次与间距

主证据获得阅读所需空间，普通解释保留中间字级，辅助注释较轻。面板标题与内部标题表达不同层次，重复时隐藏一个；不要一组内容被两层同义题签挤压。

以实际内容计高，短卡收紧后要重新安排剩余页面；长条件不持续缩字。边界围住真实内容，不能把一句话拉成大空框。相同对照保持同尺度，不为追求不同随意改变比例。

## 检查实际画面

在PPTX渲染中检查描边是否实际可见且克制、分组是否一眼可辨、文字是否对应正确证据、线的端点和标签是否清楚。看整稿是否每页仍是同样几个矩形，或反过来只剩大小字。优先修改与研究关系不匹配的分组，再微调外观。

当前插件的可编辑能力不等于任意动画、SmartArt、三维效果或图内数据可编辑。不要在JSON中编造未支持字段，不承诺没有实际生成的效果。
