# 学习参考的证据组织

## 新建汇报时确认参考意向

在首次规划新汇报时，核对用户是否已提供模板或说明不需要模板。意向未知时，将一次模板问题并入[design-dialogue.md](design-dialogue.md)的早期对话：“这次有希望参考设计的 PPT/PPTX 模板吗？可以上传；没有的话，我按当前学术设计流程继续。”区分“上传 PPT 参考 / 使用当前流程”，也可稍后提供。已有回答、已选PPT或仅修改现稿时不重复问；截图也可先学习，不要求另找PPT。

这个问题用于选择参考来源。用户选择当前流程或明确跳过时，继续查证、取图、内置卡片学习和逐页设计；不因缺少模板暂停。等待模板回答或上传时也可先做研究。刚问出问题还没有收到答复，不得立刻记成“无回答”，更不能以此跳过密度、配色等单独设计决定。只处理实际收到的文件，不假设能访问用户电脑或历史附件。

先调用`academic_ppt_contract({"topic":"preparation"})`取得准备记录schema，再把本次汇报内容和已知选择写入本地JSON，调用`academic_ppt_prepare({requestPath,outputPath?})`。模板选择写在`template`记录中，沿用工具返回的状态与下一步；生成的准备文件可用于继续任务，不能每轮把用户已回答的状态重置成未知。工具提供分支计划，不会代替宿主提问、上传或下载文件。

| `template.status` | 实际含义与处理 |
| --- | --- |
| `unasked` | 意向未知，执行一次性问题并等候真实答复；不在同一轮自动代答 |
| `awaiting-upload` | 用户选择上传但尚未收到文件；继续内容工作，收到后填真实路径，不重复问是否需要模板 |
| `provided` | 已取得本地`.pptx`或`.ppt`路径；尚无匹配观察记录时检查PPTX并看图，旧PPT先转换；已有匹配`review`则继续设计 |
| `none` | 用户明确使用当前流程，按内容和内置目录继续 |
| `unanswered` | 宿主明确返回未回答或用户已跳过模板选择，按当前流程继续；以后补充文件时再切换 |

模板上传由宿主完成。`academic_ppt_template`读取本次工作区中实际存在的`.pptx`；旧`.ppt`先通过宿主已支持的转换方式另存为PPTX，或请用户导出后附上。PDF与截图按视觉参考处理，不交给PPTX解析器，不声称支持任意Office格式或完整母版还原。文件路径、状态和说明只放入当前契约支持的位置。

## 先确定参考用途

没有参考时使用content-led；用户给出喜欢的学术汇报、希望借鉴感觉时使用reference-guided；仅明确要求逐页沿用版式时使用template-faithful。上传模板本身不等于要求整稿复制。mode记录工作约定，不会自动排版或保证模板克隆。用户提供的真实要求高于模式默认，不为消除提醒擅自切换模式。

参考学习发生在逐页设计与候选绘制之前。研究原稿怎样容纳信息、区分主次、组合局部关系和推进问题，将可迁移的方法写进[visual-decision.md](visual-decision.md)规定的逐页设计稿。普通参考允许自主改动颜色、题签、边界、比例和分区；依据本稿内容与读者任务决定保留或改造。颜色、坐标、卡数和横条比例本身不构成学习结果，也不要求为显示差异而全部改变。

## 取得实际观察

参考为PPTX时，调用`academic_ppt_template({filePath,render:true})`并取得真实渲染；fontDirectories只传实际存在的目录。按本次学习范围查看全稿概览，逐页记录职责和主要信息组合，再精看方法、对照、综合、密集页及相邻段落。不同正文类型都应进入观察，不能只看封面、目录或某一张漂亮页。结构推断、字号统计与suggestedDesign帮助定位，不替代看图；图片内部标签、继承字体和复杂母版尤其需要实看。

完成实际提取和看图后，在准备请求的`template.review`中填写工具输出的`profilePaths`、真实`visualObservations`，以及可选`renderReferences`。`academic_ppt_prepare`核对每份profile与当前上传PPTX的hash；匹配时返回`continue-reference-guided`，不重复检查同一模板。模板改变时重新提取并看图，不沿用旧profile；由旧PPT转换后先把`localPaths`换成实际PPTX。hash匹配只证明profile对应文件，视觉观察仍由实际看图者负责。

参考为PDF时查看实际页面并结合文本/字号提取；截图直接查看。不要把PDF或图片交给只处理PPTX的模板工具，不声称取得原母版或精确字体。仅有封面截图只能支持题名、元信息、配色和空间秩序的偏好，不能推断内页结构或证据密度。

核对缺失字体、替代字体、数学符号和异常换行。将渲染限制与参考本身的问题分开记录；必要时换可用渲染方式复核，不能学习缺字或错位，也不能在未打开原宿主时声称无损还原。

只提取可转移的设计依据。未获得再分发授权的用户原始PPT、截图、机构标志与提取媒体不随交付包发布。模板的论文、人物、数字、结论、背景图与旧身份不得成为新研究事实。

原文件缺失或视觉能力不足时，明确依据是用户文字、历史笔记还是实际页面，不能把记忆写成重新审阅。完成能支持的设计，保留需要实际对照的限制。

## 保存逐页观察与迁移笔记

用简短表格记录实际看过的每页：页号、页面职责、主要证据与辅助信息、主构图与局部关系、标题层级、它怎样接前后页。总览先确定结构，密集页与关键段落按可读尺寸核对。没有看过的页不列入观察范围。区分现场短讲、答辩兼复读与阅读材料，避免从封面简洁误推出正文稀疏。

| 观察项 | 在参考中看什么 | 在当前材料中怎样使用 |
| --- | --- | --- |
| 主辅证据 | 第一眼看到什么，辅助图和文字放在哪里 | 选择当前最有判断价值的图/表/关系，按职责分配空间 |
| 信息充分性 | 哪些证据、方法、条件和解释共同支持本页问题 | 先恢复必要信息，再选载体，不把字多或图多当成目标 |
| 多层组合 | 主构图下怎样继续分组，局部是否混合比较、递进、主辅或包含 | 根据当前关系选择上下、跨栏、嵌套、局部穿插等，不固定为等宽并列 |
| 局部分组 | 图像是否嵌入卡片，边界、浅底、题签、对齐或空隙表达什么归属 | 围绕当前图与对应解释组织证据组，保留独立图片与可编辑文字，不能每块同款 |
| 图文对应 | 哪段解释紧邻哪个区域，图例与限定在哪里 | 将指标、条件、边界贴到对应图/表，避免远端找关系 |
| 标题与文字层级 | 章节定位、页级题名、题签、普通解释和图注怎样区分，句子在哪里换行 | 用承托、对齐、字重和语义建立层级；精简复述，修复孤行和术语拆分 |
| 颜色与线型 | 哪些颜色表达变量、处理、模块或状态 | 建立当前材料的稳定语义，保留原图数据颜色含义 |
| 封面与标题 | 题名断行、元信息与留白的关系，是否确有必要用图 | 文字主导地重新排当前题名和身份；有明确识别用途才加图 |
| 全稿节奏 | 目录、分节、转折怎样定位，不同任务怎样变化主载体 | 用本稿问题链确定页序，科学上需要的共同尺度保持一致 |

记录可取得的来源hash及实际看过的页号或截图名，选择有用原则及需要避免的做法。区分“稳定设计语言”与“随任务变化的结构”：同组证据可一致，方法、验证、综合与计划通常需要不同阅读关系。参考中的字过小、章节错号、旧项目名、科技纹理或巨型标识都不应照搬。引用笔记即可，不把长篇分析放入正式讲稿。

## 记录具体差距，再修复候选

封面和最难正文按visual-decision绘制真实候选。保持必要内容相同，把参考正文、当前来源图和候选放在相同观看尺度比较。用以下格式记录确实观察到的差距，不只写“更丰富”“更专业”或整体分数：

| 参考页及观察 | 当前页的具体差距 | 原因 | 本轮修复与复看结果 |
| --- | --- | --- | --- |
| 实际页号；指出标题、证据组或解释怎样共同阅读 | 指出哪个内容、区域或层级不足 | 材料缺项 / 内容取舍 / 表达组织 / 渲染限制 | 写实际改动；说明新页面是否解决，或仍缺什么 |

例如，参考让处理条件与相应子图同列，而当前条件远离对应数据，属于表达组织问题；应调整邻接与对齐，再看实际输出。参考用论文图表达而当前只有摘要卡时，先核查本稿原图是否已实际查找、下载和查看，不能立刻归因于材料不同。完成获取仍只有数值记录时，可充分呈现可核验的数据、条件和方法关系，不能生成照片冒充研究证据。材料不同也不能解释题签混乱、正文全是大字、标注缺失或同款空框，这些仍需设计修复。

比较信息充分性、主构图与局部关系、标题和中间解释层、图表标注、对齐、边界及颜色职责。一个表格与几幅相关子图可以共同承担入口，参考里并非一图独大时不要强行放大一幅图挤掉其他必要信息。读取原PPTX可核对真实字号；只有PDF/截图时说明估计依据，不能声称取得精确母版。

选定后连续看三页的任务、信息增量、主视觉与局部结构。保留科学比较需要的共同尺度；不同任务的差别要体现在实际关系和表达中。完整稿再回看差距记录，不能用软件通过替代“哪些差距已经修复”。用户要求template-faithful时另按指定范围核对，披露不支持的效果。

## 参考库与组件

suggestedDesign是待审定变量，按当前图文和用户反馈适配后才记录。配色不必原样继承，可推荐design契约的学术候选或当前组合，确认后用`design.colorRoles`保持共同语义。components帮助理解局部归属；先对照实际图幅、题名、条目、解释、读数与限定，再按[card-design.md](card-design.md)查询、查看并选择。图片嵌入方式见[image-cards.md](image-cards.md)，保留原图可读区域。使用`card.preset`时遵守配方，间距与局部强调走受支持字段；关系不适配时使用原生drawings和自由区域，不杜撰覆盖参数。框、浅底和题签有职责时保留，无职责时开放；去模板化不等于去掉所有设计层次。

将实际卡片学习保存为`design.referenceStudy`，包括候选ID、实际预览路径、观察、采用的预设与内容改造。模板的`template.review`与这份记录互相补充：看过用户模板不等于看过图卡目录，调用过目录也不等于完成模板学习。已有符合当前内容的观察可以复用，不重复加载全部参考。适配理由同时落实在逐页设计稿和实际页面中。

用户卡片图可用于学习浮签、标题带、切角、编号、分隔读数等如何建立阅读层级。先确定本稿内容，再调用实际可用的宿主生图工具探索新的局部组合，查看后原生重建；不能把参考图描一遍、换色换字就作为新设计。没有生图工具仍可直接用原生目录和当前流程。模板媒体与生成参考不自动成为最终证据，参考文件也不自动获得公开再分发权限。

48页内置库按需查看结构，不加载整份示例记录作为新稿起点。其示例正文、图像和假数值不进入当前科学记录。参考页型只能是适配选项，不能反向决定删掉哪些真实证据。
