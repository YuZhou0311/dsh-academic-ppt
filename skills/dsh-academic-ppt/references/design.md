# 学术页面的视觉设计

## 先形成视觉主张

用一句话说明本报告的主题怎样成为画面，例如观测与模型之间的双向关系、尺度之间的映射、成像对象的空间结构。这个选择决定封面主视觉、方法图关系和重点色用途；不能只从主题名挑一种颜色。科学结论仍来自当前证据。

全稿统一字体层级、语义配色、线宽、圆角和间距尺度。主视觉位置、卡片数量、标题处理、页角标签与结尾构图按内容变化。固定同一标题线、右上角词组和左右两栏，不能替代设计语言。

将创作约束记为 `design.mode`：content-led自主设计，reference-guided借鉴设计语言，template-faithful服从用户明确要求的结构。组合页关系与取舍记入visualPlan。决策流程见 [visual-decision.md](visual-decision.md)，真实组件能力见 [component-grammar.md](component-grammar.md)。

## 封面独立设计

封面说明研究主题并建立视觉重心。根据题名长度、可用素材和报告气质决定构图，再选择受支持的 `cover.variant`：

| 方向 | 适用材料 | 设计重点 |
| --- | --- | --- |
| custom | 需要自己安排题名、身份与视觉区的相对位置 | 按当前题名与素材设计角色boxes，不继承预设封面家具 |
| split | 有清楚主题图片或视觉对象 | 题名与主视觉分担画面，避免正文式碎卡 |
| editorial | 题名与核心概念有表达力 | 大标题、语义断行和主题视觉形成重心 |
| framed / project | 用户偏好传统正式学术风格 | 标题、真实身份与主视觉占足面积，去掉无内容的身份基座 |
| minimal | 用户接受疏朗封面且题名有足够视觉份量 | 用户禁止大留白时不能借此保留半页空白 |

完整题名用 `cover.titleLines` 做语义换行，合起来须与slide.title逐字一致。短题可调整design.system.coverTitleSize，长题先重新断行，不堆副题。副题只解释范围。署名、单位、场合和日期须真实；未知时省略，并重排剩余信息，不能保留空机构带。

custom使用 `cover.boxes`，每项为1280×720画布中的{x,y,w,h}：title必需；有slide.subtitle才设subtitle，有cover.occasion或slide.kicker才设occasion，有presenter/affiliation/date才设metadata，有assetId或icon才设visual。metadata按报告人、单位、日期顺序显示。`cover.align`可为left/center/right，默认left；boxes和align只用于custom。先按题名行数、图片比例与真实身份决定区域，不照抄一组通用坐标。

custom不自动绘制预设横线、色块、logo、角标、页码与页脚。已填内容缺box、空box、区域越界/相撞或文字放不下都会报告问题；应调整区域和语义换行，不能缩字或静默删内容。视觉区包含visualCaption的空间，图像与图注一起分配。

`cover.assetId`和visualCaption用于已登记的主题视觉，或用cover.icon选择语义图标，assetId与icon二择一，也可都不使用。资产须为usage:decorative，不列入slide.figureIds；通过path导入时登记id、path、caption、sourceUrl、sourceVersion、license、usage、cropNote。它只是上下文视觉，不计为科学证据。科学原图承担证据时保留其身份、坐标和出处；不能把任意田块照片标成真实研究区，也不能把生成遥感/显微图当测量结果。

## 标题与页角元素可以改变

标题直接指出主题、机制或有条件的发现。方法/定义页可用简洁名词短语，结果页可用有证据的判断。不强迫每页都写“从……到……”“关键问题”“启示一二三”。

`design.chrome`定义全稿起点，`slide.chrome`按页覆盖。支持 `header:"band"|"rule"|"plain"`，以及showBrand、showSection、showPageNumber、showFooter、showSources、showTopRule和brandLabel。品牌、章节、页码、页脚与顶部横线分别选择，不捆成必须出现的一套母版。brandLabel可用空字符串清除。

逐个问：这个元素是否帮助听众辨认章节、来源或页码？若只是每页重复主题，关闭它并利用回收的正文空间。封面不再叠正文页眉；结果图页可采用plain标题；有章节导航需要时再显示section。来源是研究信息：隐藏页脚引用时，仍须在图注等适当位置提供可见来源线索，保留完整备注和参考书目，不能删除证据关联。

## 卡片是可见的内容分组

把一项完整条件、读图说明、机制解释或边界组成一张卡，标题说明职责，正文给具体内容。独立文字组须有可辨认容器；不要把三段标题和正文裸放在空侧栏。外层已有浅底或边框时，内层可开放，避免每段重复套框。

用 `design.cardDefaults`统一局部组件语言，再用 `card.appearance`逐字段覆盖。选择轮廓、浅底、实底或开放外观，以及圆角、内边距、强调边和轻微层次；卡片无需等大。精确枚举和测量规则见component-grammar。边界应围住真实内容，不能把短句拉成大空框。主证据可留在开放区域，解释卡在旁边形成主次。

语义图标帮助扫读，例如观测、模型、水分、证据与限制。用插件原生线图标或有来源的统一图标资产，不依赖emoji字形。图标含义与文字一致，大小服从标题；不靠一排小图标增加虚假信息量。主题图片提供对象和尺度的直观背景；证据图、表格与单位有更高优先级。

## 充盈与留白

将 `design.density`按需要设为compact或balanced。用户要求图文紧凑、充盈或禁止大面积留白时使用compact，并把严重空疏作为修复项。保留必要边距、行距和组间距；禁止无用途的大空洞。

重点找四种问题：正文挤在上半页；短文字组占一条高侧栏；上下两条内容之间留出大块空白；封面或结束页只有小标题与几句话。空间诊断用于定位，背景填充、卡片框、图标和大空文本框不等同有效内容。不能靠涂满底色或把quality设置改松来通过。

按顺序修复：

1. 放大真实主图、关系图、表格或有意义标题，使重点达到合适视觉份量。
2. 重新分配行列比例、卡片数量与排列；短组收紧后重新利用剩余空间。
3. 将需一起读的条件、读图说明和结论邻接组合；去掉重复面板标题与无用chrome。
4. 补上原本缺失但来源允许的比较、机制解释或有效性边界，或合并相邻页面。
5. 适合主题时加入有内容职责的图片或图标。它们不替代科学证据，也不作为消除空区告警的唯一办法。

`align:"start"`只解决局部面板过高，不能解决整页空疏；收紧后仍须检查下方。原图内部的留白和图例区域不随意裁掉。不要为占幅复制文字、增加假数据、夸大结论、塞入无关图片或不断缩字号。

## 结束页重新收束论证

结束页回答：现有证据支持什么，关键限制是什么，哪个问题值得讨论或下一步检验。可采用一个主判断与两条证据支点、主题视觉与开放问题，或让结论直接对应验证条件；不默认三列平级短句，更不只写“谢谢”。

无composition时可用 `layout:"closing"`与closing：variant为statement或evidence，statement写主判断，可带question、assetId、visualCaption和icon，并配slide.cards。assetId同样只用已登记的usage:decorative资产，不进入slide.figureIds；重要判断仍须有正文可见的证据线索。复杂综合用composition自主组织，此时不要同时设置closing对象。封面与结尾可以呼应主题视觉，但有不同信息任务；不要把所有结尾换成同一种深色大字页。

## 可读性与学术含义

画布为1280×720 CSS px，导出为13.333×7.5in，1px=0.75pt。默认正文24px约18pt、面板标题28px约21pt、图注18px约13.5pt。不得混淆px与pt。中文字体、粗体、英文长词和科学符号均需最终渲染确认。

内容超框时先删重复话、改准确短句、调比例或拆任务；不能截断文字、删单位和科学限定或连续缩字号。notes承载补充推导和口述解释；影响判断的基线、样本单位、模拟身份和结论范围留在页上。

科学图优先论文原图或当前数据。流程边表达真实时间、计算、数据或因果关系；关联不能画成已证实因果。表格保留完整比较条件，不能把不同口径混排优劣。视觉层次不能改变数据、来源与证据强度。

## 整稿节奏与真实验收

看概览，检查主要页面是否反复用同一骨架。对照任务相同且需同尺度时可同构；不同任务却只换标题和颜色时须重排。变化来自主载体、阅读方向、分组关系与视觉重心，不是每页换字体或随机换皮。

打开每页实际PPTX渲染，检查卡片轮廓与内边距、原图标签、标题与角标必要性、最大空区和焦点。没有溢出不等于设计完成。按具体失败项修复、重建复核，通过后停止无目的装饰返工。
