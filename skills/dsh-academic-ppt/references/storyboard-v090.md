## 1. 学术故事的基本单位

学术故事让听众知道为什么研究、如何判断、证据改变了什么，以及还有什么不能确定。悬念来自真实问题或方法分歧，推进来自可追溯证据，不通过夸大“突破”、制造对立或隐去反例取得戏剧感。

整稿先回答：听众已知道什么；这次要解决哪个问题；什么证据足以改变认识；哪项限制影响结论；结尾希望听众能判断什么。概述可暂时无结论，但不能在证据不足时先写强结论再补引用。

一页可以有多组共同支撑同一判断的证据。不要把一个完整比较机械切成数张只剩一句话的页面，也不要把几个互不相关的问题塞入同一“研究进展”页。

## 2. 逐页故事板

每页至少写出下列内容，使用可读的表或短段落。先调用 `academic_ppt_contract({topic:"storyboard"})`，再通过 `academic_ppt_plan` 写机器记录。

| 项目 | 必须具体到什么程度 |
| --- | --- |
| 听众问题 | 本页出现之前，听众还缺哪项认识？ |
| 主张或任务 | 一句可核对的判断；证据不够时写成问题或待检验方案 |
| 证据与来源 | paper / claim / asset 的实际 ID、页码/图号/表格位置及可用文件 |
| 推理 | 读者应从哪些比较、读数或关系得出该判断？有哪些替代解释？ |
| 必要边界 | 样本、条件、基线、单位、不确定性和适用范围中哪些必须可见？ |
| 页面关系 | 比较、先后、包含、空间、变化、汇合或解释；结构建议保持可调整 |
| 进入与离开 | 它接住前页哪个问题，给下一页留下哪项必要问题？ |
| 讲述与预算 | 需要讲多久，讲稿补充什么，哪些内容必须留在画面？ |

“展示结果”“放三篇论文”“补一张方法图”“采用高级学术风”都不算完成。原图尚未获取、数据尚未核对和关键比较缺失要进入缺项清单，不画空框让页面看起来已准备好。

工程字段对应关系：整稿使用 `objective`、`audienceTakeaway`、`throughline`、`pages` 和 `decision`；每页使用 `slideId`、`title`、`role`、`question`、`claimIds`、`assetIds`、`warrant`、`boundary`、`transition`、`seconds`、`layoutFamily`、`layoutReason`。上述每页字段均必填，最后一页 `transition` 可以为空字符串。

`role` 可选 orientation / question / mechanism / design / evidence / synthesis / limitation / proposal / references。`layoutFamily` 使用 `academic_ppt_layouts` 返回的语法 ID，原创结构填 `custom`；ID 本身不生成几何。需要维持共同尺度的重复结构可填写 `repetitionReason`。主画面必须保留的短条件、单位或判断放入 `mustShow`，不能在实现时只移到备注。

区分三种主张：

- `reported`：来源直接报告的结果，保持研究对象、数值单位、实验条件和限定。
- `inference`：作者从已记录证据推断，关联 `dependsOn`，写清 `reasoning`，避免从相关直接跳到因果。
- `proposal`：尚未验证的方案，给出问题、方法、对照、评价依据和可能反例，不写成已取得的成果。

科学限定按读者需要放置：决定比较含义的条件靠近证据；补充实现细节放讲稿或附录；来源放可定位的引用区。不能把所有不利条件移到听众看不见的备注。

## 3. 按研究任务组织整稿

以下是问题顺序的起点，不是必须套用的章节模板。

| 报告任务 | 可采用的推进 | 避免的退化 |
| --- | --- | --- |
| 论文精读 | 研究问题 → 关键假设 → 方法如何回答 → 决定性证据 → 局限与可复现性 | 按论文小标题逐段搬运 |
| 研究综述 | 共同难题 → 问题坐标 → 各路径解决什么 → 可比证据与分歧 → 仍缺哪类检验 | 国内一页、国外一页后罗列作者，无共同比较轴 |
| 进展组会 | 上次目标 → 新证据 → 与预期的差异 → 原因与替代解释 → 下一实验 | 只报工作量，失败与决策没有依据 |
| 开题 | 现实或科学矛盾 → 已知边界 → 可检验问题 → 研究设计 → 风险和判定方式 | 把计划效果提前写成成果 |
| 学位答辩 | 核心问题 → 贡献与证据 → 贡献之间的联系 → 有效性边界 → 结论 | 用“创新点”口号替代证据链 |
| 短时会议报告 | 关键问题 → 必须理解的机制 → 决定性结果 → 一项可记住且带条件的结论 | 大量背景挤掉结果、结尾只剩致谢 |

让每节问题不同且有递进。例如农业遥感同化综述可以讨论“哪些观测约束哪些状态”“误差结构怎样影响同化”“跨地点评价能否支持泛化”。这些是示例问题，不是已有研究结论；实际顺序由用户材料与听众背景决定。

比较框架须先统一研究对象、信息输入、时间尺度、训练/验证划分、基线和评价量。无法统一的研究用条件矩阵表达可比与不可比之处，不把不同论文的精度指标直接画成冠军榜。

## 4. 从语义关系选择版式

每次先说清“读者需要看见怎样的关系”，再查整页配方或使用自由构图。以下候选是可调整起点，不是要达到的数量配额。

| 读者任务 | 适合的页面组织 | 必须保留的证据条件 |
| --- | --- | --- |
| 看懂一个关键结果 | 大证据图与就近注释 | 轴、单位、图例、比较条件 |
| 比较两种方法 | 对齐双面板或同轴比较 | 相同尺度、输入与评价口径 |
| 比较多个研究 | 条件矩阵或分组证据表 | 来源、研究条件、不可比项 |
| 理解机制 | 主机制与局部放大解释 | 有依据的方向、变量与假设 |
| 理解实验设计 | 处理组、对照组与测量路径 | 独立单位、时间、随机/重复条件 |
| 看到方法流程 | 分阶段流程与输入输出 | 每一步实际操作及反馈关系 |
| 理解时间演变 | 时间轴结合观察窗口 | 真实时间、采样间隔与事件定义 |
| 识别空间变化 | 地图与区域/尺度放大 | 空间位置、比例尺、坐标与来源 |
| 阅读多面板科研图 | 保留面板索引，配同步注释 | 面板间的共享与不同条件 |
| 解释一条公式 | 公式、变量语义与作用示例 | 正确符号、量纲与假设 |
| 理解不确定性 | 区间/分布图与限制说明 | 区间定义、样本与估计方法 |
| 比较误差来源 | 分层误差图或诊断矩阵 | 可归因证据与混杂因素 |
| 理解模型消融 | 基线与删除/添加因素对照 | 相同评价协议和实验来源 |
| 汇合多项证据 | 证据路径汇入受限结论 | 哪些支持、哪些冲突、哪些未证实 |
| 判断下一实验 | 问题、可选操作与判定条件 | 未实施身份、可行性和反例 |
| 结束一个论证 | 结论、关键证据和边界同页 | 对开场问题的具体回答 |

同一整页关系可以采用不同比例与局部组件；相反，不同卡片外观也可能仍是同一整页骨架。排版多样性应在全稿缩略图和实际阅读路径中看得出来。

研究图表的线、面积、角度、颜色和位置可能编码数据，不能为视觉效果改变含义。没有真实数据时不要画貌似定量的柱形、排名或置信区间；需要示意时清楚标注并避免暗示实测。

## 5. 检查节奏与真实性

只读页标题、每页问题和承接句，检查能否理解整稿为何按此顺序出现。随后看全稿概览：长段落是否全是同一种骨架；方法、结果与综合是否得到不同表达；章节转折是否可辨；结尾是否兑现开场。

允许同一实验系列保持同轴、同位与同尺度，避免为追求“每页不同”破坏可比性。密集页后可以用真正的阶段结论降低负担，但不能插无信息口号页制造节奏。

检查时间预算与内容复杂度匹配。多面板科研图通常比标题页需要更多解读；按实际阅读和讲述估计，不声称已经真人排练。用户时长紧张时优先移出次要论证到附录，保留主证据与必要限定。

任何主张变化都回查证据与讲稿；任何素材替换都回查图注、读图提示、比较条件与引用；任何页序变化都回查章节位置和前后承接。故事板是实现依据，不是后补的装饰性说明文件。

## 6. 最短完整调用示例

下面演示三页“验证方案讨论”的请求格式，没有声称任何实验结果，也没有假造用户确认。真实汇报须替换为本次完整故事板和实际来源 ID；不能用空证据数组绕过需要证据的主张。六页及以上整稿最终交付必须含完整故事板及当前真实样张。

先查询 `academic_ppt_contract({"topic":"storyboard"})`。假设工程刚初始化在 `report/project.json`，返回修订号为 `0`，把以下完整对象保存为 `report/storyboard.request.json`：

    "throughline": "从待验证问题进入公平对照设计，再确定实施前要补齐的信息",

调用 `academic_ppt_plan`，参数为：

```json
{
  "projectPath": "report/project.json",
  "expectedRevision": 0,
  "requestPath": "report/storyboard.request.json"
}
```

使用返回的新 `revision` 进行后续写入，读取返回的 `files.storyboard` 可向用户展示规划。路径和修订号必须取自本次工程，不能长期复用示例值。要查询当前状态，保留 `projectPath`、当前 `expectedRevision`，省略 `requestPath`。

取得真实故事线决定后，将 `decision` 改为 `confirmed` 或 `delegated` 并填写真实 `userResponse`；`rationale` 可解释取舍，再提交完整故事板。当前示例的 `proposed` 不代表用户已经同意。

样张实现、构建、真实渲染且逐页 passed 审查后，再用同一 `academic_ppt_plan` 提交另一个请求文件。该文件的四个必填字段为 `kind:"pilot-review"`、`decision:"confirmed"` 或 `"delegated"`、真实 `userResponse`、具体 `notes`。不要在尚未看图或尚未得到回答/明确委托时提交。样张记录自动绑定当前内容；修改相关设计或科学内容后先重新复核。


## 样张与整稿的阶段区别

样张批准仍要求其关联论文、论点和图片的真实来源、全文与看图记录合格。完整参考文献若明确安排在尚未实现的 `role: references` 页面，以及已核对的原图若明确列在后续未实现页面的 `assetIds`，可以保留到这些页面完成；工具以 `deferredFinalIssues` 逐项返回。样张自身需要的图、未核对的证据、全文缺失和其他错误不能据此跳过。普通 `check` 与最终 `deliver` 保留全部整稿要求。
