## 先确定信息关系

卡片把相关证据、条件、解释或判断组织成可辨认的组。文字卡辅助读图，图片嵌入式卡片也可直接承载论文图与解释。先完成主要视觉材料的获取与查看，再决定哪些图文适合共同边界、哪些应开放排版。研究问题、图像比较、算法解释、配对读数和下一步安排各有不同阅读任务；不能用同一标题加正文框承载所有内容。`evidence`文字预设不能代替原图，`figure`家族则将真实资产嵌入卡内，具体选择见[image-cards.md](image-cards.md)。

在逐页设计稿中，为需要卡片的内容记录以下内容。开放图注、完整图表和共享坐标比较仍可直接排版，不强制转成卡片。

| 项目 | 要确定的内容 |
| --- | --- |
| 信息身份 | 研究问题、方法、证据、推断、条件、边界或待实施方案 |
| 内部关系 | 连续解释、标签与定义、数字与含义、逐项对应、并列对照、先后或依赖 |
| 完整内容 | 实际可见文字、来源、数据、单位、分母与限制；缺项如实保留 |
| 阅读入口 | 题名、少数关键读数或第一步，和接下来的阅读方向 |
| 页面关系 | 归属哪个图、方法或问题，与邻近对象怎样对应 |

“尚未检验”与“已验证失败”是不同信息。数字与阈值、两个指标的分母、计划与结果也不能因外观相近而合并。

## 查询与选择原生卡片

调用`academic_ppt_cards`按`family`或`purpose`检索，或用`presetId`取得单款详情。无筛选时取得简明索引；先读候选的用途、内容槽位、建议尺寸和示例，再实际查看对应预览。新建整稿不能跳过这一学习阶段，直接把所有内容写成同一种原生框；已有工程局部修改可复用已看过且仍适用的参考记录。示例内容仅说明填槽，不是本次研究证据。使用工具返回的准确ID，不凭名称猜字段。

随插件提供的[本地48卡片图册](card-library/index.html)可离线比较外观，单款SVG在同目录的`cards/{presetId}.svg`，`catalog.json`保留可查询元数据与示例。36种文字/数值/关系卡之外，12种图卡展示真实图片怎样与解释、条件和读数组合。借鉴题签、分隔、图面和说明的关系，不限定最终配色或整页布局。最终PPTX中的实际文字与尺寸仍须重新测量和渲染。

根据当前信息选择少数真正适合的候选，不要求一份报告用满48种。一个比较组的同类信息保持同结构；不同职责按实际关系变化。同一页沿用已协商的学术色板和颜色含义，不能把图册中的多个示例配色一起搬进报告，也不能只使用记得的两三个ID而忽略更适合当前图片的结构。

| `family` | 设计处理的关系 | 可先查看的具体预设 |
| --- | --- | --- |
| `research` | 问题、语境、定义与有序议题 | `research-tab`、`research-bracket`、`research-rule` |
| `method` | 核心操作、先后、输入输出、公式与协议 | `method-ladder`、`method-io`、`method-equation` |
| `evidence` | 判断与依据、来源、配对证据、观察与解释 | `evidence-claim-proof`、`evidence-compare`、`evidence-interpretation` |
| `metric` | 读数与含义、独立指标、参照和目标 | `metric-aside`、`metric-dual`、`metric-target` |
| `boundary` | 范围、风险、假设、应对与核对条件 | `boundary-cut`、`boundary-scope`、`boundary-response` |
| `progress` | 阶段、路线、里程碑、分支与下一动作 | `progress-route`、`progress-decision`、`progress-status` |
| `figure` | 12种论文图、对照、局部、条件与读数组合 | `figure-caption`、`figure-pair`、`figure-zoom`、`figure-conditions` |

例如先查询`academic_ppt_cards({"family":"metric","limit":6})`比较读数结构，再用`academic_ppt_cards({"presetId":"metric-dual"})`查看完整槽位。两项独立达标率使用各自的分母与说明；除非材料明确给出联合统计，不合并成联合达标率。

调用`academic_ppt_contract({"topic":"slide"})`核对完整字段。原生卡片使用以下内容入口：

| 字段 | 用途 |
| --- | --- |
| `preset` | 卡片目录返回的具体结构 ID |
| `figureIds` | 图卡内按预设顺序显示的已登记资产；独立图片仍用slide.figureIds，不能仅写文件路径 |
| `mediaHeight` | 图卡图片及图注槽总高，按实际图比例和卡片宽度调整，不自动裁图 |
| `title`、`body` | 本次材料的完整题名与正文，原有字段仍有效 |
| `items` | 按预设组织的条目，每项可有`label`、`value`、`unit`、`detail`；填写真实内容，不为凑结构造数 |
| `metric` | 需要保留独立重点读数时沿用既有字段，含义和条件一起可见 |
| `badge` | 确有作用的短序号或阶段名，不能暗示没有依据的等级或认证 |
| `note` | 完整限定或来源说明；主要边界仍需以正文职责可读，不能靠字段名降低要求 |
| `accent`、`icon`、`emphasis` | 受支持的局部颜色、可选语义图标和有限强调；保留整稿语义 |

按详情里的几何和容量选卡，而不是把已有文字硬塞进外观。遇到长题名、多行条件或较长单位，优先改用更合适的结构、扩大必要区域或重新分组；不截字、隐藏条目或持续缩字。预设保持自己的内部关系，不继承项目`cardDefaults`中的内部布局与装饰模式；允许继承其中的外表面 paint 参数，再由逐卡`appearance`覆盖。`appearance`接受`padding/radius/elevation`及`fill/stroke/strokeWidth/dash/shadow`外框参数。按 [academic-visual-language.md](academic-visual-language.md) 选择真正无填充的虚线范围、白底细实线、克制阴影等；开放框保留原几何。实际强调色用`card.accent`。不同时设置`templateComponentId`，也不叠加旧`style`或另一套`appearance.layout/surface/accent`。

## 把参考学习写成可审查记录

在逐页设计之前，以当前困难信息组为对象比较候选：记录看过的目录ID与实际预览路径、哪种关系有用、最终选型，以及为本稿改了哪些配色、图文比例、题签和解释。至少覆盖本稿不同的实际信息关系，不以看了几张图或用了几种样式为合格配额。

先查design契约，再将真实学习写入`design.referenceStudy`。`status: reviewed`必须含非空的`catalogIds`、`previewPaths`、`observations`和`adaptations`，描述已经完成的观察与适配，不能只填写“已学习参考”。目录ID与预览路径各最多16项，保留本稿实际相关的候选；`observations`为具体观察文字，`adaptations`为改造说明字符串数组。`selectedPresets`记录拟采用的已看过ID，可为空；直接用原生drawings重组时保存借鉴来源和改造理由，不假装使用了未采用的preset。

若当前任务确实不适用卡片参考且工程实际没有卡片，用`not-applicable`和具体`reason`说明当前表达任务与载体；有卡片的工程不能同时声明卡片参考不适用。局部改字优先沿用有效的既有记录，不为小改动虚构新学习；旧工程按实际任务补充。不能因尚未浏览目录、没有生图接口或想赶快输出整稿而跳过。参考记录与协商记录各自独立：用户选了配色，不代表作者已经学习图卡。

把最能体现取舍的卡片放进真实正文候选，向用户展示它与原图、解释、字号的组合效果；不必让用户逐款挑48个样式。候选预览是设计参考，实际正文仍须遵循已取得材料与已协商的观看方式。

## 按当前内容改造配色与结构

普通参考默认允许重新设计。先判断当前内容与参考的差别：题名长度、条目数量、解释负担、数值口径、阅读顺序和页面位置；再决定保留哪些关系、调整哪些安排。现成预设恰好适合时可以保留，不设置改色或改形数量。自主设计的依据是本次内容与读者任务，不能只因卡片看起来漂亮便原样填字，也不能仅换一种颜色就宣称重新组织了内容。

| 本次内容需要 | 可实际执行的调整 |
| --- | --- |
| 全稿色调与参考不相称，或需要兼容真实图表 | 依据已协商方向编辑`design.palette`，在`design.colorRoles`中保持颜色与含义对应；用`card.accent`作有职责的局部强调 |
| 长题名、解释或单位需要更多空间 | 调整卡片`box`、组合区域和受支持的内边距，重新测量；按信息负担分配宽高，不沿用示例比例 |
| 两项读数、条件、比较或步骤需要不同分区 | 选择匹配关系的预设；预设槽位仍不适合时，用原生`drawings`和`composition.regions`重组标题、读数、解释与限定 |
| 题签、边界或编号承担不同职责 | 换用合适预设或原生重绘题签、分隔和线框；去掉没有归属含义的套框，不改变证据强度与真实顺序 |
| 同一组比较需要可比，邻近卡片承担不同任务 | 比较组保留尺度、色义和对齐；不同任务按关系变化结构，同时保持字体、线宽和间距的共同语言 |

预设的内部`frame/header/content`配方固定，不能用虚构的列数、标题位置或分区比例字段覆盖；切换预设或用原生对象完成所需结构。未使用preset的旧卡片可使用已有`appearance.layout/surface`，不要把两套接口混写。已有工程只改颜色或预设时使用受限`card-style`；改变区域尺寸、条目组织或原生结构时按授权用`slide-content`，重新构建和看图。

例如，参考只有一个大读数，而当前材料是两项分母不同的指标，应分别保留读数、分母与解释；共享条件可放在同一完整条件区。参考的两条短句换成长方法说明时，可重组为输入、操作与输出，不能为了填满原槽位删去步骤。实际数据、数值、单位、来源、限定与证据身份保持准确，版式调整不产生新结论。

配色可以在学术色板候选上自主改动，也可按真实材料建立一致的组合。先确定主色、正文、浅底、边界和变量色各自用途，再核对实际对比；不能逐卡随机改色或覆盖来源图原有色义。采用白字标题带的预设时，强调色须足够深；浅强调色可配开放题签、浅底深字或原生重绘，不能假设引擎会自动修正文字对比。将“为什么这样配色、哪些关系需要改组”简记在`design.direction`、组合页`visualPlan.rationale`或设计工作文件中，避免把设计过程放入观众画面。

## 宿主生图可用时先探索

生图在需要设计卡片时优先提供内容相关的参考；这个优先级不覆盖论文查证与取图。它与`capabilities.imageInput`不同：能看图不代表有生图接口；生成了图也不代表能看懂结果。根据宿主实际工具列表或明确能力声明记录可用入口，不靠模型名称猜测，不搜索凭据。生图不可用时回到原生卡片设计，研究原图仍按独立的获取流程处理。

先查`academic_ppt_contract({"topic":"preparation"})`，把真实汇报题目、受众、内容块、模板选择与生图状态写入工作区 JSON，再调用`academic_ppt_prepare({requestPath,outputPath?})`。它是本地准备工具，返回下一步和提示词；它本身不请求外部服务，不创建图片，也不读取模型密钥。按返回的`designDialogue.nextAction`与`questionTiming`继续：checkpoints进入`prepare-pilot-candidates`时，先制作并实际查看候选，展示真实样张后再记录视觉选择；显式topics保留逐主题等待。已知偏好和明确委托继续沿用。可用时由当前作者按返回计划调用宿主已有的生图工具。

准备请求的`paletteMode`默认`adaptive`，将`palette`作为可调整的候选；允许按本稿内容调整色相、明暗、饱和与用量，保持全稿色义。仅当用户明确固定颜色时使用`paletteMode:"fixed"`并填写`palette`，不能因参考图已有配色就自动锁定。

按返回的`imageGeneration.batches`逐批使用各自的`prompt`，每批至多4个内容单元，并保留`id`与`cardIds`对应。单批另有兼容的`prompt`字段，多批不要把全文合成一张拥挤探索板。实际调用参数遵从宿主生图工具本身的契约；看过各批结果后再汇总引用和观察。

| 实际情况 | 处理方式 |
| --- | --- |
| 生图工具可用，用户未拒绝 | 先生成一组内容相关的小卡片参考，实际查看，再选择原生结构或自行重构 |
| 能力未知 | 检查宿主已公布的工具；无法确定则如实记录并继续原生流程，不试探任意网络接口 |
| 不可用、调用失败或用户拒绝 | 保留失败/拒绝状态，实际查看48款原生目录中的适合候选，继续逐页设计，不反复重试或阻断汇报 |
| 已生成但未看图 | 仅保留临时结果，不提交`status:generated`；实际看图后填`resultReferences`与`visualObservations`，不能把文件存在写成已学习 |
| 用户给了卡片图片或PPT | 先看用户参考并记录偏好，再让生图探索新的组合；不得追摹原图构图、替换文字后宣称原创 |

参考提示词应包含真实内容与约束，例如：

> 为学术报告《〔本次完整题目〕》探索小信息卡。目标是〔本次受众和观看场景〕。仅使用下面的内容块，每块保留题名、条件、数值、单位和证据身份：〔完整内容〕。根据每块的阅读任务、文字长度和信息关系设计分区，例如题签与连续解释、读数与定义并列、条件逐项对应、限定与相关判断相邻。依据〔本稿学术色板及颜色职责、用户明确要求保留的颜色〕自主调整主色、浅底、描边与局部强调，保持全稿色义与可读对比。参考附件的阅读组织原则，重新安排当前内容的比例、题签与分区；不要追摹原图、仅换字换色。合适的结构可以保留，不为追求不同制造装饰。图是设计探索，不是研究证据；不生成实验照片、数据图或没有材料支持的结果。各候选编号，保持中文可读，便于随后用原生PPT对象重建。

以上是提示词写法，不是固定的六块/八块配额。内容少时只探索必要候选，内容多时分批，避免一张探索板里文字过小。传给生图工具的材料只包含本次已获授权使用的内容与附件；按宿主既有服务和权限运行，不把用户模板自动发布到公共仓库。

准备请求中的`cards`使用当前材料的`purpose`、`title`、`body`及可选条目，并用`evidenceStatus`区分已核对来源、作者推断、方案、演示和未核对材料。这些字段属于准备契约，不直接复制到slide.card记录中。生图完成并实际查看后回填引用与观察；若输出计划另存文件，使用新的`outputPath`保留先前决策，不能用计划文件覆盖请求文件。

## v0.8.3：按需学习原创视觉复刻的 20 款局部卡片

在原生 48 款预设之外，另有 [20 款编辑式视觉卡片](editorial-v083/index.html)、[结构说明 JSON](editorial-v083/catalog.json)及[可编辑的四卡一页 PPTX 参考](editorial-v083/editorial-card-components-20.pptx)。它们出自生图构思后重新用原生 PowerPoint 对象复刻，均标注 `componentOnly: true`；**不是 20 套整页版式，也没有注册为新的 `academic_ppt_cards` API preset ID**。目录的 `preset` 字段是“可用现有配方作为起点”的映射，例如 C02 的三图总览更适合结合 `figure-overview-details` 和原生线条重组，不意味着 `figure-zoom` 能直接消费三张图片。

选卡必须从**本页的证据和信息关系**出发。实际打开合理候选，识别比较的尺度与共同条件、总览和局部的定位、读数与图的贴合方式，同时看题签、边界、间距与层次。新建或整稿重设计须完成相关组件学习；最终判断不需要卡片时，可以不用preset，仍记录不采用或转为开放构图的理由。不要把整张参考截图放在页面上，更不能用一张卡片顶替本页全部证据。重建时先替换真实论文图并核对原图出处、图例、坐标与裁切，再依本稿配色与字级调整题签、边界、内部分区；保留文本、数值和线条可编辑。

图册的航拍、热图和曲线来自**合成示意素材**，不代表文献结论；不要由占位图推断数值。卡片既可以占正文的局部宽度，也可以与其他对象形成宽证据组；其“局部组件”身份不取决于固定占幅百分比，而取决于是否被页级叙事组织、与其他证据共存。所有源图缩小后仍需能读清图例和刻度，四窗比较过小应拆分，不以塞满一张卡为目标。

## 从参考重建可编辑对象

实际查看生成结果，记录每个拟采用候选的阅读顺序、题签处理、边界职责、数据与解释关系，以及中文、数值和单位错误。比对原始材料，不从生成图里反向抄录数字。生图中的缺字、错误字、错单位、假图标和不必要装饰都不进入最终稿。

先核对当前材料需要的空间和关系，再选择合适的`card.preset`或使用受支持的原生`drawings`重组；按照本稿色义重新配色，依据实际内容调整题签、比例、分隔与阅读路径。生成图和模板都不锁定最终构图，不能只把图片坐标逐点描成原生对象。生成图可留在设计工作材料中，不将整块参考图片作为最终信息卡或精确证据嵌入。最终标题、正文、线框和数值应可编辑，真正研究图像仍以其原始来源使用。

若用户要求使用生成图本身作为情境插画，单独说明其用途与生成身份，不能与原生卡片、来源图或实验记录混同。视觉参考记录只证明看过设计候选，不替代最终PPTX的review。

## 与整页组合

先完成全页主关系，再安排图卡、文字卡和开放区域。读图解释贴近相应图段，条件与所属实验对齐，边界跟随相关判断，序号卡仅用于真实顺序。两项指标可共用一张图卡的读数区，但保留各自单位、分母和解释；共享条件可跨多组表达，不重复塞进每个框。卡片图面的结构见[image-cards.md](image-cards.md)。

有意义的标题带、浮签、切角、折角、序号锚点、窄侧栏和局部分隔可提供层级。选择哪种由内容关系和当前模板语言决定；不要把折角当作证据强度，把粗框当作重要性。卡片数量、宽高、排列和样式变化都不是独立质量目标。

在一页中混合开放证据区、信息卡和普通解释时，统一页级标题、共同间距、字体角色和颜色职责。局部结构可以不同，但不应像来自几套主题。相邻页面延续论证，同类比较保留同尺度，不为了避免重复而改变真实比较基线。

布局变化要发生在关系上：配对图卡可以并列，时间或层级关系可以上下，整体与局部可以嵌套，综合判断可以跨栏。不要把每页都排成一幅左图与三张右卡，也不要把整稿统一替换成同一幅上图下文。图卡数量少但关系清楚可以成立，数量很多却始终同构仍需重做。

## 检查实际卡片

查看实际PPTX渲染而非仅HTML或SVG。逐张检查完整内容、单位、行高、题签位置、折角/浮签与正文的距离、描边可见性、图标与文字重叠和最终字号。尤其检查长中文标题、英文术语、负数、区间、上下标和多行条目。

按[typography-editing.md](typography-editing.md)检查题签孤行、单位拆分、窄栏频繁换行和同义复述。图片卡内核对原图实际存在、对应来源、轴与图例未被容器遮挡。已裁切原图要与完整原图复核，避免把相邻面板残余和被截断的轴标签一起嵌入。需要更大字时先减少重复解释并调整行宽，不改变科学限定。

核对每个条目、`metric`、正文和`note`确实可见且保持正确对应；判断字段职责而非名称，关键条件不能缩成脚注。检查原生对象仍可编辑。若一组卡片明显超出页面容量，重新组织内容关系和区域，不能通过隐藏字段或取消溢出检查来交付。

最后回到页面任务：这些卡片是否使读者更容易把证据、条件和解释一起理解？若只有轮廓变多、信息关系没有改善，应重做分组或改用图、表、流程和开放注释。

对照本次内容检查适配是否兑现：长解释是否获得相应空间，读数与条件是否正确对应，同类比较是否仍同尺度同色义。保留原结构或作出改动都应有内容理由；不以改色数量、样式变化或与参考的表面差异作为质量指标。

实际使用的每个原生 `preset` 也须出现在 `referenceStudy.catalogIds` 的已查询与预览记录中，不能只登记某一款参考后直接采用未看过的配方；以 `drawings` 重新组织不要求套预设，但仍需说明学到的关系与改造。

## v0.9.1 的尺寸与颜色复核

preferredWidth和图册尺寸是学习起点，按实际区域宽度重排，再测自然高度。图卡默认省略mediaHeight，由可用区域、图注和原图比例适配；显式固定只用于有依据的比较尺度。文字卡和无证据余量需求的父面板默认收紧，显式stretch/box仍须检查空腔。收紧后重新分配整页剩余空间。深色题签、局部填色、开放证据区与逐页spaceCheck/colorCheck的实际做法见[space-and-tone.md](space-and-tone.md)。
