## 先确定信息关系

卡片用于一个可辨认的信息组。先写完整题名、正文、必要条件、读数、单位和限定，确定内部关系，再选择外观。研究问题、算法解释、证据范围、配对读数、逐项条件与下一步安排各有不同的阅读任务；不能用同一个标题加正文框承载所有内容，也不能只换颜色冒充新的结构。

在逐页设计稿中，为需要卡片的内容记录以下内容。开放图注、完整图表和共享坐标比较仍可直接排版，不强制转成卡片。

| 项目 | 要确定的内容 |
| --- | --- |
| 信息身份 | 研究问题、方法、证据、推断、条件、边界或待实施方案 |
| 内部关系 | 连续解释、标签与定义、数字与含义、逐项对应、并列对照、先后或依赖 |
| 完整内容 | 实际可见文字、来源、数据、单位、分母与限制；缺项如实保留 |
| 阅读入口 | 题名、少数关键读数或第一步，和接下来的阅读方向 |
| 页面关系 | 归属哪个图、方法或问题，与邻近对象怎样对应 |

“尚未检验”与“已验证失败”是不同信息。数字与阈值、两个指标的分母、计划与结果也不能因外观相近而合并。

## 查询与选择原生卡片

调用`academic_ppt_cards`按`family`或`purpose`检索，或用`presetId`取得单款详情。无筛选时取得简明索引；先读候选的用途、内容槽位、建议尺寸和示例，再查看对应真实预览。示例内容仅说明如何填槽，不是本次研究证据。使用工具返回的准确 ID，不凭样式名称猜字段。

随插件提供的[本地36卡片图册](card-library/index.html)可离线比较外观，单款SVG在同目录的`cards/{presetId}.svg`，`catalog.json`保留可查询元数据与示例。图册是局部卡片词汇，不是整页布局答案；最终PPTX中的实际文字与尺寸仍须重新测量和渲染。

36种预设提供不同题签、边界、读数、对照、条件和流程组织。根据当前信息选择少数真正适合的候选，不要求一份报告用满36种。一个比较组的同类信息应保持同结构；不同职责的卡片可以变化。同一页沿用当前学术色板与颜色含义，不能把候选图册中的多个示例配色一起搬进报告。

| `family` | 6款设计处理的关系 | 可先查看的具体预设 |
| --- | --- | --- |
| `research` | 问题、语境、定义与有序议题 | `research-tab`、`research-bracket`、`research-rule` |
| `method` | 核心操作、先后、输入输出、公式与协议 | `method-ladder`、`method-io`、`method-equation` |
| `evidence` | 判断与依据、来源、配对证据、观察与解释 | `evidence-claim-proof`、`evidence-compare`、`evidence-interpretation` |
| `metric` | 读数与含义、独立指标、参照和目标 | `metric-aside`、`metric-dual`、`metric-target` |
| `boundary` | 范围、风险、假设、应对与核对条件 | `boundary-cut`、`boundary-scope`、`boundary-response` |
| `progress` | 阶段、路线、里程碑、分支与下一动作 | `progress-route`、`progress-decision`、`progress-status` |

例如先查询`academic_ppt_cards({"family":"metric","limit":6})`比较读数结构，再用`academic_ppt_cards({"presetId":"metric-dual"})`查看完整槽位。两项独立达标率使用各自的分母与说明；除非材料明确给出联合统计，不合并成联合达标率。

调用`academic_ppt_contract({"topic":"slide"})`核对完整字段。原生卡片使用以下内容入口：

| 字段 | 用途 |
| --- | --- |
| `preset` | 卡片目录返回的具体结构 ID |
| `title`、`body` | 本次材料的完整题名与正文，原有字段仍有效 |
| `items` | 按预设组织的条目，每项可有`label`、`value`、`unit`、`detail`；填写真实内容，不为凑结构造数 |
| `metric` | 需要保留独立重点读数时沿用既有字段，含义和条件一起可见 |
| `badge` | 确有作用的短序号或阶段名，不能暗示没有依据的等级或认证 |
| `note` | 完整限定或来源说明；主要边界仍需以正文职责可读，不能靠字段名降低要求 |
| `accent`、`icon`、`emphasis` | 受支持的局部颜色、可选语义图标和有限强调；保留整稿语义 |

按详情里的几何和容量选卡，而不是把已有文字硬塞进外观。遇到长题名、多行条件或较长单位，优先改用更合适的结构、扩大必要区域或重新分组；不截字、隐藏条目或持续缩字。预设使用自己的布局与表面，不继承项目`cardDefaults`；`appearance`仅用`padding`、`radius`、`elevation`微调，实际强调色用`card.accent`。不同时设置`templateComponentId`，也不叠加旧`style`或另一套`appearance.layout/surface/accent`。

## 宿主生图可用时先探索

生图负责提供内容相关的设计参考。它与`capabilities.imageInput`不同：能看图不代表有生图接口；生成了图也不代表能看懂结果。根据宿主实际工具列表或明确能力声明记录可用入口，不靠模型名称猜测，不搜索凭据。

先查`academic_ppt_contract({"topic":"preparation"})`，把真实汇报题目、受众、内容块、模板选择与生图状态写入工作区 JSON，再调用`academic_ppt_prepare({requestPath,outputPath?})`。它是本地准备工具，返回下一步和提示词；它本身不请求外部服务，不创建图片，也不读取模型密钥。可用时由当前作者按返回计划调用宿主已有的生图工具。

按返回的`imageGeneration.batches`逐批使用各自的`prompt`，每批至多4个内容单元，并保留`id`与`cardIds`对应。单批另有兼容的`prompt`字段，多批不要把全文合成一张拥挤探索板。实际调用参数遵从宿主生图工具本身的契约；看过各批结果后再汇总引用和观察。

| 实际情况 | 处理方式 |
| --- | --- |
| 生图工具可用，用户未拒绝 | 先生成一组内容相关的小卡片参考，实际查看，再选择原生结构或自行重构 |
| 能力未知 | 检查宿主已公布的工具；无法确定则如实记录并继续原生流程，不试探任意网络接口 |
| 不可用、调用失败或用户拒绝 | 保留失败/拒绝状态，直接用36款原生目录与当前逐页设计流程，不反复重试或阻断汇报 |
| 已生成但未看图 | 仅保留临时结果，不提交`status:generated`；实际看图后填`resultReferences`与`visualObservations`，不能把文件存在写成已学习 |
| 用户给了卡片图片或PPT | 先看用户参考并记录偏好，再让生图探索新的组合；不得追摹原图构图、替换文字后宣称原创 |

参考提示词应包含真实内容与约束，例如：

> 为学术报告《〔本次完整题目〕》探索小信息卡。目标是〔本次受众和观看场景〕。仅使用下面的内容块，每块保留题名、条件、数值、单位和证据身份：〔完整内容〕。设计若干有实质差异的组合，例如题签与连续解释、读数与定义并列、条件逐项对应、限定与相关判断相邻。沿用〔本稿学术色板及颜色职责〕，用可辨认描边、明确题签和适量留白形成层级。参考附件中的阅读组织原则，重新安排当前内容；不要复刻附件的具体框形、位置与文本。图是设计探索，不是研究证据；不生成实验照片、数据图或没有材料支持的结果。各候选编号，保持中文可读，便于随后用原生PPT对象重建。

以上是提示词写法，不是固定的六块/八块配额。内容少时只探索必要候选，内容多时分批，避免一张探索板里文字过小。传给生图工具的材料只包含本次已获授权使用的内容与附件；按宿主既有服务和权限运行，不把用户模板自动发布到公共仓库。

准备请求中的`cards`使用当前材料的`purpose`、`title`、`body`及可选条目，并用`evidenceStatus`区分已核对来源、作者推断、方案、演示和未核对材料。这些字段属于准备契约，不直接复制到slide.card记录中。生图完成并实际查看后回填引用与观察；若输出计划另存文件，使用新的`outputPath`保留先前决策，不能用计划文件覆盖请求文件。

## 从参考重建可编辑对象

实际查看生成结果，记录每个拟采用候选的阅读顺序、题签处理、边界职责、数据与解释关系，以及中文、数值和单位错误。比对原始材料，不从生成图里反向抄录数字。生图中的缺字、错误字、错单位、假图标和不必要装饰都不进入最终稿。

选择合适的`card.preset`并重填核对过的文字与数据；预设不能表达时使用受支持的原生`drawings`重建。生成图可留在设计工作材料中，不将整块参考图片作为最终信息卡或精确证据嵌入。最终标题、正文、线框和数值应可编辑，真正研究图像仍以其原始来源使用。

若用户要求使用生成图本身作为情境插画，单独说明其用途与生成身份，不能与原生卡片、来源图或实验记录混同。视觉参考记录只证明看过设计候选，不替代最终PPTX的review。

## 与整页组合

先完成全页主关系，再安排小卡片。读图解释贴近相应图段，条件与所属实验对齐，边界跟随相关判断，序号卡仅用于有真实顺序的步骤。两项指标可共用一个卡片但保留各自单位、分母和解释；共享条件可跨多组表达，不重复塞进每一个框。

有意义的标题带、浮签、切角、折角、序号锚点、窄侧栏和局部分隔可提供层级。选择哪种由内容关系和当前模板语言决定；不要把折角当作证据强度，把粗框当作重要性。卡片数量、宽高、排列和样式变化都不是独立质量目标。

在一页中混合开放证据区、信息卡和普通解释时，统一页级标题、共同间距、字体角色和颜色职责。局部结构可以不同，但不应像来自几套主题。相邻页面延续论证，同类比较保留同尺度，不为了避免重复而改变真实比较基线。

## 检查实际卡片

查看实际PPTX渲染而非仅HTML或SVG。逐张检查完整内容、单位、行高、题签位置、折角/浮签与正文的距离、描边可见性、图标与文字重叠和最终字号。尤其检查长中文标题、英文术语、负数、区间、上下标和多行条目。

核对每个条目、`metric`、正文和`note`确实可见且保持正确对应；判断字段职责而非名称，关键条件不能缩成脚注。检查原生对象仍可编辑。若一组卡片明显超出页面容量，重新组织内容关系和区域，不能通过隐藏字段或取消溢出检查来交付。

最后回到页面任务：这些卡片是否使读者更容易把证据、条件和解释一起理解？若只有轮廓变多、信息关系没有改善，应重做分组或改用图、表、流程和开放注释。
